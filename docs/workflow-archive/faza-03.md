### Фаза 3: Інфраструктура (завершено 2026-10-13, HEAD `b307a22`)

- [x] **П3.1:** Прибрано `continue-on-error: true` з Codecov-кроку в `.github/workflows/preview.yml` (ADR-0017) — `CODECOV_TOKEN` налаштовано і завантаження підтверджено (2026-10-13, `outcome=success`); тепер невдале завантаження покриття ламає CI (червоний CI = стоп). Коміт workflow-файлу — `--no-verify` з ручними перевірками hook'а (guard не знає про авторизацію власника; зміна самої задачі явно авторизована вказівкою «роби П3.1»).
- [x] **П3.2:** Дозволено `.github/workflows/` у pre-commit guard при ADR у коміті — раніше `scripts/pre-commit.sh` блокував коміти з workflow-файлами завжди, і авторизовані власником зміни (П12, П3.1) доводилося комітити з `--no-verify` і ручними перевірками. Зроблено (ADR-0018): правило 1c — якщо серед staged файлів є `.github/workflows/`, то в тому ж коміті має бути файл у `docs/adr/` (той самий патерн, що й правило 1b для `package.json`, ADR-0012). `--no-verify` більше не потрібен — усі перевірки hook'а виконуються й на комітах з workflow-файлами; ADR у коміті не гарантує авторизації власника — власник стежить за ADR у рев'ю. Логіку перевірено на обох сценаріях: workflow без ADR → відмова до тестів; workflow + ADR → тести й exact-байти проходять.
- [x] **П3.3:** Публікація TypeDoc-довідки на GitHub Pages (ADR-0019) — крок `npm run docs` у CI після `npm run build` (порядок обов'язковий: `vite build` очищає `dist/`, TypeDoc пише в `dist/api/` за конфігом ADR-0016), довідка потрапляє в той самий Pages-артефакт, що й демо: https://sergkarpenko.github.io/rubezh/api/ — оновлюється з кожним пушем у main. Лінки TypeDoc відносні (`data-base="./"`), субшлях `/rubezh/` навігацію не ламає. Workflow змінено легально за процесом ADR-0018 (ADR-0019 у тому ж коміті, без `--no-verify`); порядок кроків валідовано локально (`npm run build && npm run docs`).
- [x] **П3.4:** Dependabot для оновлення залежностей (ADR-0020; вибір власника у сесії 2026-10-13: Dependabot над Renovate — нативний, нічого встановлювати; Renovate вимагає стороннього App або self-hosted workflow). Оновлює лише версії наявних залежностей.
