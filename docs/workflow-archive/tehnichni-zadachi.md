- [x] **Т.4 (запит власника 2026-10-18, сесія закриття Фази 12 «запланий це виправити, або виправ відразу» — обрано виправити відразу): version-bump у pre-commit hook.** Спостереження релізу v0.4.0: `npm version N.N.N --no-verify` не прокидає прапорець у `git commit` під Husky — хук виконувався і падав на правилі 1b (package.json без ADR), бамп доводилось робити вручну + `git commit --no-verify` з ручним повтором перевірок хука (прецеденти v0.2.0/v0.3.0/v0.4.0). Рішення — ADR-0070 (доповнює ADR-0012/0014/0054; урок П7.5 «гейт живе в механізмі репо, а не в увазі агента»): правило 1b розрізняє version-bump (контентні рядки дифа staged package.json — лише поле `"version"` → без ADR, реліз-крок ADR-0054) і зміну залежностей/скриптів/конфігурації (як і раніше — лише з ADR у тому ж коміті, ADR-0012). Критерії: (1) bump-only проходить правило 1b; (2) зміна залежностей без ADR — як і раніше FAIL; (3) `npm version` проходить хук без `--no-verify`.

Логіку перевірено: живий прогін хука зі staged bump-only 0.4.0 → 0.5.0 — «[OK] package.json: лише version-bump» і хук повністю успішний (npm test + exact-байти пройшли); grep-ланцюг правила на синтетичних дифах — «лише version» → OK, «version + залежність» і «лише залежність» → потребує ADR.
