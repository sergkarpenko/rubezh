#### Середній пріоритет
- [x] **П7:** Юніт-тести для `main.ts` — два шари: (1) чиста «візуальна логіка» виділена й експортована (`cellFromPoint`, `samePath`, `hpColor`, `geoEventText`, `battleEventText`), 15 тестів; (2) переробка за ADR-0013 — DOM-тести UI-флоу через jsdom (`main.ui.test.ts`, 10 тестів: ініціалізація → час → радар → місія → бій → демо → закриття), розмітка з реального index.html. **DOM-тест зловив реальний баг**: кнопка «Кінець ходу» з ітерації 5.3 не працювала (aliensTurn викликався в хід гравця) — виправлено. Візуальну поведінку перевірити в прев'ю.
- [x] **П8:** Інтеграційні тести повного циклу — `src/cycle.test.ts`, 5 тестів, тільки через публічне API (як у `main.ts`: geo → mission → `bot.autoBattle` → squad → geo): (1) вікно місії — НЛО виявляється радаром і приземляється; (2) перемога — НЛО зачищено з геосцени (`mission_won`), виживші лікуються на базі, час геосцени заморожено під час бою; (3) поразка — перма-смерть у ростері (загін вилучено, решта ростеру йде на повторну місію тим самим НЛО), НЛО лишається до `ufo_left`, після вікна місія недоступна; (4) детермінізм — той самий хід дає байт-у-байт той самий лог бою; (5) ізоляція шарів — місія не витягає `geo.rng`, траєкторія геосцени не залежить від запуску і результату бою. 126/126 тестів локально і в CI.

#### Низький пріоритет
- [x] **П9:** Pre-commit hooks — Husky + lint-staged (ADR-0014, процес ADR-0012: авторизація власника, окремий коміт `chore(deps):`). `"prepare": "husky"` — хук встановлюється автоматично при `npm install` на будь-якому клоні (`core.hooksPath = .husky/_`, генеровані шими в `.gitignore` за авторизацією власника). `.husky/pre-commit` викликає наявний `scripts/pre-commit.sh` (правила AGENTS.md, рубіж ADR-0012, тести, exact-байти) — джерело правди перевірок одне; ручний симлінк `.git/hooks/pre-commit` видалено як мертвий. `lint-staged` встановлено одним пакетом, конфігурацію підключимо у П10 разом з ESLint/Prettier (без лінтера йому нема що запускати). Husky-хук перевірено на реальному коміті залежностей.
- [x] **П10:** ESLint + Prettier (ADR-0015, процес ADR-0012: вказівка власника «роби П10»). dev-залежності: `eslint`, `typescript-eslint`, `prettier`, `eslint-config-prettier`. `eslint.config.js` (flat config): рекомендований набір TS-правил + `@typescript-eslint/no-explicit-any: error` (AGENTS.md: суворі типи), область `src/**/*.ts`. `.prettierrc` під існуючий стиль (`printWidth: 140`, `singleQuote: true`, `semi: true`, `trailingComma: es5`) — стартовий коміт форматування 21 файл (без логічних змін), ESLint зловив мертвий імпорт `Unit` у `ai.ts` (видалено). `lint-staged` з П9 нарешті працює: у `.husky/pre-commit` перед проєктними перевірками `npx lint-staged` (`eslint --fix` + `prettier --write` на staged `src/**/*.ts`). Скрипти: `lint`, `lint:fix`, `format`, `format:check`. CI лінт не запускає (workflow змінювати заборонено) — рубіж на коміті.

CI-кроку немає (workflow змінювати заборонено) — `npm run docs` локально; публікація довідки на Pages — кандидат у Фазу 3.
- [x] **П12:** Codecov + покриття ядра (ADR-0017, процес ADR-0012: вказівка власника «роби п12»; зміну FORBIDDEN `.github/workflows/preview.yml` власник явно авторизував). dev-залежність `@vitest/coverage-v8@2.1.9` (в парі з vitest 2.1).
