# 0025. Захист гілки main — force-push/deletion + required status checks

- Статус: accepted
- Дата: 2026-10-13

**Контекст.** CI (`preview.yml`) запускається лише на push у main, тож PR-и Dependabot (ADR-0020) мержилися без жодної автоматичної валідації: у першому ж потоці (PR #1–#6, тег `iter-6.1`) PR #1 довелося перевіряти вручну у ворктрі, а бампи GitHub Actions (#2–#6) пройшли лише пост-фактум CI — черговий бот-PR міг би поламати main до того, як його хтось помітить. Заборона агентам міняти історію в AGENTS.md — домовленість, а не механізм; банер GitHub «main branch isn't protected» підказав механічну гарантію. Власник ухвалив (сесія 2026-10-13): захист від force-push/видалення + required status checks, без вимоги «тільки через PR».

**Рішення.** Ми захищаємо main правилами branch protection: заборонені force-push і видалення гілки; для мержу PR обов'язковий зелений статус чека `test`. Для цього додаємо `.github/workflows/ci.yml` (ADR-0018 — ADR у тому ж коміті) з тригером `pull_request: branches: [main]`: тести, покриття ядра з порогом 80% (ADR-0017), збірка Vite, генерація TypeDoc (ADR-0019) — той самий набір кроків, що й у `preview.yml`, без завантаження на Codecov і без деплою на Pages. `enforce_admins: true` — чек обов'язковий і для власника (якщо CI червоний, мерж заблокований; вимкнення захисту — свідома дія власника). Прямі пуші в main не вимагаються через PR і залишаються чинним соло-процесом (локальний `npm test` → push, як у ADR-0009/0020); force-push заборонений механічно для всіх.

**Наслідки.** Бот-PR Dependabot більше неможливо залити без зеленого CI — «CI — останній рубіж» (урок 1) тепер виконується механізмом, а не тільки звичкою; випадкове переписування історії або видалення main блокуються на рівні GitHub. Ціна: мерж PR чекає завершення чека (~1 хв); новий бот-PR чекає чека `test` з `ci.yml`, тож ім'я джоба `ci.yml` не можна перейменовувати без оновлення required check у налаштуваннях репозиторія (поза кодом, у Settings → Branches). Зміна рішення — новий ADR із полем Supersedes.
