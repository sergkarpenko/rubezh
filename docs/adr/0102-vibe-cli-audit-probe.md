# 0102. Проба аудиту PR через Mistral Vibe CLI в CI

- Статус: accepted (мерж PR власником = «схвалюю» — конвенція ADR-0018/0052)
- Дата: 2026-11-20
- Доповнює: ADR-0097 (два аудитори PR), ADR-0095/0098 (аудитор Mistral `mistral-audit`), ADR-0101 (Mistral — лише аудитор), ADR-0018 (зміна workflow — з ADR у точці коміту)
- Автор: Claude Code (рішення власника 20.11.2026 у чат-аналізі відповіді 402; задача Т.82)

## Контекст

Джоба `mistral-audit` (ADR-0095) викликає API Mistral ключем Studio і з 20.11.2026 ≈ 13:31 UTC отримує 402 `billing_wallet_depleted`: прямі виклики API (Completion) на плані Team оплачуються лише з гаманця, а бюджет плану покриває використання Vibe Code. Рішення власника (20.11.2026, дослівно): «робимо перевірку з ключем», «Vibe CLI нормальна опція»; на пропозицію «зробити це кроком Т.82, ретро фази 15 зсунути на Т.83» — «згоден». Власник також хоче, щоб аудитор бачив увесь репозиторій, а не лише диф, і зауважив, що в плагіні VS Code (той самий локальний рантайм, що й CLI) Vibe точніше виконує інструкції, ніж у вебі.

Окремого ключа типу Vibe створити не можна: «New key» в адмінці дає ключ Studio, а ключ Vibe — один на користувача (Code › Extensions). Рішення власника на старті Т.82 (кнопкою, дослівно): «Наявний …tW93».

## Рішення

1. **Новий workflow `.github/workflows/vibe-audit.yml`** поруч із `mistral-audit`: подія `pull_request` (лише гілки цього репозиторію, без Dependabot) і ручний запуск з номером PR; чек не обов'язковий. Секрет — `MISTRAL_VIBE_API_KEY` (ключ Vibe); `MISTRAL_API_KEY` не змінюється. Vibe CLI — `mistral-vibe` закріпленої версії (3.1.3) через `uv`.
2. **Логіка — у `scripts/audit-vibe-cli.mjs`** з режимом `--self-test` (самоперевірка — перший крок джоби, червоний чек лише від неї). Назва не починається з `vibe-`, щоб не плутати з замороженими скриптами `scripts/vibe-*` (ADR-0100).
3. **Прямий виклик:** один `POST /v1/chat/completions` ключем Vibe; код і тіло відповіді — у журнал і першим рядком коментаря. Відповідає на питання, чи працює ключ Vibe поза Vibe (тоді `mistral-audit` можна перевести на нього без переписування).
4. **Аудит:** `vibe --prompt-file … --output text --output-dir … --model mistral-large-4-0 --thinking medium --max-turns 60 --max-price 2 --time-limit 1500 --trust --auto-approve` у копії репозиторію на голові PR із встановленими залежностями. Промпт — англійською, знахідки — українською, до десяти, кожна з файлом, рядком і дослівною цитатою; скрипт відкидає знахідку, цитати якої немає ні у файлі на голові PR, ні в дифі, і називає відкинуті в коментарі. Результат — один коментар у PR з позначкою `<!-- vibe-audit -->` (оновлюється) з рядком прогону з `export.json`: токени, ціна за тарифом Vibe, причина зупинки.
5. **Безпека прогону.** Vibe 3.1.3 у неінтерактивному режимі не вимикає запис файлів ні `--enabled-tools` / `--disabled-tools`, ні `permission = "never"` у конфігурації, а `bash` без `--auto-approve` відхиляється (перевірено в Т.82 на підставному сервері). Тому: Vibe працює в копії, checkout без збережених даних входу (`persist-credentials: false`), дозвіл токена — `contents: read`, у дочірнього процесу немає `GITHUB_TOKEN`; ключ вирізається з усього, що йде в журнал і коментар.
6. **Збій** (код виходу Vibe 1 чи 2, 402, відповідь без блоку JSON) — коментар «Аудиту не було» з причиною і зелений чек, як у `mistral-audit`.
7. **Ролі `AGENTS.md`.** Vibe читає `AGENTS.md` сам; шапку «Rules for AI Agents (Vibe Work / Vibe Code)» і принцип 6 мінімально поправлено, щоб не давати аудиторові ролі виконавця. Повне переписування розділів «Процес для Vibe …» — кандидат 84, окремим ADR.
8. **Контрольна точка — 5 PR** з прогоном `vibe-audit`. Якщо жодної унікальної підтвердженої знахідки (такої, якої не дав аудитор для мержу) — новим ADR вимкнути обидві джоби Mistral (`mistral-audit` і `vibe-audit`), замість ADR-0097. Якщо є — новим ADR вирішити, яка з двох джоб лишається.
9. **Оплата.** Гаманець API — $0, тож успішний прогін сам означає «платить план». Якщо ключ Vibe дає 402 чи відмову — це теж результат: запис у звіті кроку, рішення — власник.

## Наслідки

- На кожен PR — до трьох аудитів: аудитор для мержу (умова класу `auto`, ADR-0094), `mistral-audit` (поки 402) і `vibe-audit`. Умову мержу і далі виконує лише аудитор для мержу.
- Прогін `vibe-audit` триває до ≈ 25 хв і витрачає місячний ліміт Vibe власника (Code › Extensions — «Monthly usage»).
- Ключ Vibe спільний із локальним CLI і плагіном VS Code власника: ротація ключа вимагає оновити і секрет.

## Альтернативи

- **Поповнити гаманець API** — відхилено власником (гаманець не поповнюється).
- **Офіційний action `mistralai/mistral-vibe`** — передає лише `-p`, без `--output-dir`, лімітів і моделі; CLI викликається напряму.
- **Ротувати ключ Vibe під CI** — відхилено власником на старті Т.82 (зламав би локальний CLI і плагін).
- **`--system-prompt-file` з роллю аудитора** — не взято: замінює власні інструкції Vibe про інструменти; роль аудитора — у промпті, `AGENTS.md` поправлено (п. 7).
