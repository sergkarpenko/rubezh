# 0071. Формат графічних ассетів обирається за доцільністю — WebP, PNG, JPEG

- Статус: accepted (явне рішення власника у сесії П13.4 2026-10-19)
- Дата: 2026-10-19
- Замінює (частково): ADR-0068 (пункт про формат PNG для ассетів відображення; решта пунктів ADR-0068 чинні — ліниве завантаження, фолбек кодом, тести від ассетів не залежать)
- Доповнює: ADR-0069 (розмір ассетів не обмежено; оптимізація — на кроці інтеграції за результатом прев'ю), ADR-0031/0064 (стиль шару відображення), docs/design/style-references.md (треки стилю)
- Автор: Vibe Code за дорученням власника (сесія П13.4, ітерація 2)

## Контекст

ADR-0068 зафіксував PNG як формат ассетів відображення. Обраний власником «багатий» 3D-стиль оформлення (style-references.md) дає фото-подібні рендери, які PNG стискає погано: лого стартового екрана 1024×768 = 1.0 МБ; навіть палітрове стиснення PNG (pngquant, 840px) = 207 КБ. Власник на прев'ю П13.4 (ітерація 1): «1 МБ — занадто, оптимізувати»; ітерація 2: «можемо використовувати любі потрібні формати». WebP того ж кадру = 82 КБ (q90) при RMSE 4.36/255 проти безвтратного — у 12× легше за PNG-оригінал і у 2.5× легше за палітровий PNG.

## Рішення

1. **Формат ассета не фіксований PNG** — обирається на кроці інтеграції за доцільністю (вага, прозорість, якість):
   - WebP — фото-подібні 3D-рендери оформлення (лого, фони, рамки);
   - PNG — плоскі/палітрові зображення, прозорі силуети, іконки;
   - JPEG — без прозорості, де артефакти стиснення прийнятні.
2. **Розмір ассета — не критерій приймання (ADR-0069), але вага сторінки — практична мета**: фото-подібний ассет за замовчуванням оптимізується (розмір під щільність відображення, WebP тощо); фінальне слово — за власником у прев'ю (ADR-0060).
3. **Рушійні вимоги без змін**: ліниве завантаження, текстовий/кодовий фолбек при недоступності ассета (headless/офлайн), тести від ассетів не залежать, exact-байти бінарних файлів — за git blob-hash, коміт бінарних байтів — локальним клоном.
4. **Браузерна підтримка**: WebP підтримують усі цільові браузери проєкту (Chromium/Playwright — смоки, Safari/iOS 14+ — iPad власника); фолбек робить потенційну несумісність некритичною.
5. **style-references.md оновлюється слідом за цим ADR** (вимоги до ассетів і робочий цикл).

## Наслідки

- Лого стартового екрана: `assets/logo.webp` 840×630 (2× від 420 CSS-px) ≈ 82 КБ замість 1.0 МБ PNG — без відчутної втрати якості (RMSE 4.36/255, відхилення >16 на ~1.5% каналів — дизеринг у сяйві).
- Вибір формату — частина кроку інтеграції, не окремий ADR на кожен файл; цей ADR знімає PNG-монополію ADR-0068.
- Якщо колись знадобиться формат із затримкою браузерної підтримки (AVIF тощо) — новий ADR.

## Альтернативи

- Палітровий PNG (pngquant) — відхилено: 207 КБ проти 82 КБ при порівнянній піксельній якості (RMSE 3.46 проти 4.36 — різниця непомітна, вага у 2.5× гірша).
- Лиши PNG і змиритись з вагою — відхилено власником (ітерації 1–2 прев'ю П13.4).
- JPEG 97 КБ — відкинуто: без прозорості, артефакти на неонових градієнтах, без переваг над WebP.
