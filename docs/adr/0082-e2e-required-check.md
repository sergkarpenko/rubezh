# 0082. Чек `e2e` — обов'язковий чек гілки `main`

- Статус: accepted (мерж PR власником = «схвалюю» — конвенція ADR-0023/0030/0052)
- Дата: 2026-11-11
- Доповнює: ADR-0080 (сценарій приймання в браузері; п.8 «поки не обов'язковий» цим ADR виконано), ADR-0028 (захист гілки `main`), ADR-0076 (гейти в CI)
- Автор: Claude Code (запит власника 2026-11-11, «Хвіст Т.8»)

## Контекст

ADR-0080 п.8 лишив чек `e2e` необов'язковим: перевести його в required мав власник після кількох зелених прогонів на реальних PR зі змінами коду (орієнтир плану — три). На 2026-11-11 чек пройшов зеленим на PR #272 (сам сценарій), #273, #274 (Т.9 — перший PR зі змінами коду гри) і #275. На #274 сценарій уже працював як гейт: перевірка від супротивного показала, що повернення старої поведінки туману дає червоний крок.

## Рішення

1. Рішення власника (2026-11-11, у сесії): не чекати трьох PR зі змінами коду — `e2e` стає обов'язковим чеком `main` зараз, поруч із `test`, `codecov/patch`, `pr-size`.
2. Налаштування захисту гілки змінено 2026-11-11 за дорученням власника: агент додав чек у формі правила в браузері власника, збереження власник підтвердив сам (GitHub вимагає підтвердження особи; запис цих налаштувань через API з хмарної сесії закрито). Джерело чека — GitHub Actions, як у `pr-size`.
3. Формулювання «поки не required» прибрано з кроку 5 циклу в `docs/workflow.md` і з коментаря джоби `e2e` у `ci.yml`. Сама джоба не змінюється.

## Наслідки

- PR із червоним або незавершеним `e2e` не мержиться. Час до мержу не зростає: на PR #272–#275 джоба `e2e` тривала 74–84 с, `test` — 80–103 с, вони йдуть паралельно.
- Нестабільний сценарій тепер блокує мерж усіх PR. Якщо `e2e` впаде без причини в коді, спершу перезапуск джоби; повторне падіння — дефект сценарію чи гри, фіксити до продовження (той самий стоп, що й для `test`).
- Зняти чек з обов'язкових може лише власник у налаштуваннях репозиторію; це зміна рішення — новим ADR.
