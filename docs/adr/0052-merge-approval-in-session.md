# ADR-0052: Конвенція мержу — явний апрув власника в сесії

**Статус:** accepted
**Дата:** 2026-10-15
**Автор:** Vibe Code (за рішенням власника 2026-10-15)
**Заміняє:** -
**Суперседе:** -
**Доповнює:** ADR-0023 (merge = «схвалюю»), ADR-0028 (доставка гілкою + PR), ADR-0050 (схвалення одним власником)

---

## Контекст

ADR-0023/0028 формулюють мерж як «merge = „схвалюю" у коментарі» — без вказівки, де саме має бути схвалення. На практиці лінії пR.2/пR.3 (2026-10-15) власник апрувував серії безпосередньо в сесії агента («замержи, я апрувлю»), і агент виконував merge (`gh pr merge --merge`) одразу після зеленого CI — цикл «PR → мерж» стиснувся з години до хвилини без втрати контролю: рішення про мерж усе одно ухвалює людина.

Формулювання «у коментарі» без цієї конвенції змушує нову сесію або чекати коментар у PR, або імпровізувати — саме те, що процес має виключати.

## Рішення

1. **Агент може виконати merge PR (merge-комітом) після ЯВНОГО апруву власника в сесії.** Явний апрув — пряма вказівка власника в чаті сесії або в коментарі PR («змерджи», «апрувлю», «merge») для конкретного PR або оголошеної серії PR.
2. **Без явного апруву мерж заборонений** — як і раніше (ADR-0023/0028): агент не мержить «за замовчуванням», апрув попередньої серії не узагальнюється на нові PR.
3. **Форма мержу незмінна:** merge-коміт у main (не squash) — теги iter-X.Y стоять на merge-комітах (ADR-0050).
4. Механічні гейти незмінні: зелені `test` + `codecov/patch` до мержу; апрув власника — поверх гейтів, не замість них.

## Наслідки

### Переваги

1. Швидкий цикл для серій PR (пR.2: 10 мержів, пR.3: 4) без втрати людського контролю.
2. Однозначне правило для нових сесій — нема імпровізації навколо «де саме схвалення».
3. Відповідальність не міняється: мерж = рішення власника, виконання — механічне.

### Ризики

1. Апрув «на серію» може бути сприйнятий як карт-бланш — тому прямо вказано: без явного апруву нових цілей мерж заборонений.
2. Апрув у чаті не лишається в історії GitHub — компенсується ланцюжком PR (описи) + workflow.md (звіти виконання з номерами PR і merge-комітів).

## Реалізація

- AGENTS.md, розділ «Категоричні заборони»: формулювання «Мержити PR» уточнено посиланням на цю конвенцію (явний апрув у сесії дозволяє мерж агентом; без нього — заборонено).
- workflow.md: звіти про мержі агентом фіксуються з номерами PR і merge-комітів (прецедент: пR.3, PR #83–#85, 2026-10-15).

## Зв'язок

- **ADR-0023:** «merge = „схвалюю"» — дана конвенція уточнює форму схвалення, не міняючи суті.
- **ADR-0028:** доставка гілкою + PR у main — без змін.
- **ADR-0050:** один рев'юер-людина — без змін; якщо з'явиться другий рев'юер, конвенцію переглянути новим ADR.
