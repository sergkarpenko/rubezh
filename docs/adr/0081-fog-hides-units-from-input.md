# 0081. Юніт у тумані для вводу гравця не існує

- Статус: accepted (мерж PR власником = «схвалюю» — конвенція ADR-0023/0030/0052)
- Дата: 2026-11-11
- Доповнює: ADR-0006 (туман війни — лише рельєф), ADR-0027 (тап-тап руху), ADR-0080 (сценарій приймання)
- Автор: Claude Code (запит власника 2026-11-11, задача Т.9; знахідка Т.8)

## Контекст

ADR-0006 визначає, які клітинки гравець бачить, і шар відображення невидимих демонів не малює. Але ввід бою позицію невидимого демона все одно видавав — трьома шляхами:

1. клік по невидимій клітинці з демоном давав підказку «Там нікого не видно (туман війни)», а по порожній невидимій — прев'ю шляху;
2. наведення на таку клітинку шляху не малювало: `findPath` вважає зайняту ціль недосяжною;
3. прев'ю шляху огинало невидимого демона, бо `findPath` вважає зайняті клітинки непрохідними.

Гравець міг знайти всіх демонів перебором клітинок, не зробивши жодного ходу.

## Рішення

Рішення власника (2026-11-11, з двох варіантів — цей і «у туман не ходять»): **демона в тумані для вводу гравця не існує.**

1. Невидима клітинка поводиться як порожня незалежно від того, чи стоїть там юніт: той самий клік, те саме наведення, та сама підказка.
2. Шлях гравця планується за видимим: `findPath(state, start, goal, maxNodes, seen)` — юніт у клітинці поза `seen` шляху не перекриває. Без `seen` поведінка незмінна.
3. Якщо під час руху наступна клітинка шляху зайнята, рух закінчується перед нею: `moveUnit(state, id, path, stopAtUnit = true)` повертає юніта, що перекрив шлях. Пройдені кроки й витрачені AP лишаються; підказка бою називає юніта. Без `stopAtUnit` зайнята клітинка — помилка, як і раніше.
4. Рельєф у тумані лишається відомим (мапа місії показана цілком, ADR-0006): «Туди не дістатись» для стіни нічого не видає.

## Наслідки

- RNG рішення не чіпає (ADR-0003): ні `findPath`, ні зупинка руху кидків не роблять; реакційний вогонь дозору спрацьовує на кожному зробленому кроці, як і раніше.
- ШІ демонів і боти (`ai-utils.ts`, `ai-bot.ts`) викликають `findPath` без `seen` — їхня поведінка і детерміновані траєкторії авто-бою не змінюються. Те, що бот за гравця прокладає шлях із знанням про невидимих демонів, — окреме питання, цим ADR не розв'язане.
- Дзеркало сценарію приймання (`e2e/mirror.ts`) планує шлях тим самим `seen`; сценарій перевіряє в браузері, що тап по клітинці невидимого демона дає прев'ю шляху.
- Рух у туман став ризикованішим: оперативник може витратити AP і зупинитись упритул до демона. Це свідома частина рішення.
