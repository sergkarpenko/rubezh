# 0028. Доставка змін — тематична гілка + PR, мерж власником

- Статус: accepted
- Дата: 2026-10-14
- Supersedes: ADR-0025

## Контекст

ADR-0025 ухвалив захист main без вимоги «тільки через PR»: «прямі пуші в main… залишаються чинним соло-процесом». Пізніше власник увімкнув у налаштуваннях репозиторія «Require a pull request before merging» (+1 approving review) поверх чека `test` і `enforce_admins` — прямий пуш у main став механічно неможливим, але ані ADR, ані AGENTS.md/workflow.md це не зафіксували. AGENTS.md досі дозволяє «Пуш до main», workflow.md (цикл зміни, кроки 4–5) описує «коміт у main → пуш», і кожна нова сесія агента ламалась об захист: коміт у локальний main → push відхилено → імпровізована гілка + PR (слід: PR #11, feat/p6.3, feat/p6.4, PR #16, #17, #18). Ретроспектива 2026-10-14: docs-и мають описувати фактичний механізм, а не припущення.

## Рішення

Ми доставляємо усі зміни в main лише через тематичну гілку + PR; прямого пушу в main немає.

- Робота одразу в тематичній гілці від актуального `origin/main` (наприклад `fix/p6.6-overwatch-artifacts`, `docs/phase6a-close`); коміти в локальний main сесії не роблять.
- Гілка пушиться в origin, відкривається PR у main: у описі — що змінено, чому, критерії приймання (ADR-0023), результат локальної перевірки (`npm test`, lint, build).
- Обов'язковий зелений чек `test` (`.github/workflows/ci.yml`, required status check з ADR-0025); червоний CI = стоп.
- Мерж (merge-комітом) робить лише власник — це «схвалюю» в термінах ADR-0023. Агент ніколи не мержить PR і не намагається пушити в main.
- Після мержу: `git checkout main && git pull --ff-only` (мержі — merge-комітами, тож fast-forward коректний), гілку видаляємо; тег `iter-X.Y` — на merge-коміті в main після валідації людиною.
- Захист гілки (фактичні правила): заборона force-push і видалення, обов'язковий чек `test`, вимога PR + 1 approving review, `enforce_admins: true` — чинний і для власника.

## Наслідки

Кожна сесія припиняє ламатись об захист main: процес у AGENTS.md/workflow.md збігається з механізмом репозиторія. Мерж = явне рішення власника, CI обов'язково зелений до мержу — «CI — останній рубіж» тепер наскрізний. Ціна: +1–2 хвилини на PR; зміна налаштувань захисту GitHub — свідома дія власника, яка має супроводжуватись новим ADR (правило цього ADR). Зміна рішення — новий ADR із полем Supersedes.
