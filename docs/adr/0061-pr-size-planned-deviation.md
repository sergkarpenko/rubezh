# 0061. Плановані відхилення від ліміту розміру PR

- Статус: accepted (мерж PR власником = «схвалюю» — конвенція ADR-0023/0052)
- Дата: 2026-10-17
- Частково Supersedes: ADR-0036 (механізм винятків; базовий ліміт 500 рядків лишається; прецедент часткового Supersedes — ADR-0031)
- Автор: Vibe Code (рішення власника у ретроспективі П11.2 2026-10-17, варіант «c»)

## Контекст

ADR-0036 встановив жорсткий ліміт 500 рядків зміни (delta) на PR. Ретроспектива П11.2 (2026-10-17) показала тертя: крок плану «модуль + тести за критеріями + сейв-інтеграція» (П11.2, диф 701 рядок) фізично не влазить у 500 без штучного розривання — серія з 3 PR рве тести між PR (гірше для рев'ю і гейту codecov/patch), а звернення до власника посеред виконання — зайвий цикл: єдина затримка сесії. Водночас побічний ефект ліміту корисний і підтверджений фактом: він змусив порахувати диф до коміту, шукати шов модульності та стиснути тестовий файл 414 → 352 рядки без втрати покриття.

## Рішення

Ми використовуємо ліміт 500 рядків як базовий рубіж, а винятки робимо планованими — на етапі планування, а не посеред виконання (варіант «c», рішення власника 2026-10-17):

1. Базовий ліміт 500 рядків delta зберігається для всіх PR за замовчуванням.
2. Work-сесія при плануванні кроку оцінює прогноз дифа (сума: новий/змінений код + тести за критеріями кроку):
   - прогноз у межах 500 — крок планується як один PR;
   - прогноз понад 500 — крок одразу планується або як серія 2–3 PR, кожен з незалежно зеленими тестами і смисловим швом (прецедент пR.3), або з явним записом у кроці плану: «прогноз дифа ~N рядків; відхилення від ADR-0036 схвалено планом» (мерж плану власником = схвалення відхилення, ADR-0023/0052).
3. Виконавча сесія не зупиняється посеред кроку на питанні про розмір: план містить схвалене відхилення → один PR з посиланням на план; не містить, а диф вийшов понад 500 → серія PR або повернення до власника ДО реалізації.
4. Незаплановане перевищення без запису в плані — відхилення, що потребує явного апруву власника в сесії (прецедент: П11.2, PR #141, 701 рядок).

## Наслідки

- Ліміт лишається гейтом проти неконтрольованих PR; виняток стає планованим записом у кроці плану, а не імпровізацією виконавця посеред сесії.
- Work-сесії додається дешевий обов'язок оцінки обсягу кроку (сума критеріїв, не точна оцінка).
- Продовжують діяти винятки ADR-0036: docs-PR і Dependabot — без обмежень; виняток «рефакторинг за попереднім схваленням» тепер покривається пунктом 2 (запис у плані).
- Зміна базового ліміту або механізму — лише через новий ADR з полем Supersedes.

## Альтернативи

- Підняти межу до 700–800 рядків для фіч-PR з покриттям ≥ 80% — відкинуто власником (варіант «a»): слабший гейт, тиск на декомпозицію зникає.
- Лишити як є: ліміт + звернення до власника посеред виконання — відкинуто власником: зайвий цикл, уже спожитий у П11.2.
- Плановані відхилення без збереження жорсткого ліміту — відкинуто: ліміт дає корисний тиск на декомпозицію і стиснення тестів (факт П11.2).
