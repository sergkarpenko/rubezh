# ADR-0050: Схвалення merge — один власник

**Статус:** accepted
**Дата:** 2026-10-15
**Автор:** Vibe Code (за рішенням власника 2026-10-15)
**Заміняє:** -
**Суперседе:** ADR-0039
**Доповнює:** ADR-0023 (мерж = «схвалюю»), ADR-0028 (гілка + PR, merge власником), ADR-0034 (гейт codecov/patch)

---

## Контекст

ADR-0039 вимагає мінімум 2 схвалення для merge PR у main, посилаючись на практики великих команд (Google, Microsoft, Netflix), і заявляє «Заміняє: ADR-0028». У «Рубіжу» один власник-людина і AI-агенти: агент не може бути другим рев'юером (схвалення — людська відповідальність, ADR-0023), тож правило у поточній конфігурації рівнозначне повній зупинці мержів. ADR-0039 ніде не впроваджено (AGENTS.md/workflow.md/GitHub далі описують merge власником за ADR-0028/0023), але сам факт його існування з полем «Заміняє: ADR-0028» сіє суперечність для кожної нової сесії, яка читає ADR як джерело правди.

Власник ухвалив (2026-10-15, ревізія впроваджень ADR-0036–0048): правило двох схвалень шкідливе, повернутися до схвалення одним власником.

## Рішення

1. Схвалення PR = merge власником = «схвалюю» (ADR-0023/0028) — без змін, один рев'юер-людина.
2. Механізм якості, який реально діє в репозиторії, — механічні гейти, а не кількість рев'юерів: обов'язкові зелені чеки `test` (ci.yml) і `codecov/patch` ≥ 95% (ADR-0034), ліміт розміру PR ≤ 500 рядків (ADR-0036), плани EARS (ADR-0023).
3. Якщо в проєкті з'явиться другий рев'юер-людина, рішення можна переглянути новим ADR.

## Реалізація (налаштування GitHub, власник 2026-10-15)

Branch protection для `main`: Require a pull request before merging — увімкнено; **required approvals — 0** (автор PR = власник: агент пушить гілки обліковим записом власника, GitHub забороняє самосхвалення, тож «1 approval» блокує мерж або працює як пустий гейт через admin-bypass — механічний двійник ADR-0039); required status checks — `test` + `codecov/patch` (ADR-0034); Require linear history — вимкнено (мерж — merge-комітами, теги iter-X/Y стоять на merge-комітах); Allow force push / Allow deletion — вимкнено (ADR-0025/0028).

## Наслідки

### Переваги
1. Процес доставки не блокується; чинна практика (ADR-0028) і документація знову узгоджені.
2. Якість контролюється механізмами репозиторія (CI-гейти), які не залежать від уваги людей — сесія агента скінчена, CI ні.

### Недоліки
1. Один рев'юер — менше очей; компенсується CI-гейтами і детермінованими тестами.

## Ревізія

Переглядається новим ADR при появі другого постійного рев'юера-людини.
