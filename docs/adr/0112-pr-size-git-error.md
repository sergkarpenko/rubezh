# 0112. `scripts/pr-size.sh`: помилка git — код 2, а не «0 рядків» і `[OK]`

- Статус: accepted (мерж PR власником = «схвалюю» — конвенція ADR-0052)
- Дата: 2026-11-22
- Доповнює: ADR-0077 (скрипт і workflow `pr-size`; коди виходу 0 і 1 без змін), ADR-0036 (ліміт 500 рядків), ADR-0018 (workflow без змін)
- Автор: Claude Code (рішення власника 22.11.2026 на фініші Т.112 кнопкою — «pr-size.sh і помилка git (Recommended)»; кандидат 31)

## Контекст

- `pr-size.sh` рахував рядки конвеєром `git diff --numstat "$BASE...$HEAD" | awk …` усередині `$(…)`. Код виходу конвеєра — код `awk`, тож збій git губився: `awk` бачив порожній вхід і друкував `TOTAL 0`, скрипт — «Разом у підрахунку: 0 рядків» і `[OK]`, код 0.
- Замір у Т.113 на `985f2e0` (тимчасовий репозиторій з двома гілками без спільного предка): `pr-size.sh master other` — «fatal: … no merge base», потім «0 рядків», `[OK]`, код 0; `pr-size.sh nosuch HEAD` — «unknown revision», «0 рядків», `[OK]`, код 0.
- Так буває в мілкому клоні агента (`--depth=1`, після нового коміту в `main` спільного предка немає) — довідник `docs/agents/common.md` попереджав про це з Т.36. У CI (`fetch-depth: 0`) вада не проявлялась, але тихий `[OK]` там пропустив би PR без підрахунку.
- `scripts/pr-class.sh` такої вади не має: диф береться присвоєнням, і збій git дає ненульовий код (`nosuch HEAD` — код 128).

## Рішення

1. Перед дифом скрипт перевіряє: обидві ревізії є в клоні (`git rev-parse --verify`) і мають спільного предка (`git merge-base`). Ні — повідомлення `[FAIL] …` (у CI — `::error::…`) з порадою `git fetch --depth=50 origin main` і код виходу 2.
2. Диф береться окремим присвоєнням `NUMSTAT="$(git … diff --numstat …)"`; його ненульовий код — те саме повідомлення і код 2. `awk` читає вже збережений вивід.
3. Коди 0 (у межах ліміту чи плановане відхилення) і 1 (перевищення) — без змін; код 2 уже означав неправильні аргументи, тепер ще й «розмір не пораховано».
4. Workflow `pr-size` без змін: ненульовий код червонить чек, як і раніше.

## Наслідки

- Перевірка Т.113: без спільного предка, з неіснуючою базою чи головою — `[FAIL]` і код 2 (з `GITHUB_ACTIONS=true` — `::error::`); порожній диф (`master master`) — «0 рядків», `[OK]`, код 0; звичайна гілка з кодом і документом — 1 рядок, документ поза підрахунком; PR #427 (`985f2e0^1…985f2e0^2`) — 5 рядків і старою, і новою версією.
- Відхилено: `set -o pipefail` (скрипт — `#!/bin/sh`, POSIX `sh` до 2024 року `pipefail` не мав, `dash` старших версій його не знає); самоперевірка `--self-test` за зразком `pr-class.sh` (потрібен новий крок у workflow — окреме рішення з ADR-0018; кандидат на потім); зміна `pr-class.sh` (вади немає).
