# 0059. Звуковий шар — WebAudio синтезом кодом

- Статус: accepted (рішення власника в сесії П11.7, 2026-10-17: межі серії «2 PR» і дефолт «звук увімкнено» ухвалені на старті кроку; мерж PR власником = «схвалює» — конвенція ADR-0023/0052)
- Дата: 2026-10-17
- Доповнює: ADR-0003 (детермінізм), ADR-0010 (ванільний TS у відображенні), ADR-0012 (без нових залежностей), ADR-0037 (модульна архітектура src/ui/\*), ADR-0026 (тумблер у localStorage поза сейвом), ADR-0063 (headless-DOM-смок — аудіо не має кидати в headless)
- Автор: Vibe Code (сесія П11.7; план кроку — Фаза 11 у docs/workflow.md, контекст ADR-0058)

## Контекст

Фаза 11 додала науку, цех і предмети; гра має повний бойовий цикл (постріли трьох режимів, смерть, перехоплення, місії), але без звукового супроводу. Аудіофайли збільшили б репозиторій і вагу прев'ю, а аудіобібліотеки — залежності (ADR-0012). Браузерний WebAudio вміє синтезувати звуки кодом (осцилятори, шумовий буфер, огинаючі гучності) — це відповідає принципу «ванільний TS» (ADR-0010) і мінімалізму (ADR-0007 за духом).

Обмеження середовища: autoplay policy браузерів дозволяє звук лише після жесту користувача; jsdom (ADR-0013) і headless-смок (ADR-0063) живуть без WebAudio — модуль не має кидати винятки в цих середовищах; детермінізм (ADR-0003) забороняє вплив звуку на траєкторії і стан.

## Рішення

1. **Синтез кодом, без аудіофайлів і залежностей (ADR-0012).** Модуль `src/ui/audio.ts` — шар відображення (ADR-0037; прецедент модулів src/ui/\*), не core: звук суто відображення, стан гри і траєкторії — байт-у-байт незмінні (критерій 1).

2. **Рецепти — детерміновані константи.** Осцилятори (square/sawtooth/triangle/sine) з огинаючими гучності через `setValueAtTime`/`exponentialRampToValueAtTime`; шум — буфер, заповнений фіксованим LCG (жодного `Math.random`; ADR-0003 — випадковість лише у виводі на колонки, не в стан).

3. **Набір звуків:** постріли трьох режимів (короткий/прицільний/черга — різні сигнатури), влучання, смерть, виявлення НЛО, результат місії (перемога/поразка), клік UI.

4. **Лінива ініціалізація + typeof-гейт.** `AudioContext` створюється при першому виклику звуку (перша/graph — клік користувача, autoplay policy); `typeof AudioContext` відсутній (jsdom, старі браузери) → модуль no-op без винятків — патерн `hasRaf` (main.ts). Стан `suspended` → тихий `resume()` у try/catch.

5. **Wiring без дублювання умов:** звук там, де журнал уже бачить подію — drain-контур `journal.ts` (`onBattleSound`/`onGeoSound` — опціональні залежності: постріл/влучання/смерть з бойових подій, виявлення НЛО і результат місії з geo-подій); клік UI — делегований слухач на `document` (усі `button`).

6. **Тумблер у топбарі.** Кнопка `#btn-sound`; стан — localStorage, ключ `rubezh.sound` ('1'/'0'), **поза сейвом** (ADR-0026 не зачіпається, формат сейву без змін). Дефолт за відсутності ключа — **увімкнено** (рішення власника, сесія П11.7). Недоступне сховище — тихо: стан не персиститься (гілки помилок сховища — в adapter з try/catch, прецедент save-panel.ts), тумблер у сесії працює, повідомлень у журнал нема.

## Наслідки

- Тести аудіо-модуля — на моках (jsdom без WebAudio): мок `SoundContext`, перевірки параметрів синтезу за подіями, no-op без API, тумблер з гілками помилок сховища; критерій 1 — лог бою + `rng.state` байт-у-байт зі звуком «увімкненим» (мок) і без (патерн ізоляції П11.2/П11.4).
- Headless-DOM-смок (ADR-0063) лишається зеленим: typeof-гейт — нуль pageerror у headless.
- Ядро `src/core/`, сейв-формат, e2e/смоки — без змін; покриття ядра ≥ 80% не падає (файли кроку — у src/ui).
- Зміна наборів звуків/рецептів (константи відображення) — без ADR; зміна способу (залежність, аудіофайли) — лише новий ADR із полем Supersedes.
