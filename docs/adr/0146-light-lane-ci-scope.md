# 0146. Легка зміна і обсяг перевірок CI за зміненими файлами

- Статус: accepted (мерж PR власником = «схвалюю» — конвенція ADR-0052)
- Дата: 2026-11-25
- Частково Supersedes: ADR-0094 п. 4–5 (аудит — умова мержу класу `auto`: для легкої зміни не потрібен), ADR-0097 і ADR-0104 (два аудитори на кожному PR: на легкій зміні — жодного), ADR-0076 (окремий крок `npm test` у джобі `test`)
- Доповнює: ADR-0018 (зміна workflow з ADR), ADR-0128 і ADR-0131 (`shuffle`), ADR-0080 і ADR-0082 (`e2e`), ADR-0034 (`codecov/patch`), ADR-0093 (тег кроку), ADR-0014 (pre-commit)
- Автор: Claude Code (рішення власника 25.11.2026 кнопкою — «Легка смуга + CI (Рекомендовано)»; запит власника того ж дня: «валідації кожної зміни досить довгі навіть якщо зміни тільки в документації або допоміжних скриптах… невеличких змін багато… гра майже не розвивається»)

## Контекст

- Вимір 25.11.2026 (прогони `ci` PR #490–#494, журнал джоб): увесь `ci` на PR — ≈ 2 хв; `npm test` 23 с і одразу той самий прогін з покриттям `npm run test:coverage` 33 с; `e2e` ≈ 1 хв 50 с; `vibe-audit` 1,5–5 хв. Від відкриття PR до мержу — 8–20 хв; крок цілком (Т.177–Т.180 поспіль) — 35–60 хв і 0,8–1,7 млн токенів.
- Отже, час кроку з'їдає не CI, а однаковий для будь-якої зміни шлях: номер кроку, запис у `docs/workflow.md`, тег, два аудитори, другий пуш виправлень за аудитом, журнал і документ стану сесії. Рядок документації проходить його так само, як зміна ядра.
- За документом стану сесії з Т.136 по Т.180 зміни, помітні гравцеві, — приблизно 7 кроків із 45; активної фази гри немає від `v0.7.0` (Т.77).
- Фільтри `paths` на рівні workflow не годяться: обов'язковий чек, чия джоба не стартувала, висить «Expected» і блокує мерж; джоба, пропущена через `needs`, вважається зеленою — помилка визначення обсягу тихо пропустила б перевірки.

## Рішення

1. **Рівень зміни** дає `scripts/ci-scope.sh <base> <head>` (диф від спільного предка): `docs` — лише `docs/**`; `tools` — ще `scripts/**` і кореневі `*.md`; `full` — усе інше. Файл тестів будь-де, сам скрипт, `scripts/pr-class.sh`, посилання, підмодуль і порожній диф — `full`. Помилка git — код 2. Самоперевірка — `--self-test`.
2. **CI за рівнем** (`ci.yml`): кожна джоба стартує завжди і першим кроком визначає рівень (`HEAD^1 HEAD` merge-коміту PR, `fetch-depth: 2`); решта кроків — з умовою. `docs`: лише перевірка оболонки workflow; `tools`: ще `tsc -p tsconfig.scripts.json`, лінт, формат; `full`: усе, як раніше. `shuffle` і `e2e` поза `full` — лише крок рівня. Помилка скрипта червонить джобу.
3. **`codecov/patch`** поза `full`: крок `codecov-action` з `run_command: empty-upload` і `force: true` — без звіту чек інакше не приходить.
4. **Один прогін тестів у джобі `test`:** крок `npm test` прибрано — `npm run test:coverage` ганяє ті самі тести.
5. **Легка зміна** — рівень не `full` і клас `auto` за `scripts/pr-class.sh` (одна команда: `sh scripts/ci-scope.sh --light <base> <head>` → `light=true`). Для неї:
   - немає номера кроку, запису в `docs/workflow.md`, рядка `Iter-Tag` і ADR;
   - аудиту немає: субагента не запускати, `vibe-audit` пропускає кроки аудиту сам — рівень і клас рахує скриптами з бази PR (ручний запуск — завжди аудит);
   - мерж — сесією після зелених обов'язкових чеків, без «схвалюю»; власникові — один рядок: номер PR і що змінено;
   - окремої сесії на неї не відкривати: легкі зміни їдуть у PR найближчого кроку гри (тоді це звичайний PR кроку) або копляться в один PR на фазу.
6. **Кандидати процесу заморожено на час фази гри:** новий кандидат записується, але кроком не стає; після фази — один технічний блок з тих, що двічі завадили кроку гри або економлять виміряний час. Виняток — поломка, що блокує мерж.
7. **Pre-commit:** `npm test` у хуку — лише для рівня `full` індексу (`ci-scope.sh --staged`; помилка скрипта — `full`).

## Наслідки

- PR лише з документів: `ci` — до ≈ 20 с замість ≈ 2 хв, без `vibe-audit`; головний виграш — пункт 5: немає запису кроку, аудиту і другого пушу.
- Обов'язкові чеки `main` і захист гілки без змін; `pr-size` і `check` — як раніше (PR без рядка `Iter-Tag` чек `check` пропускає).
- Ризик: помилку в документі чи допоміжному скрипті аудитор більше не ловить. Прийнято: такі помилки не доходять до гравця, а їх виправлення і породжувало більшість дрібних кроків. ADR, `AGENTS.md`, `README.md`, правила `docs/workflow.md`, скрипти CI і хуків — клас `approve`, тобто не легка зміна: «схвалюю» й аудит лишаються.
- Не перевірено до мержу: порожнє завантаження Codecov на справжньому PR рівня `docs` (цей PR — `full`). Перший легкий PR після мержу — перевірка; якщо `codecov/patch` не приходить, виправлення — окремим PR (поломка, що блокує мерж).
- Відхилено: `shuffle` за розкладом замість PR — зміна захисту `main` у браузері власника заради ≈ 40 с паралельної джоби; окрема джоба `scope` з `needs` — пропущені залежні джоби зелені; фільтри `paths` — обов'язкові чеки висять; лишити `vibe-audit` на легких змінах — він і давав другий пуш.
