# 0065. Каркас екранів і навігації: стартовий екран, вікно налаштувань, вкладки колонки

- Статус: accepted (подано разом з планом Фази 12; мерж PR власником = «схвалюю» — конвенція ADR-0023/0030/0052)
- Дата: 2026-10-18
- Доповнює: ADR-0027 (каркас прев'ю — лишається ігровим екраном), ADR-0010 (цільовий UI — ванільний TS + Canvas 2D), ADR-0026 (налаштування — localStorage поза сейвом), ADR-0059 (тумблер звуку мігрує у вікно налаштувань), ADR-0033 (складність — у діалозі нової партії), ADR-0058 (числові ефекти — з констант каталогів)
- Автор: Vibe Work (рішення власника — сесія планування П12.1 2026-10-18)

## Контекст

Після Фаз 6–11 статус-колонка ігрового екрана накопичила п'ять панелей (фінанси, ростер, дослідження, цех, збереження) — єдиний екран перевантажено, на планшеті незручно (фідбек власника). Немає стартового екрана: сторінка одразу кидає в ігровий інтерфейс; налаштування розкидані (тумблер звуку в топбарі). Фідбек власника про розвиток: «усе підписано, але що отримає гравець — незрозуміло». Ігровий UX-стандарт: меню до старту гри, налаштування — окремим вікном, мінімум рівнів навігації, результат рішення видимий до вибору.

## Рішення

**Стани шару відображення** (`src/main.ts` + новий модуль `src/ui/screens.ts`; ядро не зачіпається):

1. **Стартовий екран** (без активної партії): логотип «Рубіж», меню — «Нова партія» (діалог: сід, складність легкий/норма/складний — ADR-0033), «Продовжити» (останній активний слот; за відсутності сейвів — недоступний; вибір слота — 3 слоти за ADR-0026), «Налаштування», «Як грати» (help.ts без змін), версія гри (ADR-0054 п.5).
2. **Ігровий екран** — чинний каркас ADR-0027 (топбар + фокусна зона + колонка стану + журнал); у топбарі додається кнопка «Меню».
3. **Модальні вікна**: «Налаштування» — секція «Звук» (міграція тумблера з топбара, ADR-0059; контракт «тихо» на помилки сховища), формат розширюваний (ключі `rubezh.settings.*` у localStorage поза сейвом); «Меню» — у грі: Налаштування, «Як грати», «На стартовий екран» (вихід із підтвердженням, якщо після останнього збереження були зміни).

**Реструктуризація статус-колонки (геосцена):** вкладки «Загін» (ростер, екіпірування, фінанси), «База» (дослідження, цех), «Система» (збереження). Журнал лишається окремою зоною з вкладками подій (Фаза 6a). Активна вкладка запам'ятовується (localStorage). У бою колонка приглушена (патерн Фази 6a) — фокус на бойовищі не конкурує з вкладками.

**Зрозумілість розвитку (геосцена):** картки протоколів і предметів показують числовий ефект ДО дії: «+2 макс. HP (10 → 12)», «+5% точності (кап 95%)», «пошкодження 3–5, зона хреста, уражає і своїх», «+2 урону за раунд повітряного бою». Джерело чисел — константи каталогів ядра (ADR-0058; одне місце правди — текст ефекту не дублює числа руками). Кнопки без AP/коштів показують причину (патерн П6.14).

**Навігаційні правила:** перехід між екранами — миттєвий, без анімацій на rAF (інваріант idle → 0 перерисовок); глибина меню до гри — максимум один діалог; нові елементи отримують семантичні класи без колізій з чинними контрактами DOM-тестів (урок П11.6).

## Наслідки

- Гра починається як «гра»: власна точка входу, налаштування в одному місці, розвантажений ігровий екран; ризик перевантаження колонки знімається вкладками.
- Шар відображення зростає модульно (screens.ts, вікно налаштувань); щоб main.ts не перевищив ліміт ADR-0036 — прогноз дифа на плануванні, серії за ADR-0061.
- DOM-тести флоу екранів — критерій кроків П12.2–П12.5; валідація візуальних кроків — через прев'ю гілок до мержу (практика П11.5+).
- Зміна каркасу — новий ADR із полем Supersedes.

## Альтернативи

- Два окремих застосунки (меню ігра окремими бандлами) — відхилено: один бандл і стан екранів у шарі відображення простіші, деплой Pages не міняється.
- Налаштування інлайн у топбарі (тумблери) — відхилено власником: окреме вікно.
- Реструктуризація колонки окремою фазою — відхилено власником: повний флоу в одній фазі.
- Автозбереження при виході на стартовий екран — відхилено: рішення про збереження лишається за гравцем (ADR-0026 — лише вручну).
