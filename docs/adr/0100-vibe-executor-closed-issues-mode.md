- Статус: accepted (мерж PR власником = «схвалюю» — конвенція ADR-0018/0052)
- Дата: 2026-11-19
- Частково Supersedes: ADR-0042 (лише роль Vibe Code як виконавця планів іншого агента — для кроків Т.N; ролі Vibe Work і решта ADR-0042 без змін)
- Частково Supersedes для PR із задач issue (п. 4): ADR-0094 п. 3–4 (мержить і запускає аудит сесія приймання, а не автор PR; замість звіту кроку — issue і опис PR) і ADR-0097 п. 1 і п. 4 (аудитора для мержу запускає сесія приймання; рахунок аудиторів — в описі PR, не в записі кроку). Для кроків Т.N обидва ADR без змін
- Доповнює: ADR-0094 (клас PR), ADR-0096 (довідники агентів), ADR-0097 (два аудитори на кожному PR)
- Автор: Claude Code (рішення власника 2026-11-19 у чаті перепланування після Т.73; задача Т.74)

## Контекст

З Т.39 частину кроків виконував Mistral Vibe Code за планом сесії Claude: план у `docs/plans/`, шаблон `docs/plans/TEMPLATE-vibe.md` (Т.52–Т.67), скрипти `scripts/vibe-plan-blocks.mjs`, `scripts/vibe-plan-check.mjs`, `scripts/vibe-step.py` (Т.54–Т.70), прототип планувальника, навмисні поломки, аудит і порції знахідок для виконавця.

Власник (19.11.2026, дослівно): «використання vibe code як зараз недоречне, опус його повністю контролює і по суті дублює роботу… ідея була в тому щоб робити більше, по ітогу робимо менше, довше і дорожче».

Числа: розміри PR — `./scripts/pr-size.sh <merge>^1 <merge>` на merge-комітах кроків; ціна і звернення Т.44–Т.49 — розклад у розділі «Ціна сесії» `docs/agents/common.md`; Т.71 і Т.73, час до мержу — журнал сесій власника поза репозиторієм.

| Що | Кроки | Розмір PR | Ціна сесії Claude | Звернень |
| --- | --- | --- | --- | --- |
| крок гри, код пише сесія Claude, один PR | Т.45–Т.49 | 74–155 рядків | ≈ 0,92–1,22 млн | 21–31 |
| те саме, три PR трьома сесіями | Т.44 | 297, 478 і 312 рядків | ≈ 5,45 млн (1,43–2,48 на сесію) | 119 |
| крок гри силами Vibe, один PR | Т.71, Т.73 | 406 і 219 рядків | ≈ 6,4 і ≈ 5,1 млн | 146 і 124 |

Т.72 (силами Vibe, 189 рядків) у таблиці немає: сесія ціну не записала. Час до мержу: крок сесії Claude з одним PR — ≈ 45 хв, Т.71 і Т.73 — ≈ 2 год 10 хв.

Із 24 кроків Т.50–Т.73 дев'ять — шаблон і скрипти для Vibe, п'ять — по одному тесту силами Vibe, шість — зміни, які бачить гравець. У Т.71 і Т.73 код виконавця збігався з прототипом планувальника побайтно: роботу зроблено двічі. (Застереження: Т.44–Т.49 — інша модель і виміряно до мержу й запису документів.)

## Рішення

1. **Схему «Vibe — виконавець за планом Claude» згорнуто.** Нових кроків Т.N з виконавцем Vibe немає; код кроків гри пише сесія, яка веде крок.
2. **Шаблон, зразки планів і скрипти схеми заморожено, не видалено:** `docs/plans/TEMPLATE-vibe.md`, `scripts/vibe-plan-blocks.mjs`, `scripts/vibe-plan-check.mjs`, `scripts/vibe-plan-check-selftest.mjs`, `scripts/vibe-step.py` — позначка «заморожено (ADR-0100)» на початку файла; далі не уточнюються. Плани кроків `docs/plans/t39-…`–`t73-…` — записи виконаних кроків, лишаються як є без позначки. Матеріал лишається для занять і для історії.
3. **Довідник `docs/agents/common.md`:** розділ «Крок, який виконує інший агент» скорочено до посилання на цей ADR; повний текст — `git fetch --depth=1 origin tag iter-T.73 && git show iter-T.73:docs/agents/common.md`.
4. **Режим Issues (спосіб 1), експеримент:**
   - задача — GitHub issue з міткою `vibe` за шаблоном `.github/ISSUE_TEMPLATE/vibe.md`: що зробити, механічний оракул, чого не чіпати, клас PR лише `auto` (ADR-0094);
   - агент (Mistral Vibe Code) бере issue — номер дає сесія, що його запустила, або перше вільне з міткою `vibe` — і сам робить гілку і PR без номера кроку і без рядка `Iter-Tag` (workflow `iter-tag` такий PR пропускає, чек `check` лишається зеленим — `scripts/iter-tag.sh`, зміна `.github/workflows/` не потрібна); в описі PR — `Closes #N`;
   - приймає PR пачкою окрема сесія Claude: диф, чеки, обидва аудитори (ADR-0097; аудитора для мержу запускає вона), знахідки — коментарем у PR, **одне коло виправлень**, далі мерж (клас `auto`, мержить сесія приймання) або закриття PR і повернення задачі в кандидати;
   - рахунок аудиторів (знайдено / підтверджено) і кіл виправлень — розділ «Аудит» в описі PR, який дописує сесія приймання; ціна пачки і на PR — рядок у журналі сесій власника; результат КТ — новий запис у `docs/workflow.md` разом із наступним кроком процесу або ADR закриття режиму;
   - як агентові брати issue — розділ «Задача з issue» у `docs/agents/common.md`.
5. **Контрольні точки (вимога власника 19.11.2026: «якщо буде все одно неефективно, то залишити тільки аудіт»):**
   - КТ-0 — підготовка режиму вкладається в цей крок; окремих кроків процесу «для Vibe» після нього немає;
   - КТ-1 — після першої пачки (3–4 PR): змержено щонайменше половину; жодному змерженому не треба було більше одного кола; приймання ≤ ≈ 0,7 млн на PR; крок гри поруч не затримався;
   - КТ-2 — після другої пачки: ті самі умови і ≤ ≈ 0,5 млн на PR; рішення — не пізніше релізу v0.7.0;
   - КТ не пройдено → режим закривається рядком нового ADR, Mistral лишається лише аудитором у CI (ADR-0097).
6. Склад аудиторів (ADR-0097), workflow-файли, скрипти CI і `package.json` цим ADR не змінюються.

## Уроки згорнутої схеми (спостереження після мержу Т.73; у довідник не переносяться)

- `vibe-step.py docs` звіряє з таблицею плану лише кольори поломок, а не те, чи якір виконавця ламає описане: у Т.73 поломка 3 у виконавця ламала гілку Esc узагалі, кольори збіглися випадково.
- Порядок і умови з опису поведінки виконавець легко спрощує (Т.73: порядок Esc і умова повернення фокусу). Звідси для режиму Issues: давати лише задачі, де результат перевіряє механічний оракул.
- Вікно сесії Vibe під час ущільнення контексту ≈ 2 хв показує лише перше повідомлення і «Thinking» — це не зависання; стан брати з GitHub.

## Наслідки

- Крок гри знову веде одна сесія: план, код, тести, аудит, мерж; Vibe не дублює планувальника.
- Vibe отримує вузькі задачі поза грою з оракулом, який перевіряє команда; приймання не потребує плану й прототипу.
- Кандидати процесу про шаблон і скрипти Vibe знято; кандидат «режим Issues, спосіб 2» (Action → Vibe CLI) — лише після пройденої КТ-2.

## Альтернативи

- **Лишити схему й уточнювати шаблон далі** — відхилено власником: дев'ять кроків шаблону не зробили крок Vibe дешевшим за крок сесії.
- **Одразу лишити Mistral лише аудитором** — відкладено: спершу дві пачки issue з контрольними точками.
- **Видалити шаблон і скрипти** — відхилено: матеріал потрібен для занять; заморожений файл не заважає.

## Критерії приймання

- `AGENTS.md` має рядок ADR-0100 у таблиці ADR;
- скрипти й шаблон п. 2 мають позначку «заморожено (ADR-0100)» у перших рядках і без інших змін;
- `.github/ISSUE_TEMPLATE/vibe.md` є, ≈ 10 рядків, клас `auto`; `.github/workflows/` не змінено;
- `docs/agents/common.md` має розділ «Задача з issue» і не має розділу з порадами кроку Vibe за планом.
