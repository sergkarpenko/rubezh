# 0036. Обмеження розміру Pull Request

- **Статус:** accepted
- **Дата:** 2026-10-15
- **Автор:** Vibe Code (за запитом користувача)

## Контекст

Поточний процес дозволяє PR будь-якого розміру. Аналіз останніх PR показує:
- PR #62 (п8.3) мав ~200 рядків зміни — прийнятний розмір
- Деякі історичні PR перевищували 1,000+ рядків, що ускладнює рев'ю

Великі PR мають такі недоліки:
- Складніше рев'ювати (потрібен значний час на аналіз)
- Вищий ризик пропустити помилки
- Складніше тестувати та перевіряти
- Ускладнює відстеження змін

## Рішення

Встановити **жорстке обмеження розміру PR до 500 рядків зміни (delta)**.

### Винятки:
- **Рефакторинг коду** — з попереднім схваленням у workflow.md
- **Документаційні зміни** — без обмежень
- **Dependabot PR** — автоматичні оновлення залежностей

## Наслідки

### Переваги:
- Швидше рев'ю коду
- Зменшення ризику помилок
- Краща модульність змін
- Простіше тестування

### Недоліки:
- Деякі великі функції доведеться розбивати на кілька PR
- Додаткові накладні витрати на управління декількома пов'язаними PR

### Альтернативи, які були розглянуті:

1. **М'яке обмеження (soft limit)** — просто попередження, без блокування
   - ❌ Не вирішує проблему великих PR

2. **Обмеження 1,000 рядків**
   - ❌ Все ще надто великий для ефективного рев'ю

3. **Обмеження за кількістю файлів**
   - ❌ Не враховує складність змін у кожному файлі

4. **Обмеження за часом рев'ю**
   - ❌ Суб'єктивний критерій, важко автоматизувати

## Реалізація

1. **GitHub Branch Protection** (для `main`):
   - Додати **required status check** для перевірки розміру PR (через GitHub Action)
   - Використати [size-label-action](https://github.com/pascalgn/size-label-action) для автоматичного міткування PR за розміром
   - Блокувати merge для PR з міткою `size/XL` (понад 500 рядків)

2. **GitHub Action для перевірки розміру:**
   ```yaml
   # .github/workflows/pr-size-check.yml
   name: PR Size Check
   on:
     pull_request:
       types: [opened, synchronize, reopened, edited]
   
   jobs:
     size-check:
       runs-on: ubuntu-latest
       steps:
         - uses: pascalgn/size-label-action@v1
           with:
             sizes: |
               xs: 0
               s: 100
               m: 300
               l: 500
               xl: 1000
         - name: Block if XL
           if: contains(github.event.pull_request.labels.*.name, 'size/XL')
           run: |
             echo "::error::PR перевищує 500 рядків зміни"
             exit 1
   ```

3. **Оновлення документації:**
   - Додати правило до `AGENTS.md` у розділ "Дозволено"
   - Оновити `docs/workflow.md` з новим обмеженням

4. **Шаблон PR:**
   - Додати поле `Depends on: #XXX` для зв'язку пов'язаних PR
