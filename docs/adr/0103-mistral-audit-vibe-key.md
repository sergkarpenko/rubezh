# 0103. Аудитор `mistral-audit` — на ключі Vibe

- Статус: accepted (мерж PR власником = «схвалюю» — конвенція ADR-0018/0052)
- Дата: 2026-11-20
- Доповнює: ADR-0095/0097/0098 (аудитор Mistral `mistral-audit`), ADR-0102 (проба Vibe CLI, секрет `MISTRAL_VIBE_API_KEY`), ADR-0018 (зміна workflow — з ADR у точці коміту)
- Автор: Claude Code (рішення власника 20.11.2026 на фініші Т.83; задача Т.84)

## Контекст

Джоба `mistral-audit` (ADR-0095) викликає `POST /v1/chat/completions` ключем Studio із секрету `MISTRAL_API_KEY`. Такі виклики на плані Team оплачуються лише з гаманця API, а гаманець не поповнюється (рішення власника). 20.11.2026 з ≈ 13:31 UTC API відповідав 402 `billing_wallet_depleted`; на #397 і #398 знову відповідав при гаманці $0,00 — причину не з'ясовано, тобто на це не можна покладатися.

Проба Т.82 (звіт `docs/reports/t82-vibe-audit-probe.md`) показала: той самий прямий виклик ключем Vibe (секрет `MISTRAL_VIBE_API_KEY`) дає 200 з моделлю `mistral-large-latest`, а панель Mistral (Admin › Usage) записує його як Billable, Vibe Code — тобто з плану Vibe. Рішення власника на фініші Т.83 (кнопкою, дослівно): «86: mistral-audit на ключ Vibe (Recommended)».

## Рішення

1. **Джоба `mistral-audit` бере секрет `MISTRAL_VIBE_API_KEY`.** У скрипт він іде тією самою змінною `MISTRAL_API_KEY`, тому `scripts/mistral-audit.mjs` не переписується; змінено лише текст помилки, коли секрету немає (називає `MISTRAL_VIBE_API_KEY`). Модель, рівень міркувань, контекст (ADR-0098) і самоперевірка (ADR-0099) — без змін.
2. **Старий секрет `MISTRAL_API_KEY` лишається в репозиторії**, але жодна джоба його не читає. Видалити його і ключ `rubezh-ci-mistral-audit` в адмінці Mistral — лише за рішенням власника.
3. **Перевірка наживо — у PR цього кроку:** коментар `mistral-audit` з відповіддю моделі, а в панелі Mistral — запит як Vibe Code.
4. **Збій** — як і раніше (ADR-0095): коментар «Аудиту не було» і зелений чек.
5. **Проба `vibe-audit` (ADR-0102) іде далі без змін.** Її перший рядок (прямий виклик ключем Vibe) тепер дублює `mistral-audit`; прибирати його — разом із рішенням контрольної точки ADR-0102 п. 8.

## Наслідки

- Обидві джоби Mistral витрачають місячний ліміт плану Vibe власника. Прогін `mistral-audit` — ≈ 80–100 тис. токенів вводу і кілька тисяч виводу, тобто менше за прогін `vibe-audit` (≈ 0,95 млн вводу, переважно з кешу).
- Ротація ключа Vibe вимагає оновити один секрет, і він тепер потрібен обом джобам.
- Кандидат 35 (ліміт витрат на ключ `rubezh-ci-mistral-audit`) втрачає сенс, поки ключ Studio не використовується.

## Альтернативи

- **Поповнити гаманець API** — відхилено власником.
- **Перейменувати змінну в скрипті на `MISTRAL_VIBE_API_KEY`** — не взято: більша зміна скрипта і самоперевірки без користі для поведінки.
- **Вимкнути `mistral-audit`, лишити лише `vibe-audit`** — це питання контрольної точки ADR-0102 п. 8 (5 PR), а не цього кроку.
