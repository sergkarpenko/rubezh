# ADR-0053: Справжня фіксована ціль codecov/patch — виправлення конфіга ADR-0034

**Статус:** accepted
**Дата:** 2026-10-15
**Автор:** Vibe Code (технічна задача Т.1)
**Заміняє:** -
**Суперседе:** -
**Доповнює:** ADR-0034 (гейт codecov/patch 95%), ADR-0035 (звіт на PR)

---

## Контекст

ADR-0034 зафіксував ціль patch-покриття `target: 95%` у `codecov.yml`, але фактично чек `codecov/patch` рахував авто-ціль: на PR #83 провалився з «97.77% of diff hit (target 99.38%)» при `target: 95%` у конфізі — порівняння йшло з покриттям тих самих рядків у базі (~покриття репо), а не з 95%. Робоча планка сесій фактично була «100% нових рядків» (урок пR.3). Задача Т.1 (workflow.md): з'ясувати причину або обновити ADR до фактичної поведінки.

**Причина (встановлено 2026-10-15):** `codecov.yml` не проходив валідацію Codecov — поле `only_pull_requests` невідоме схемі:

```
$ curl --data-binary @codecov.yml https://codecov.io/validate
Error at ['coverage', 'status', 'patch', 'default', 'only_pull_requests']:
unknown field
```

Невалідний конфіг Codecov **мовчки відкидає цілком** (без червоного чека чи попередження на PR) — усі статуси падають у дефолтну авто-ціль. Тому фіксований `target: 95%` ніколи не застосовувався: гейт працював, але не з цілю з ADR-0034.

## Рішення

1. **Виправити поле:** `only_pull_requests: true` → `only_pulls: true` (валідна назва поля, та сама поведінка — статус лише для PR). Після правки валідатор повертає `Valid!` з `target: 95.0`.
2. Решта конфіга без змін: `target: 95%`, `threshold: 0%`, project-статус вимкнено — рішення ADR-0034 відновлено як задумано, без зміни суті.
3. **Правило процесу:** кожну зміну `codecov.yml` валідувати перед комітом (`curl --data-binary @codecov.yml https://codecov.io/validate`) — невалідний конфіг не падає ніде помітно, єдиний симптом — «плаваюча» ціль чека.

## Наслідки

- Критерій Т.1 виконано: чек `codecov/patch` на наступних PR порівнюватиме з фіксованою ціллю 95%, заявленою в ADR-0034.
- Гейт стає м'якшим за фактичну робочу планку 2026-10-15 (авто-ціль ~99.4%): диф до 95% нових рядків проходить; серії, що тримали 100%, нічого не втрачають — це повернення до ухваленої власником цифри «Схвалюю, 95%» (ADR-0034).
- Ціна зміни порогу незмінна (ADR-0034): правка `codecov.yml` + новий ADR.

## Зв'язок

- **ADR-0034:** рішення (фіксований target 95% як required check) — без змін; цей ADR фіксує причину, чому воно не застосовувалося, і виправляє реалізацію.
- **ADR-0035:** звіт покриття на PR — без змін; джерело даних гейта те саме.
