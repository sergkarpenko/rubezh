# ADR-0029: Підфаза 6b «Арт» — векторні спрайти й анімація прев'ю (стиль «Гібрид»)

## Статус

proposed (мерж PR власником = «схвалюю» → accepted, ADR-0023)

## Контекст

Графіка проєкту — мінімалізм без художника (ADR-0007): геометричні силуети. Власник обрав стиль C «Гібрид» (2026-10-13): рисованих спрайти юнітів поверх геометричного фону + нескладна анімація. Поточне відображення статичне: юніти — кружки, канви перерисовуються лише на зміну стану; П6.6 запровадив clearRect на весь buffer кожен кадр.

Обмеження: ядро `src/core/` не змінюється (ADR-0002/0010); нові залежності — лише через ADR-0012 (тут не потрібні); детермінізм — лог не залежить від відображення; продуктивність і батарея на iPad Pro; без файлів асетів і художника.

Рішення власника (дизайн-сесія 6b, 2026-10-14): спрайти — векторні, кодом Canvas 2D; набір анімацій — повний на бойовищі плюс пульс радара на геосцені; анімаційний рушій — на розсуд агента (вибір нижче); обсяг — бойовище повністю + мінімальний арт геосцени.

## Рішення

1. **Векторні спрайти кодом.** Юніти малюються Canvas 2D-примітивами (без зовнішніх файлів, без PNG, без залежностей): солдат і прибульчик — різні впізнавані силуети з характером (тіло + зброя «АР-14 Гарт» / «Імпульсний різак»), масштабуються в діапазоні 520–720px. Малювання не викликає RNG.
2. **Хелпер шару відображення.** Чисті функції малювання (спрайти, анімаційні кадри) — в окремому файлі `src/render.ts` (НЕ `src/core/` — ADR-0002; шар відображення за ADR-0010), експортовані для юніт-тестів. main.ts — оркестрація і виклики.
3. **Анімація — суто візуальний шар.** Дії ядра застосовуються миттєво; анімація лише відтворює результат поверх фактичного стану. Стан ядра, `state.log`, траєкторії — байт-у-байт незмінні; анімації не викликають RNG; DOM-тести перевіряють стан, не кадри, і не залежать від анімації.
4. **Анімаційний рушій (вибір агента, авторизовано власником).** Черга анімацій + цикл `requestAnimationFrame`, який працює ЛИШЕ поки є активні анімації (idle → 0 перерисовок — батарея iPad). Кожен кадр — clearRect на весь buffer (урок П6.6); статичний стан малюється існуючими render-функціями, анімаційний шар — зверху.
5. **Набір анімацій (власник, 2026-10-14).** Бойовище: хід юніта (інтерполяція вздовж шляху), трасер кулі, спалах влучання, смерть юніта, спалах заступи. Геосцена (мінімум): пульс радара, м’якші позначки НЛО. Туман війни незмінний: анімується лише видиме гравцю; невиявлені НЛО не показуються і не анімуються (4.2, ADR-0026).

## Альтернативи

- **Растрові PNG-спрайти** (зовнішні файли/генератор) — відкинуто власником: ускладнює pipeline, додаткові файли; можливий апгрейд пізніше поверх того самого інтерфейсу малювання.
- **Постійний rAF-цикл** — відкинуто: марна витрата батареї; idle без перерисовок.
- **Анімація стану в ядрі** — відкинуто: порушує ізоляцію шарів (ADR-0002) і детермінізм логу.

## Наслідки

- Новий файл шару відображення `src/render.ts` + виклики в `main.ts`; ядро, залежності й тести ядра не зачіпаються.
- Юніт-тести чистих функцій малювання — у шарі відображення; DOM-тести лишаються на стані.
- Ризик: складніша логіка головного циклу рендера — контрольовано кроком П6.8 (рушій) з критерієм «idle → 0 перерисовок» і уроком П6.6 (clearRect кожен кадр).
