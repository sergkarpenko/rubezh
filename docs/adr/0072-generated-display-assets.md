# 0072. Згенеровані графічні ассети шару відображення

- Статус: accepted
- Дата: 2026-10-19
- Supersedes: частково ADR-0007, ADR-0031
- Доповнює: ADR-0064, ADR-0065, ADR-0068, ADR-0069, ADR-0071, ADR-0060
- Автор: Vibe Work (П14.1, сесія планування Фази 14)

## Контекст

Фаза 13 (П13.4) довела повний цикл роботи з ассетами на лого стартового екрана: генерація → вибір власника → бінарний коміт Vibe Code → інтеграція → оптимізація (ADR-0068/0069/0071). Після Фаз 12/13 власник оцінив графіку шару відображення «дуже примітивною»: юніти — кодові матриці 16×16 @2× (5–6 кольорів, 2 кадри стій/крок), терен — два тони на клітинку, панелі без графічного оформлення (обраний у П12.7 варіант panel-frame не реалізований), фон стартового екрана — тимчасовий (розите лого; доручення ретроспективи Ф13), геосцена — пласка сітка. 2026-10-19 власник обрав джерело нового вигляду ігрового шару — згенеровані растрові спрайти (фолбек — чинні матриці ADR-0031); backlog відкладено до завершення Фази 14.

## Рішення

1. Джерело графіки шару відображення — згенеровані растрові ассети у папці `assets/`: атлас спрайтів юнітів, тайлсет терену бою, тайли геосцени, рамки панелей (9-slice), іконки вкладок, фон стартового екрана.
2. Стиль — за двома треками ADR-0064: ігровий шар (спрайти, тайли, іконки) — плоский піксель-арт палітри П12.7 (#00E5FF, #FF2E88, #FFB347, #060A14 та похідні); оформлення (рамки, фон стартового екрана) — багатий 3D. Промпти генерації — docs/design/style-references.md (розділ Фази 14).
3. Фолбек обов’язковий: чинні матриці sprites.ts не вилучаються; тести від ассетів не залежать; завантаження ліниве; невдача завантаження — тихий перехід на матриці.
4. Приймання: стиль і прев’ю затверджуються власником ДО мержу (ADR-0069, патерн П11.5+); числа (розміри кадрів, крок сітки, масштаб) узгоджуються ДО прев’ю (урок iter-13.5).
5. Робочий цикл — як у П13.4: генерація у Work-сесії → вибір варіанта власником → бінарний коміт Vibe Code (Work-канал бінарні пуші не підтримує) → інтеграція та оптимізація (ADR-0071).
6. Ядро `src/core/` — без змін; розклад варіантів терену за cellHash без RNG; механізм матриць ADR-0031 лишається фолбеком.
7. Без нових залежностей (ADR-0012 не зачіпається).

## Наслідки

Стрибок якості вигляду без ризику механіки: детермінізм, сейви і тести ядра від ассетів не залежать. Ціна: ручний цикл передачі бінарників і ризики генерації (кирилиця, непрозоре тло — зачистка на етапі інтеграції). Змінити — новим ADR. Відхилені альтернативи: (а) більші кодові матриці — стабільно, але стиль обмежений, власник відхилив; (б) гібрид «матриця + ассет» як обов’язкове правило — зайва складність, гібрид лишається винятком; (в) покупні спрайт-паки — стилістична й ліцензійна невизначеність проти палітри Розриву.
