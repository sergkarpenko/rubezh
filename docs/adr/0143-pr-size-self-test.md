# 0143. Самоперевірка `scripts/pr-size.sh` — режим `--self-test` і перший крок джоби `pr-size`

- Статус: accepted (мерж PR власником = «схвалюю» — конвенція ADR-0052)
- Дата: 2026-11-25
- Доповнює: ADR-0077 (`scripts/pr-size.sh` і workflow `pr-size`), ADR-0112 (код 2 на помилку git), ADR-0061 (мітка `size-deviation`), ADR-0018 (зміна workflow — з ADR), ADR-0094 (клас PR)
- Автор: Claude Code (рішення власника 25.11.2026 на фініші Т.175 кнопкою — «pr-size --self-test (113) (Рекомендовано)»; кандидат процесу 113)

## Контекст

- `scripts/pr-size.sh` вирішує обов'язковий чек `pr-size` (ліміт 500 рядків коду, ADR-0036), але, на відміну від `scripts/pr-class.sh` і `scripts/iter-tag.sh`, не мав самоперевірки: правку скрипта (маска «поза підрахунком», межа ліміту, диф від merge-base, код 2 з ADR-0112) перевіряв лише ручний прогін автора і аудит.
- Звірка на `main` = `20ec950`: режиму `--self-test` у `pr-size.sh` немає; workflow `pr-size` уже викликає самоперевірку `pr-class.sh` кроком `sh scripts/pr-class.sh --self-test`; у `common.md` («Скрипти CI і workflow») — правило «логіку workflow, що вирішує про мерж, писати в скрипті з режимом `--self-test`».

## Рішення

1. `scripts/pr-size.sh --self-test` (єдиний аргумент) — 24 випадки в тимчасовому репозиторії (`mktemp -d`, прибирається `trap`): для кожного — гілка `work` від `main`, запуск самого скрипта, звірка коду виходу (0 / 1 / 2) і рядка, який має бути (і якого не має бути) у виводі. Групи: поза підрахунком (порожній диф, `docs/` з не-`.md` файлом, `*.md` поза `docs/`, ассет, бінарний, lockfile, `assets/` не в корені, тека, схожа на `docs`), підрахунок (додані + видалені, шлях не ASCII, запуск із підтеки, диф від merge-base), ліміт (500 і 501 типово, `PR_SIZE_LIMIT`, `PR_SIZE_DEVIATION` = `true` / `false`, `::error::` у CI), помилки з кодом 2 (немає ревізії base чи head, немає спільного предка, збій `git diff` — видалений об'єкт blob гілки, не ті аргументи).
2. Самоперевірка скидає `GITHUB_ACTIONS`, `PR_SIZE_DEVIATION`, `PR_SIZE_LIMIT` з оточення: у джобі `GITHUB_ACTIONS=true` змінив би вивід випадків. Підсумок — `[OK] Самоперевірка pr-size.sh: N випадків`, код 0; інакше — перелік невдалих випадків з їхнім виводом і код 1.
3. Workflow `pr-size` — новий перший крок «Самоперевірка скрипта розміру PR» (`sh scripts/pr-size.sh --self-test`) перед «Розмір PR»: червона самоперевірка валить чек незалежно від розміру PR, а перевищення ліміту не ховає її результату. Логіка підрахунку, коди виходу і вивід звичайного режиму без змін; рядок «Використання» називає новий режим.
4. Заодно (кандидат процесу 162, правка того ж класу з цим ADR): коментар кроку `npx tsc --noEmit -p tsconfig.scripts.json` у `.github/workflows/ci.yml` називає охоплення ADR-0140 і ADR-0141 (кореневі `playwright*.config.ts`, `e2e/smoke.e2e.ts`); сам крок без змін.

## Наслідки

- Перевірка самоперевірки — навмисні поломки копії скрипта: прибрати пропуск `docs/`, `*.md` (кожен окремо), ассетів, lockfile; маска `assets/` без `^`; диф `..` замість `...`; `-lt` замість `-le`; ігнорувати `PR_SIZE_DEVIATION`; рахувати лише додані; `core.quotepath=on`; прибрати перевірку спільного предка; не розрізняти `GITHUB_ACTIONS`; ковтати помилку `git diff`; `[OK]` поруч з `::error::` — кожну ловить щонайменше один випадок.
- Час кроку — ≈ 1 с локально (24 маленькі коміти). Скрипт — під `sh` (на раннері `dash`), самоперевірка теж; перевірено `sh` і `dash`.
- Правка `pr-size.sh` надалі — разом із випадком самоперевірки (порада — `docs/agents/common.md`, «Скрипти CI і workflow»). Клас PR такої правки — `approve` (скрипт CI, `scripts/pr-class.sh`), як і раніше.
- Відхилено: окремий файл самоперевірки поруч (як `scripts/mistral-audit-selftest.mjs`, ADR-0099) — самоперевірка ≈ 120 рядків, як у `pr-class.sh` і `iter-tag.sh`, що тримають її в тому самому файлі; крок самоперевірки після «Розмір PR» — перевищення ліміту зупинило б джобу до самоперевірки; самоперевірка в `npm test` (тест vitest над скриптом) — скрипт `sh` перевіряється там, де він працює, і не залежить від Node.
