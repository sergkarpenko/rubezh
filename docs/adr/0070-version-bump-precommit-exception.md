# 0070. Version-bump у pre-commit hook — виняток із правила 1b (ADR-0012)

- Статус: accepted (запит власника у сесії закриття Фази 12 «запланий це виправити, або виправ відразу» — обрано «виправ відразу», 2026-10-18; конвенція 2026-10-15 — нові ADR подаються одразу accepted)
- Дата: 2026-10-18
- Доповнює: ADR-0012 (залежності — лише з ADR + авторизація власника), ADR-0014 (Husky pre-commit), ADR-0030 (зміни процесу — через ADR), ADR-0054 (реліз-крок «Реліз vN.N.N»)
- Автор: Vibe Code (технічна задача Т.4 — позафазна, рішення власника)

## Контекст

Реліз-крок ADR-0054 піднімає `version` у package.json. Правило 1b хука `scripts/pre-commit.sh` (ADR-0012/0014) вимагає файл у `docs/adr/` у тому ж коміті для будь-якого staged package.json, тому реліз-бамп доводилось комітити з `--no-verify` і ручним повтором перевірок хука (прецеденти v0.2.0/v0.3.0/v0.4.0). У П12.8 `npm version 0.4.0 --no-verify` виявив, що npm не прокидає цей прапорець у `git commit` під Husky — хук усе одно виконався і впав на правилі 1b; бамп зроблено вручну + `git commit --no-verify`.

Це ручний обхід механізму всупереч уроку П7.5 («гейт має жити в механізмі репозиторія, а не в увазі агента»): захист правила 1b насправді цілує зміни залежностей (ADR-0012), а version-bump не є зміною залежностей — це вже констатовано в прецедентах релізів («version-bump ≠ зміна залежностей, методику ADR-0054 затверджено»).

## Рішення

Правило 1b хука розрізняє version-bump і зміну залежностей:

- якщо контентні рядки дифа staged package.json — лише поле `"version"`, коміт проходить без ADR (виняток ADR-0070: реліз-крок ADR-0054);
- будь-який інший рядок дифа package.json (залежності, скрипти, конфіг) — як і раніше, лише з ADR у тому ж коміті (ADR-0012).

`npm version N.N.N` після цього проходить хук повністю (тести, exact-байти) без `--no-verify` і без ручного повтору перевірок.

## Наслідки

- Реліз-крок ADR-0054 стає суто механічним: бамп комітиться хуком; `--no-verify` для бампу більше не потрібен. Методика релізу не міняється — тег і GitHub Release, як і раніше, лише після валідації власника (ADR-0023/0052).
- Захист ADR-0012 не слабшає: зміна залежностей/скриптів у package.json без ADR — як і раніше, блокується хуком.
- Обмеження винятку: розпізнається виключно поле `"version"`; сумісний коміт «бамп + залежності» без ADR упаде (свідомо).
- Зміна правила — лише через новий ADR із полем Supersedes.

## Альтернативи

- Статус-кво (`--no-verify` + ручні перевірки хука) — відкинуто: ручний обхід механізму, увага агента скінчена (урок П7.5).
- Документувати ручну процедуру бампу в workflow.md — відкинуто: інструкція замість механізму, дрейфує.
- CI-гейт замість pre-commit — відкинуто: перевірка мала б бути або завжди зеленою до реліз-PR, або блокувати docs-PR (та сама аргументація, що в ADR-0055 для гейту на merge).
