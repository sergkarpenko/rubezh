# 0062. Автосмок прев'ю і кореня після деплою

- Статус: accepted (рішення власника в сесії П11.5, 2026-10-17; мерж PR власником = «схвалює» — конвенція ADR-0023/0052)
- Дата: 2026-10-17
- Доповнює: ADR-0060 (прев'ю гілок на Pages до мержу), ADR-0018 (workflow-файли — лише з ADR у точці коміту), ADR-0012 (без нових залежностей)
- Автор: Vibe Work (рішення — власник, ретроспектива П11.5)

## Контекст

Перший живий запуск прев'ю (П11.5) упав на кроці складання артефакта — і це виявила лише людина в журналі рана. Валідація власником (критерій 1) — відкриття URL браузером — плюс запит власника у сесії: тримати main максимально стабільним, працюючи через прев'ю, і за можливості додати автосмок. Після `deploy-pages` Pages-сайт вважається живим, але CDN-край може віддавати затримку; смок має бути терпимим до кількасекундного розповзання.

## Рішення

У `preview-branch.yml` (джоб `deploy`, після `deploy-pages`) — два смок-кроки без нових залежностей (ADR-0012, curl з образу раннера):

- **сторінка гілки**: `GET` URL прев'ю, очікується HTTP 200; до 5 спроб з паузою 10с (розповзання CDN), невдача всіх → червоний ран з українським повідомленням `::error::`;
- **корінь main**: `GET` основного URL, очікується 200 — ран впевнений, що деплой прев'ю не зламав основний сайт (критерій 2 ADR-0060 стає автоматизованим).

Смок — наявнісна перевірка (HTTP 200), не DOM-тест: UI-логіку далі тримають юніт/DOM-тести (ADR-0013), а візуальну коректність — власник у браузері за URL з рана.

## Наслідки

- Червоний ран прев'ю = сторінка не віддається або зламаний корінь — власник бачить це раном, а не білим екраном браузера; URL з logs/summary лишається джерелом для ручної перевірки.
- Смок не ловить вмістових дефектів (не той білд, зламаний JS) — прийнято: прев'ю — кадрова перевірка власником; розширення до DOM-смоку (headless-браузер) — нова залежність, кандидат на окреме рішення власника.
- Зміна методики — лише через новий ADR із полем Supersedes.

## Альтернативи

- DOM-смок у headless-браузері (Playwright) — відкинуто: нова залежність (ADR-0012) заради перевірки, яку власник усе одно робить очима.
- Смок у джобі build (до деплою, по артефакту) — відкинуто: перевіряє файл, а не те, що реально віддає Pages після деплою.
- Без смоку, лише ручна перевірка — відкинуто рішенням власника в сесії П11.5.
