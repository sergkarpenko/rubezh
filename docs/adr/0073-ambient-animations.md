# 0073. Обмежені ambient-анімації

- Статус: accepted
- Дата: 2026-10-19
- Supersedes: частково ADR-0029
- Доповнює: ADR-0031, ADR-0064, ADR-0065, ADR-0059, ADR-0003
- Автор: Vibe Work (П14.1, сесія планування Фази 14)

## Контекст

Правило idle → 0 перерисовок (ADR-0029) економить батарею iPad: без подій шар відображення не малює. 2026-10-19 власник дозволив обмежені «живі» ambient-ефекти, щоб гра виглядала жвавою, з умовами, що зберігають призначення правила (економія батареї, детермінізм). Це уточнення ADR-0029, а не скасування.

## Рішення

1. Ambient-ефекти — лише відображення: стан ядра, лог, rng не змінюються; ambient не входить у події логу і в тести логіки.
2. Гейт видимості: малювання лише коли документ видимий (rAF не тікає у фоні; visibilitychange) і минув wall-clock інтервал від останньої події; у фоні/паузі — 0 перерисовок (правило ADR-0029 зберігається як базовий режим).
3. Тумблер: «Налаштування» → «Анімація»; ключ `rubezh.settings.ambient` у локальному сховищі; дефолт — увімкнено.
4. Бюджет: частота ambient-шару ≤ 10 fps; одночасних активних ефектів — не більше сталої шару відображення.
5. Фіксований перелік ефектів затверджується у плані фази (П14.8); нові постійні цикли анімації — лише через новий ADR.

## Наслідки

«Жива» картинка без витрати батареї у фоні і без ризику детермінізму. Тестовий критерій П14.8: лог партії байт-у-байт однаковий з увімкненим і вимкненим ambient; у jsdom (без rAF) — 0 перерисовок за typeof-гейтом (прецедент П6.16). Змінити перелік або бюджет — новим ADR.
