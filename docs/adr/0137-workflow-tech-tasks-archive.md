# 0137. Записи «Технічних задач» — в архів на ревізії: `docs/workflow.md` тримає записи від попередньої ревізії

- Статус: accepted (мерж PR власником = «схвалюю» — конвенція ADR-0023/0030/0052)
- Дата: 2026-11-24
- Доповнює: ADR-0074 (структура `docs/workflow.md`: активна фаза + архів), ADR-0094 (клас PR), ADR-0096 (довідники агентів)
- Автор: Claude Code (Т.169, рішення власника кнопкою «А. Т.5–Т.157 + правило»)

## Контекст

ADR-0074 (2026-10-19) переніс завершені фази в `docs/workflow-archive/` і поставив контрольний поріг ≈ 200 КБ, після якого `docs/workflow.md` знову реструктуризують новим процесним ADR. Механіка ADR-0074 стосується лише фаз: блок фази переносить ретроспективний PR цієї фази. Позафазних записів «Технічних задач» вона не стосується. Від Т.5 (2026-11-10) кроки йдуть поза фазами, і кожен лишає запис у розділі «Технічні задачі (позафазні)». Ретро-PR для них немає, тож розділ лише росте.

На `main` `1df6e66` (після Т.168) `docs/workflow.md` займає 800 847 байтів:

| Частина | Байтів |
| --- | --- |
| Преамбула, процес, теги, «Рішення» (до розділу «Уроки» і після нього, вище «Поточного статусу») | ≈ 23 000 |
| «Уроки» | ≈ 103 500 |
| «Технічні задачі»: записи Т.5–Т.157 | 601 266 |
| «Технічні задачі»: записи Т.158–Т.168 | 46 841 |
| Backlog, візуальні порівняння, індекс архіву | ≈ 26 000 |

`AGENTS.md` і довідники радять не читати файл цілком, а брати заголовки й діапазони рядків. Проте рядки записів займають по кілька кілобайтів, тож `grep` по файлу повертає великі шматки. Крім того, аудитор `vibe-audit` читає файл у копії репозиторію сам.

## Рішення

1. Записи Т.5–Т.157 розділу «Технічні задачі (позафазні)» перенесено в `docs/workflow-archive/tehnichni-zadachi-t5-t157.md` дослівно, байт у байт (механіка ADR-0074 п. 2). Файл має шапку з посиланням на ADR. У `docs/workflow.md` під заголовком розділу стоїть рядок-покажчик, а в індексі архіву — рядок про новий файл. Записи Т.1–Т.4 лишаються в `docs/workflow-archive/tehnichni-zadachi.md`. Від Т.158 записи лишаються в `docs/workflow.md`.
2. Подальша механіка. PR кожної ревізії документів сесій (крок ≈ раз на 10 кроків, його обирає власник) переносить в архів дослівно записи «Технічних задач» від першого запису в розділі до запису перед попередньою ревізією включно. Архів-файл — новий, `docs/workflow-archive/tehnichni-zadachi-tA-tB.md`, де A і B — перший і останній перенесені кроки. Рядок-покажчик під заголовком розділу оновлюється, у індекс архіву додається рядок. Наприклад, ревізія Т.178 перенесе Т.158–Т.167 (попередня ревізія — Т.168). Чинні архів-файли не редагуються (ADR-0074).
3. Перенесення звіряють скриптом. З нового `docs/workflow.md` і вирізаного діапазону збирають файл бази: діапазон стає на місце рядка-покажчика, рядок-покажчик повертають до тексту бази (на першому переносі, Т.169, його в базі не було), а додані рядки PR (рядок індексу, запис кроку, інші нові рядки) прибирають. Цей файл порівнюють з `git show origin/main:docs/workflow.md` байт у байт. Окремо тіло архів-файла після шапки порівнюють з вирізаним діапазоном. Команду і результат пишуть в описі PR. Скрипт — разовий скрипт сесії поза репозиторієм; спосіб описано в довіднику (`docs/agents/common.md`, пункт «Ревізія»).
4. Розділ «Уроки» не переноситься: це правила активного процесу (ADR-0074 п. 1). Новий запис кроку, як і досі, стає перед рядком «- **Backlog (відкладено…**».
5. Запис кроку, якого немає в `docs/workflow.md`, шукають в архіві: `git grep -n '^- \[x\] \*\*[TТ]\.N ' docs/workflow-archive/` (запис Т.39 починається латинською `T`; окремого запису Т.77 немає — крок описано в `faza-15.md`, кандидат 89). Посилання на кшталт «запис Т.N у `docs/workflow.md`» у чинних ADR і звітах не правляться: ADR не оновлюються, а звіти — історичні документи.
6. Механіка п. 2 замінює для `docs/workflow.md` контрольний поріг ADR-0074 п. 6 (≈ 200 КБ, після якого потрібен новий ADR). Без записів кроків файл займає ≈ 153 КБ. Після ревізії в ньому лишаються записи ≈ 10 кроків (Т.158–Т.168 — ≈ 47 КБ), а перед наступною — ≈ 20. Тож розмір коливатиметься між ≈ 200 і ≈ 245 КБ. Новий процесний ADR потрібен, якщо файл перевищить ≈ 300 КБ або значно виростуть «Уроки».

## Наслідки

- `docs/workflow.md`: 800 847 → 203 197 байтів (−75 %; з записом Т.169 і абзацом правила). Найбільша частина тепер — «Уроки».
- PR ревізії отримує механічну роботу: перенесення, покажчик, індекс, звірка скриптом. Розмір PR це не збільшує, бо `docs/` поза підрахунком `pr-size` (ADR-0077). Клас PR ревізії не змінюється: перенесення лежить нижче «Поточного статусу проєкту», тож за `scripts/pr-class.sh` воно — «не гра».
- `scripts/pr-class.sh`, `scripts/audit-vibe-cli.mjs` і workflow без змін. Промпт `vibe-audit` і далі називає `docs/workflow.md` для запису кроку з PR: такий запис — від попередньої ревізії, тобто в основному файлі. Записи старших кроків аудитор знаходить через `grep` у копії репозиторію.

## Альтернативи

- «Б. Т.5–Т.157, одноразово» (те саме перенесення без правила п. 2). Відхилено власником кнопкою. Аргумент сесії: без механіки файл за ≈ 150 кроків знову виріс би до 800 КБ, і знадобився б окремий крок із ще одним ADR.
- «В. Усі Т.5–Т.168 + правило». Відхилено власником кнопкою. Аргумент сесії: записи останніх кроків найчастіше потрібні наступним крокам і аудиторові, тому їм краще лишатися в основному файлі.
- Перенести і «Уроки». Не пропонувалося: ADR-0074 п. 1 тримає їх в основному файлі як правила для всіх агентів, а `AGENTS.md` (розділ «Уроки») — як єдине місце уроків.
- Дописувати записи в чинний `tehnichni-zadachi.md`. Не пропонувалося: ADR-0074 забороняє редагувати архів-файли. Окремий файл на діапазон кроків легше звірити `diff`.
