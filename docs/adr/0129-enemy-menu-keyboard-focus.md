# 0129. Меню на ворогові — фокус після дії з клавіатури на картку стрільця

- Статус: accepted (мерж PR власником = «схвалюю» — конвенція ADR-0052)
- Дата: 2026-11-24
- Доповнює: ADR-0120 (меню на ворогові), ADR-0119 (смуга загону), рішення Т.73 (фокус вікон)
- Автор: Claude Code (Т.152; рішення власника кнопкою — у записі Т.152 у `docs/workflow.md`)

## Контекст

- Кнопки меню на ворогові (`#benemy`, ADR-0120) — звичайні `button`: до них можна дійти клавішею Tab і натиснути Enter або пробіл. Дія закриває меню (постріл — одразу; «Граната» зводить гранату), картка ховається разом із кнопкою у фокусі, і фокус падає на `body`: наступний Tab починає з верху сторінки (кандидат 132, залишок кандидата 128).
- Правило вікон Т.73 (фокус повертається туди, звідки відкрили) тут не підходить дослівно: меню відкриває тап по демону на канві, яка фокусу не має.

## Рішення

1. Дія кнопкою меню з клавіатури — фокус на картку бійця, що стріляв (вибраного), у смузі загону `#bsquad` (рішення власника «А. Картка стрільця»): на ній видно AP після дії, Tab далі — інші бійці. Меню закривається, як і досі.
2. «З клавіатури» — подія `click` без кліків миші (`detail === 0`, так браузер шле клік від Enter і пробілу) на кнопці, що мала фокус. Клік мишею (`detail ≥ 1`) і тап фокус не рухають — у Chrome клік мишею теж фокусує кнопку, тому самого фокуса замало.
3. Те саме для «Граната»: після зведення фокус на картці стрільця. Enter на картці — вибір того самого бійця, що, як і досі, знімає зведений режим (П11.6, `selectOwn`).
4. Код — обробник кліку `#benemy` у `src/main.ts`; `src/ui/enemy-menu.ts`, `src/ui/input.ts`, вигляд і тексти без змін. Перемальовка смуги загону вже тримає фокус на тій самій картці (аудит PR #443).

## Відхилені варіанти (рішення власника)

- «Б. Меню лишається» — після пострілу меню не закривається, фокус на тій самій кнопці: змінює поведінку ADR-0120 і для миші.
- «В. Поле бою» — фокус на канву поля (`tabindex="-1"`): канва без рамки фокуса, а наступний Tab іде до кнопок під полем, не до бійців.
