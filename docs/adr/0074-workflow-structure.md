# 0074. Структура workflow.md: активна фаза + архів завершених фаз

Статус: accepted

Дата: 2026-10-19

Доповнює: ADR-0023, ADR-0028, ADR-0043

Автор: Vibe Work (рішення власника, Work-сесія 2026-10-19)

## Контекст

`docs/workflow.md` виріс до 464 КБ (726 рядків, ~294 тис. символів ≈ 100–160 тис. токенів) і читається ЦІЛИМ кожною сесією Vibe Code (крок 1 «Циклу зміни ядра») — це помітно сповільнює роботу агентів (фідбек власника 2026-10-19). Склад: «Поточний статус» 296,5 КБ (64%; завершені фази 1–13, техзадачі, лінія пR), «Уроки» 74,6 КБ (16%), «Теги ітерацій» 70 КБ (15%; рядки фаз 0–13 — історичні), процес < 5%; розділ «Архів фаз» був фактично мертвим (0,6 КБ, лише Фаза 1).

## Рішення

1. `docs/workflow.md` лишається «офісом» активного процесу: преамбула + процес (принципи, цикл ядра) + конвенції тегів + рядки тегів АКТИВНОЇ фази + ВСІ уроки (дослівно, не розрізаємо — найцінніший матеріал для агентів) + «Рішення» + «Поточний статус» (статус фаз) + АКТИВНА фаза + індекс архіву. Цільовий розмір ~117 КБ (−75%).
2. Завершені фази 1–13, лінія пR, позафазні технічні задачі та історичні рядки тегів (фази 0–13) переносяться в `docs/workflow-archive/` (faza-01.md … faza-13.md, linia-pr.md, tehnichni-zadachi.md, iteration-tags.md) ДОСЛІВНО, байт-у-байт, без редагування змісту.
3. Механіка подальших фаз: ретроспективний PR завершеної фази переносить її блок і рядки тегів цієї фази з workflow.md в архів-файл фази (faza-NN.md), лишаючи рядок в індексі архіву; уроки завершеної фази цим самим PR можуть переноситись в архів-файл фази.
4. ADR-0023 не порушується: вимоги активної фази (блок «Рішення власника», EARS-критерії) лишаються у workflow.md.
5. Крок 1 «Циклу зміни ядра»: агент читає workflow.md (активна фаза, «Наступні кроки», уроки); архів `docs/workflow-archive/` — лише за потреби (посилання в індексі).
6. Контрольний поріг ~200 КБ: при наборі workflow.md ~200 КБ — наступна реструктуризація (новим процесним ADR).

## Наслідки

- Контекст кожної кодової сесії: ~117 КБ замість 464 КБ (−75%).
- Історія фаз повністю збережена в репо; архівні файли не редагуються (тільки створюються/поповнюються ретро-PR фаз).
- Ретро-PR фази отримує додаткову механічну роботу (перенесення блоку + рядків тегів в архів, оновлення індексу) — ціна швидкості щоденних сесій.
- `docs/workflow-archive/*.md` додано в ALLOWED-таблицю AGENTS.md (Створювати); реєстр ADR — ADR-0074; AGENTS.md 2.0 → 2.1.
