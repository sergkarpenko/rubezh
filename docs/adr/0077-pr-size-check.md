# 0077. Автоматична перевірка розміру PR — скрипт + workflow `pr-size`

- Статус: accepted (мерж PR власником = «схвалюю» — конвенція ADR-0023/0030/0052)
- Дата: 2026-11-10
- Частково Supersedes: ADR-0040 (форма реалізації: без міток розміру і коментарів у PR; рішення «перевіряти автоматично» лишається)
- Доповнює: ADR-0036 (ліміт 500 рядків), ADR-0061 (плановані відхилення), ADR-0069 (ліміти лише для коду), ADR-0018 (workflow-файли — з ADR)
- Автор: Claude Code (запит власника 2026-11-10, задача Т.5c; спостереження — аналіз процесу 2026-11-10)

## Контекст

ADR-0040 (accepted, 2026-10-15) вирішив перевіряти розмір PR автоматично і навів текст workflow `pr-size-check.yml`, але файл у репозиторій так і не потрапив: ліміт ADR-0036 весь цей час тримався на увазі агента і прогнозі дифа на плануванні (ADR-0061). Фактична історія (підрахунок цим скриптом по всіх 244 змержених PR до `a9ff074`): 22 PR перевищили 500 рядків коду, з них 18 — уже після прийняття ліміту (PR #62); частина — плановані серії рефакторингу пR.2/пR.3 і схвалені відхилення (П11.2, PR #141 — 701 рядок, скрипт дає те саме число), решта ніде не зафіксована як відхилення.

Текст workflow з ADR-0040 реалізовувати дослівно вже не можна — після нього ухвалено:

- ADR-0061: відхилення можливе, якщо воно заплановане;
- ADR-0069: бінарні ассети в ліміт не входять;
- виняток ADR-0036 для документації (майже половина PR проєкту — docs).

Крім того, workflow з ADR-0040 потребував прав `pull-requests: write` (мітки, коментарі) і рахував диф `origin/main..pr-branch`, а не від merge-base.

## Рішення

1. **Логіка — у `scripts/pr-size.sh <base> <head>`**, workflow лише викликає скрипт. Той самий скрипт агент запускає локально до пушу (`./scripts/pr-size.sh origin/main HEAD`) — це «прогноз дифа» ADR-0061 фактом, а не оцінкою.
2. **Що рахуємо:** додані + видалені рядки дифа `base...head` (від merge-base). Тести входять у підрахунок (ADR-0061: «код + тести за критеріями кроку»).
3. **Що не рахуємо:** `docs/**` і `*.md` (ADR-0036); `assets/**` і будь-які бінарні файли (ADR-0069); `package-lock.json` (генерований).
4. **Ліміт — 500** (ADR-0036; базовий ліміт цим ADR не змінюється).
5. **Плановане відхилення (ADR-0061) — мітка `size-deviation` на PR.** З міткою перевищення друкується, але чек зелений. Мітку ставить той, хто може послатися на запис «відхилення від ADR-0036 схвалено планом» у кроці плану; опис PR містить це посилання; мерж власником підтверджує відхилення (ADR-0052). Незаплановане перевищення — як і раніше, питання власнику ДО мержу (ADR-0061 п. 4).
6. **Workflow `.github/workflows/pr-size.yml`**, джоба `pr-size`: події `pull_request` у `main` (`opened`, `synchronize`, `reopened`, `edited` — перенацілення складеного PR, `labeled`/`unlabeled`); права лише `contents: read`; без сторонніх actions, крім `actions/checkout`. PR від Dependabot пропускаються (ADR-0036).
7. **Статус required-чека** — дія власника в Settings → Branches (чек `pr-size`), після першого зеленого живого рану (прецедент ADR-0034: гейт діє лише як required check; урок П11.5: механіку workflow перевіряє живий ран). До цього чек інформаційний.
8. Мітку `size-deviation` у репозиторії створює власник (разова дія) або перший PR, що її потребує.

## Наслідки

- Ліміт ADR-0036 переходить з уваги агента в механізм репозиторія (урок П7.5).
- Серії складених PR: чек запускається на PR серії після перенацілення на `main` (як і `test`, урок П11.4).
- Мітки розміру (`size:xs…xl`) і коментар-попередження з ADR-0040 не реалізуються: вони вимагали прав запису і дублювали вивід чека.
- Скрипт — POSIX sh + git + awk, без залежностей (ADR-0012 не зачіпається); поза скоупом ESLint/Prettier, як і решта `scripts/`.
- Зміна ліміту, складу винятків або механізму відхилень — лише через новий ADR.

## Альтернативи

- Реалізувати workflow ADR-0040 дослівно — відкинуто: суперечить ADR-0061/0069 і блокував би docs-PR.
- Маркер відхилення в описі PR замість мітки — відкинуто: текст опису крихкий до правок, мітка однозначна і видима у списку PR.
- Готовий action з Marketplace — відкинуто: стороння залежність у CI заради 30 рядків shell.
