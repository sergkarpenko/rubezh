# 0095. Зовнішній аудит PR моделлю Mistral — джоба CI з коментарем у PR

- Статус: accepted (мерж PR власником = «схвалюю» — конвенція ADR-0018/0052)
- Дата: 2026-11-15
- Доповнює: ADR-0094 (аудит PR як умова мержу класу `auto`); ADR-0018 (зміна workflow-файлу — з ADR); ADR-0052 (апрув власника)
- Автор: Claude Code (рішення власника 2026-11-14: кандидат 25 «Mistral — аудитор PR»; відповіді власника кнопками в сесії Т.37; задача Т.37)

## Контекст

З Т.34 кожен PR кроку до мержу читає аудитор — модель без контексту сесії (ADR-0094). Досі аудитора запускала та сама сесія, що писала PR: вона обирає, що йому дати, і вона ж переказує результат. Аудит не лишає сліду в репозиторії, окрім переказу в описі PR.

Mistral оплачений і простоює: розробка зараз іде в сесіях Claude. Застосунок MistralAI встановлено на репозиторій, але він лише дає продуктам Mistral (Vibe, AI Studio) доступ до коду; на подію PR він не реагує, і джоба GitHub Actions викликати модель через нього не може — потрібен ключ API.

Рішення власника (сесія Т.37, кнопками):

- модель — Mistral Large 4 (`mistral-large-latest`); Devstral і Medium 3.5 на дату рішення виведені з обігу;
- Mistral іде поруч з аудитом Opus-субагентом два-три кроки, а не замінює його;
- збій API або зіпсована відповідь — зелений чек і коментар про збій.

## Рішення

1. **Workflow `mistral-audit`** — на подію `pull_request` у `main` (`opened`, `synchronize`, `reopened`). PR з форку і PR Dependabot пропускаються: секрету вони не отримують.
2. **Логіка — у `scripts/mistral-audit.mjs`** (Node без залежностей), у yml лише виклики. `--self-test` проганяє збирання дифа на тимчасовому репозиторії і повний прохід з підставним API; самоперевірка — перший крок джоби.
3. **Що бачить аудитор:** `AGENTS.md` з бази PR (PR не може послабити правила, за якими його читають; зміну правил видно в дифі), назву й опис PR, диф `base...head` по файлах. Поза показом — `package-lock.json` і бінарні ассети; межі — 60 000 знаків на файл і 240 000 на диф; усе не показане перелічено в коментарі. Команд аудитор не запускає, решти репозиторію не бачить.
4. **Модель** — `mistral-large-latest`; іншу задає змінна репозиторію `MISTRAL_MODEL` (без зміни workflow). Один виклик API на пуш; повтор до трьох спроб на 429, 5xx і помилку мережі.
5. **Результат — один коментар у PR** з позначкою `<!-- mistral-audit -->`: до десяти знахідок (важливість, «перевірене» чи «припущення», файл, рядок, доказ), лічильник токенів, перелік не показаного. На наступний пуш той самий коментар оновлюється. Текст моделі в коментарі — без HTML, згадок користувачів і переносів рядка.
6. **Збій не блокує мерж.** Немає секрету, API недоступний, відповідь не розібрано, диф не зібрано — коментар «Аудиту не було: причина» і зелений чек. Червоний чек — лише червона самоперевірка. Чек `mistral-audit` не обов'язковий.
7. **Роль на час порівняння (Т.37–Т.39).** Аудит у розумінні ADR-0094 і далі проводить сесія (Opus-субагент). Знахідки Mistral сесія читає через REST і розбирає так само: підтверджені — виправити в тому ж PR, відхилені — перелічити з причиною в описі PR. У журналі кроків — знайдено / підтверджено для обох аудиторів. Чи замінює Mistral аудит субагентом — вирішує власник після порівняння, новим ADR; тоді «Аудиту не було» означатиме «аудиту немає» і PR класу `auto` чекатиме «схвалюю» (сумнів = «схвалюю»).
8. **Секрет `MISTRAL_API_KEY`** — у секретах Actions репозиторію. Ключ не потрапляє ні в журнал, ні в коментар, ні в тексти помилок (самоперевірка це перевіряє).

## Наслідки

- Кожен PR має слід незалежного читання в самому PR — видно власникові, сесії й агентам Mistral.
- Диф, опис PR і `AGENTS.md` надсилаються в API Mistral.
- Аудитор слабший за субагента в одному: він не може запустити команду і перевірити твердження — бачить лише диф. Тому «перевірене» в його знахідках означає «видно з рядка дифа».
- Диф — недовірені дані для моделі: текст у PR може намагатися керувати аудитором. Захист: позначки меж даних у запиті, аудитор без інструментів, вивід знешкоджено, коментар — дані для сесії, а не вказівки; рішень про мерж коментар не ухвалює.
- Секрет доступний workflow на гілці репозиторію: хто має право пушу, може його прочитати зміненим workflow. Право пушу мають власник і його агенти; PR з форку секрету не бачить.
- Ціна — один виклик на пуш у PR, до ≈ 100 тис. токенів вводу.

## Перевірка

- `node scripts/mistral-audit.mjs --self-test` — зелений;
- на PR цього кроку джоба лишає коментар: знахідки або «Аудиту не було» з причиною.
