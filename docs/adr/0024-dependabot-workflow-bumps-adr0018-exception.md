# 0024. Dependabot-бампи GitHub Actions — виняток із ADR-0018

- Статус: accepted
- Дата: 2026-10-13

**Контекст.** ADR-0018 вимагає ADR у тому ж коміті для будь-яких змін `.github/workflows/*.yml`. ADR-0020 налаштував Dependabot для екосистеми `github-actions`: бот створює PR з бампами версій actions у workflow, і такі PR не містять ADR — формальний конфлікт з ADR-0018. У першому ж потоці (2026-10-13) бот відкрив п'ять PR-ів з бампами actions у `preview.yml` (#2–#6); власник ухвалив: мержити їх лише після окремого ADR, що знімає цей конфлікт. Guard-правило 1c pre-commit бот-мержі не блокує (бот мержиться через GitHub, а не через hook) — тож рішення стосується політики рев'ю, а не механіки комітів.

**Рішення.** Ми трактуємо PR Dependabot, що містять лише бампи версій наявних actions (рядки `uses:` у `.github/workflows/*.yml`), як канал ADR-0020: мерж власником = авторизація, окремий ADR на кожен бамп не потрібен. ADR-0018 лишається чинним для всіх ручних змін workflow-файлів (люди й агенти) та для бот-PR з будь-якими іншими змінами workflow (нові кроки, нові екшени, зміна тригерів чи permissions) — такі зміни мержаться лише з ADR у тому ж коміті, як звичайно.

**Наслідки.** Рутинні бампи actions більше не потребують ADR-сесій; контроль лишається через рев'ю diff бот-PR (Dependabot прикладає changelog) і CI на main після мержу — деплой превью є інтеграційним тестом самих екшенів. Ризик: мажорні бампи actions можуть міняти поведінку (раннер node, вихідні артефакти) — їх проглядати уважніше; червоний CI на main = стоп до відкату. Зміна рішення — новий ADR із полем Supersedes.
