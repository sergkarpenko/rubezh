# 0063. Headless-DOM-смок прев'ю (Playwright)

- Статус: accepted (рішення власника в сесії П11.5, 2026-10-17: «Headless-DOM-смок — через додатковий ADR з аналізом; залежність буде проапрувована»; мерж PR власником = «схвалює» — конвенція ADR-0023/0052)
- Дата: 2026-10-17
- Доповнює: ADR-0062 (автосмок прев'ю — HTTP 200; його п.«Альтернативи» передбачив це окреме рішення), ADR-0060 (прев'ю гілок), ADR-0012 (залежність — ADR + явна авторизація власника; цей ADR = та авторизація)
- Автор: Vibe Work (аналіз і вибір — сесія П11.5; рішення — власник)

## Контекст

Смок ADR-0062 — наявнісний: HTTP 200 не гарантує, що сторінка жива як документ (JS бандл міг не завантажитись, канвас не створився, render-цикл упав). Візуальну коректність прев'ю все одно перевіряє власник очима, але «білий екран» варто ловити раном — до відкриття браузера людиною. Власник ухвалив розширення до headless-DOM-смоку за окремим ADR з аналізом рішень; додаткова залежність — за процесом ADR-0012, авторизація власником дана в сесії П11.5 умовно на результат аналізу.

## Аналіз альтернатив

| Варіант                            | Плюси                                            | Мінуси                                                                  |
| ---------------------------------- | ------------------------------------------------ | ----------------------------------------------------------------------- |
| **@playwright/test (вибрано)**     | ранер+твердження+трейси «з коробки», auto-wait, один devDep, `npx playwright install chromium` (~1 хв у CI, без системних deps на ubuntu), страндарти галузі | браузер у CI (~50с встановлення на ран; без кешу) |
| Puppeteer                          | схожа вага, chromium-only                        | без ранера/тверджень — власний цикл і перевірки; менш активно розвивається для тестів |
| puppeteer-core + Chrome з образу раннера | без завантаження браузера npm-пакетом      | залежність від шляху/версії Chrome в образі GitHub (крихкість між оновленнями образів); все одно npm-пакет |
| Cypress                            | багатий UI для дебагу                            | найважчий бінарно, орієнтований на dev-server, не на статичний задеплоєний URL; надмірно для смоку |
| jsdom-перевірки (без нової залежності) | нульове навантаження                         | не браузер: Canvas 2D/WebAudio відсутні у jsdom — хибні падіння/проходження; не ловить справжні рантайм-помилки рендера |
| сирий Chrome DevTools Protocol     | без npm-залежності                               | власна інфраструктура клієнта CDP — код підтримки дорожчий за залежність |

Критерії вибору: реальний браузер (канвас/аудіо як у власника), мінімальний код підтримки, один devDep, передбачуваність у CI. @playwright/test — єдиний варіант, що закриває всі чотири.

## Рішення

DevDep `@playwright/test` (ADR-0012; авторизація — власник, сесія П11.5), конфіг `playwright.config.ts` (єдиний проєкт chromium, ретраї 2, трейс на падінні), спек `e2e/smoke.e2e.ts`, скрипт `npm run test:smoke`. Ціль — env `SMOKE_URL` (без env — локальний статичний сервер `http://localhost:8000/rubezh/`).

Твердження смоку (один тест, одна сторінка): HTTP 200, `<title>` містить «Рубіж», перший `canvas` видимий, нуль `pageerror` і console-error. Папка `e2e/` — поза `src/`: не входить у юніт-покриття (ADR-0017) і TypeDoc (entryPoints src/), гейт codecov/patch не зачіпається. Іменування — `*.e2e.ts` з `testMatch` у конфігу Playwright: суфікс не потрапляє у глоб vitest (`**/*.{test,spec}.ts`), тож юніт-прогони (`npm test`, `test:coverage`) спеку не тягнуть — валідовано живим прогоном (без цього юніт-ран падає на імпорті Playwright-стенду).

У `preview-branch.yml` (джоб `deploy`, після смоків ADR-0062): чекаут main + `npm ci` + `npx playwright install --with-deps chromium` + `npm run test:smoke` з `SMOKE_URL` = URL прев'ю. Інструментарій смоку береться з main, ціль — задеплоєне прев'ю: прев'ювана гілка коду смоку не виконує.

## Наслідки

- Червоний ран прев'ю = сторінка мертва як документ (білий екран, впав рендер) — власник бачить це раном, а не в браузері; візуальну коректність смок не замінює (свідомо не порівнює пікселі/скріншоти).
- Ціна: один devDep + ~1 хв на ран прев'ю (встановлення chromium); тільки на dispatch-прев'ю — на пуш у main і на PR смок не запускається.
- Dependabot оновлює `@playwright/test` за загальним процесом (ADR-0020).
- Зміна методики (скріншот-тести, більше браузерів) — лише через новий ADR із полем Supersedes.
