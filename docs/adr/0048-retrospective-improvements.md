# ADR-0048: Покращення процесу на основі ретроспективи

**Статус:** Proposed  
**Дата:** 2026-10-15  
**Автор:** Vibe Code  
**Замінює:** -  
**Суперседе:** -  

---

## Контекст

Після аналізу поточного стану проекту та попередніх сесій виявлено кілька проблем, які потребують системного вирішення:

1. Відсутність чіткого механізму синхронізації між Vibe Work та Vibe Code
2. Неузгодженість у нумерації та форматі промптів
3. Відсутність швидкого старту для нових сесій
4. Недостатня документація процесу для прискорення роботи

## Рішення

Впровадити наступні покращення:

### 1. Стандартизація промптів (ADR-0045)
- Всі промпти повинні мати формат `pX.Y`
- Заборонено використовувати неструктуровані промпти

### 2. Синхронізація між агентами (ADR-0046)
- Vibe Code не може починати роботу без наявності плану
- Обов'язкова перевірка наявності документів перед початком

### 3. Швидкий старт для сесій (ADR-0047)
- Уніфікований алгоритм початку сесії
- Автоматизовані перевірки стану проекту

### 4. Покращена документація
- Оновлений AGENTS.md з чіткими правилами
- Оновлений workflow.md з уточненими процесами
- Додані шаблони для планів та ADR

## Конкретні зміни

### В AGENTS.md:
- Додати розділ "Швидкий старт для нових сесій"
- Уточнити розподіл ролей між Vibe Work та Vibe Code
- Додати приклади правильних та неправильних промптів
- Додати розділ "Часті помилки та їх уникнення"

### В workflow.md:
- Додати детальний опис процесу для кожного етапу
- Уточнити критерії прийняття для кожного етапу
- Додати розділ "Ретроспектива та покращення"
- Додати шаблони для планів (EARS-format)

### Нові ADR:
- ADR-0045: Формат промптів для нових сесій
- ADR-0046: Синхронізація робочого процесу між агентами
- ADR-0047: Швидкий старт для нових сесій
- ADR-0048: Покращення процесу на основі ретроспективи (цей документ)

## Наслідки

### Переваги:
- Покращена узгодженість між сесіями
- Зменшення кількості помилок
- Прискорення процесу розробки
- Кращий контроль якості

### Недоліки:
- Додаткова робота з документацією
- Можливі затримки на етапі планування

### Мітгація:
- Автоматизувати перевірки
- Використовувати шаблони для документів
- Впровадити status-checks в CI/CD

## Альтернативи

1. **Не вносити змін** - Продовжити роботу в поточному форматі. Відхилено через наявні проблеми.
2. **Часткові зміни** - Впровадити лише деякі покращення. Відхилено через неузгодженість.
3. **Радикальний рефакторинг** - Повністю змінити процес. Відхилено через високий ризик.
