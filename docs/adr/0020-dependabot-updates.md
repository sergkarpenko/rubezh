# 0020. Автоматичні оновлення залежностей — Dependabot, мерж = авторизація

- Статус: accepted
- Дата: 2026-10-13

**Контекст.** Крок П3.4 плану Фази 3. ADR-0012 вимагає для оновлення версій уже наявних залежностей той самий шлях, що й для нових (ADR + авторизація власника + окремий коміт `chore(deps):`) — рутинні патчі витрачають сесію і роблять власника вузьким місцем; у самому ADR-0012 передбачено перегляд автоматизації окремим рішенням. Вибір сервісу — рішення власника (сесія 2026-10-13, вказівка «роби П3.4»): Dependabot проти Renovate. Renovate гнучкіший (розклад, групування, lockfile maintenance, automerge), але вимагає встановлення стороннього Mend Renovate App на репозиторій (крок власника поза репо) або self-hosted workflow з токеном — додаткова поверхня довіри заради ~12 dev-залежностей. Dependabot нативний: один конфігураційний файл у репо, нічого не встановлювати; репозиторій публічний — version updates доступні без обмежень.

**Рішення.** Ми використовуємо Dependabot version updates: конфіг `.github/dependabot.yml` — екосистема `npm` (каталог `/`, тижневий розклад, dev-залежності згруповані в один PR) та екосистема `github-actions` (оновлення версій actions у workflow). Бот-PR — окремий канал і свідомий виняток із листа про «той самий шлях» ADR-0012 (не скасування ADR-0012): мерж PR власником = авторизація, окремий ADR на кожне оновлення не потрібен; ADR-0012 лишається чинним для нових залежностей і будь-яких ручних змін `package.json` (pre-commit guard, правило 1b, чіпає лише локальні коміти — бот мержиться через GitHub, а не через hook). Автомерж вимкнено: кожен PR мержить власник після зеленого CI; повідомлення комітів бота мають префікси `chore(deps):` / `chore(ci):` (Conventional Commits). Конфіг лежить у `.github/`, не в `.github/workflows/` — процес ADR-0018 не застосовується.

**Наслідки.** Рутинні патчі залежностей більше не витрачають сесію; контроль лишається: Dependabot оновлює лише версії наявних залежностей (нових не додає — вага бандлу під контролем), кожен PR видно в рев'ю до мержу, `npm test` у CI працює як рубіж і на оновленнях. Ціна: тижневий потік PR-ів, які треба проглядати; групування dev-залежностей зменшує кількість PR-ів до одного-двох. Зміна рішення (наприклад, перехід на Renovate або повернення до повного процесу ADR-0012) — новий ADR із полем Supersedes.
