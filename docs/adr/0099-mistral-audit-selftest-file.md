# 0099. Самоперевірка аудитора Mistral — окремий файл

- Статус: accepted (мерж PR власником = «схвалюю» — конвенція ADR-0018/0052)
- Дата: 2026-11-15
- Доповнює: ADR-0095 (скрипт аудитора і його самоперевірка — перший крок джоби); ADR-0098 (контекст аудитора; поведінку аудиту цей ADR не міняє); ADR-0018 (зміна workflow-файлу — з ADR)
- Автор: Claude Code (рішення власника 2026-11-15, кнопкою в чаті на старті кроку: «Кандидат 40: самоперевірка окремо»; задача Т.42)

## Контекст

Після Т.41 `scripts/mistral-audit.mjs` мав 1214 рядків, з них 667 — функція самоперевірки. Обидва кроки, що міняли скрипт (Т.37 і Т.41), вийшли за ліміт 500 рядків (ADR-0036) і потребували мітки `size-deviation` (ADR-0061): кожна зміна логіки тягне за собою перевірки в тому самому файлі. Читачеві (і аудиторові, якому файл подається в дифі) логіку аудиту доводилось шукати серед тестових даних.

## Рішення

1. **Самоперевірка — у файлі `scripts/mistral-audit-selftest.mjs`.** Функцію `selfTest` перенесено без змін у наявних перевірках (функція стала експортом; додано дві перевірки — п. 4 і п. 5); файл імпортує основний скрипт і запускається сам: `node scripts/mistral-audit-selftest.mjs`. У мережу не ходить, поза тимчасову теку не пише — як і раніше.
2. **Джоба `mistral-audit` викликає цей файл** першим кроком. Умова зеленого — код виходу 0 і рядок підсумку «помилок 0»: у кроці явно ввімкнено `pipefail`. Досі крок ішов під `bash -e` без `pipefail`, і код виходу самоперевірки в конвеєрі з `grep` губився — гейтом був лише рядок підсумку.
3. **Прапорець `--self-test` основного скрипта лишається** як короткий шлях: запускає файл самоперевірки окремим процесом і повертає його код.
4. **Межі й допоміжні функції, потрібні перевіркам, основний скрипт віддає одним об'єктом `internals`.** Це не публічний інтерфейс: ним користується лише файл самоперевірки. Щоб об'єкт не розійшовся з кодом непомітно, самоперевірка звіряє числові межі з виписаними числами: зміна межі в коді потребує зміни цього рядка перевірки.
5. **Файл самоперевірки — файл аудитора:** PR, що його міняє, отримує в коментарі аудитора ту саму позначку «PR змінює самого аудитора», що й для скрипта та workflow. Ім'я файла згадано у workflow, тож за `scripts/pr-class.sh` його зміна — клас `approve` (ADR-0094): послабити перевірки без «схвалюю» не можна.
6. **Без змін:** що бачить аудитор, модель, коментар, поведінка при збої, чек не обов'язковий (ADR-0095, ADR-0097, ADR-0098).

## Альтернативи

- **Лишити один файл.** Кожна наступна зміна аудитора знову виходить за ліміт розміру.
- **Назвати файл `*.test.mjs`.** Його підхопив би `vitest` (`npm test`) — самоперевірка працює з git у тимчасовій теці й до тестів гри не належить.
- **Workflow не чіпати, файл самоперевірки завантажувати з основного скрипта за прапорцем.** Тоді ім'я файла ніде у `.github/` не згадано і його зміна стає класом `auto` — перевірки аудитора можна було б послабити без «схвалюю».

## Наслідки

- Основний скрипт — 577 рядків, самоперевірка — 734; зміна логіки з перевірками має шанс укластись у 500 рядків.
- Сам PR перенесення великий за підрахунком (перенесені рядки рахуються і як видалені, і як додані) — мітка `size-deviation` за ADR-0061.
- `docs/reports/t37/mutations.py` і `docs/reports/t41/mutations.py` запускали копію одного файла з прапорцем `--self-test` — після поділу самі по собі не працюють; переліки поломок Т.41 проганяє `docs/reports/t42/mutations.py` над двома файлами.
