# ADR-0075: Евакуація з місії

**Дата:** 2026-10-25  
**Статус:** accepted (планувальний PR Фази 15; рішення власника зафіксовані в блоці фази у docs/workflow.md)  
**Доповнює:** ADR-0021 (економіка), ADR-0022 (patrol ШІ), ADR-0026 (сейв-контракт), ADR-0033 (мета кампанії)  
**Пов’язані:** ADR-0003 (детермінізм), ADR-0054 (версіонування)

## Контекст

Понині бій місії має два виходи: перемога (усі прибульці мертві) чи поразка (увесь загін мертвий). Проміжного виходу нема: загін не може відступити, щоб врятувати поранених, — програна позиція означає смерть усього загону. Евакуація з місії — давній пункт backlog (з переліку пост-MVP, 2026-10-16); власник обрав її темою Фази 15 (2026-10-25). Це фича ядра: змінюються бойове ядро (нова дія), ШІ (множина цілей), зв’язок шарів (новий результат місії) і економіка (врятовані без премії).

## Рішення

Рішення власника (2026-10-25, Work-сесія планування):

1. **Евакуація — із зони висадки загону** (SQUAD_SPAWN, чинна зона появи загону на мапі місії) у будь-який момент бою. Спеціальної точки евакуації на мапі не додається.
2. **НЛО при евакуації лишається приземленим** (як при поразці): вікно посадки тікає далі чинною логікою geo.ts; премія за місію не нараховується; місію можна спробувати повторно новим загоном.
3. **Бій завершується лише коли живих солдатів на полі немає** — всі живі евакуйовані або загинули. «Залишити» солдата на полі не можна: явного «відльоту» з живими на полі нема; солдат, який не дійшов до точки, просто продовжує бій (і, як наслідок, може загинути — перма-смерть наскрізна).
4. **Евакуюватись можна з будь-якою кількістю живих.** Результат «евакуйовано» настає при ≥1 врятованому; 0 врятованих (усі загинули) — чинна «поразка» 5.0 без змін.

Рішення реалізації (кандидати агента; уточнюються probe П15.5 і валідацією):

- Дія evacuate(state): активний солдат у клітинці зони висадки, вартість **2 AP** (кандидат); солдат вилучається з поля й потрапляє в список evacuated стану бою; подія evac_unit у лог бою.
- Евакуйований не бере участі у подальшому бою: не ціль ШІ, пострілів, гранат, дозору й реакційного вогню; ШІ діє лише щодо неевакуйованих, при 0 видимих цілях — patrol до зони висадки (ADR-0022 без змін).
- Новий результат місії «евакуйовано» (mission_evacuated): completeMission при 0 живих на полі й ≥1 евакуйованому повертає цей результат; НЛО лишається (як при поразці), премія не нараховується; врятовані проходять чинний контур уцілілих applyMissionResult (лікарня при пораненні за ADR-0021, предмети збережені).
- Сейв-контракт (ADR-0026): evacuated — стан бою, сейв у бою недоступний, формат сейву не росте; сейви сумісні без міграції. Версія — MINOR v0.7.0 (ADR-0054).
- Детермінізм (ADR-0003): нова дія не тягне RNG; траєкторії геосцени без фічі і з нею — за умови однакових дій байт-у-байт.

## Наслідки

- З’являється третій вихід із бою: «евакуйовано» — врятовані солдати залишаються в ростері (перма-смерть зберігається для загиблих), ціною премії й залишеного НЛО.
- Тактика місій ускладнюється: відступ під вогнем у зону висадки стає валідною стратегією рятунку ветеранів (значення ветеранів у рахунку зростає).
- Ризик балансу: безпремійний безпечний вихід може стати «пасивною» стратегією — контрольується probe П15.5 за методикою «порожніх перемог» (урок П11.8); політика бота для probe — окремий кандидат після грід-проби.
- UI: нова команда у тулбарі й на клавіатурі (V), підсвітка зони висадки, повідомлення-причини відхилення — крок П15.4.
