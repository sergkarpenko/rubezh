# 0019. Публікація TypeDoc-довідки на GitHub Pages — `/api/` поруч із демо

- Статус: accepted
- Дата: 2026-10-13

**Контекст.** Крок П3.3 плану Фази 3. ADR-0016 дав локальну генерацію довідки (`npm run docs` → `dist/api/`), але без публікації: довідка видно лише тому, хто клонує репозиторій. Превью демо вже деплоїться на Pages з кожного пушу в `main` (ADR-0009), довідка того ж API могла б жити поруч. Нюанс порядку кроків: `vite build` очищує `dist/` — генерація має виконуватися після збірки. Розглянуті альтернативи: окремий сайт Pages з іншим репозиторієм/гілкою (друге місце правди і другий конвеєр наради); Wiki GitHub (інший формат, без HTML TypeDoc); деплой `dist/api` окремим артефактом (два деплої Pages — конфлікт concurrency і складніший workflow). Зміна workflow-файлів тепер легальна за процесом ADR-0018 (ADR у тому ж коміті).

**Рішення.** Ми публікуємо довідку в тому ж Pages-артефакті, що й демо: у CI крок `npm run docs` виконується після `npm run build` (порядок обов'язковий: `vite build` очищає `dist/`, TypeDoc пише в `dist/api/` за конфігом ADR-0016), і `upload-pages-artifact` уже заливає весь `dist`. URL довідки: `https://sergkarpenko.github.io/rubezh/api/` — поруч із демо, оновлюється з кожним пушем у `main` автоматично. TypeDoc генерує відносні посилання (`data-base="./"`), тож субшлях `/rubezh/` не ламає стилі й навігацію; локально поведінка та сама (`npm run build && npm run docs`).

**Наслідки.** Публічна довідка API ядра доступна за постійним URL без клону репозиторія; «джерело одне» з ADR-0016 зберігається — довідка перегенерується з коду в кожному пуші, не комітиться. Ціна: Pages-артефакт важчає на розмір HTML-довідки (мегабайти, несуттєво для Pages); крок додає ~2–3 с до CI. Демо не зачіпається — `dist/api` лягає поруч, не конфліктуючи з ассетами Vite. Зміна рішення (наприклад, окремий домен/брендинг довідки) — новий ADR із полем Supersedes.
