# 0010. Цільовий шар відображення — ванільний TS + Canvas; React-віджети — довідкові прототипи

- Статус: accepted
- Дата: 2026-10-13

**Контекст.** Відображення прототипувалося як React-канваси (BattleWidget 3.6, GeoWidget 4.2/5.1) у прототипувальному середовищі. У репозиторій вони потрапили як довідковий знімок `src/ui/`: містять вбудовані копії модулів ядра (джерело правди дублюється й розходиться), залежать від React, якого немає у залежностях проєкту. Онлайн-превью (ADR 0009) продемонструвало, що ванільний TS + Canvas 2D достатній для цільового відображення і прямо відповідає ADR 0001 (браузер, без фреймворків). Відкрите питання: розвивати `src/main.ts` як цільовий UI чи підтримувати обидва шари.

Розглянуті альтернативи: зробити React залежністю і розвивати `src/ui/` як цільовий UI (суперечить ADR 0001, додає вагу залежностей); паралельна підтримка двох шарів відображення (подвійне обслуговування, дублікати ядра у віджетах розходяться з `src/core/`).

**Рішення.** Ми використовуємо `src/main.ts` (ванільний TS + Canvas 2D) як єдиний цільовий шар відображення, який розвиваємо далі: інтерактивний тактичний бій у превью — наступна ітерація. `src/ui/` — довідкові прототипи: нові можливості ядра в них не портуються, функціонально не підтримуються; їхня роль — історія прототипування та джерело UX-рішень для портування в main.ts. Інтеграція ростеру в GeoWidget.tsx не виконується: ростер і місії живуть у превью (main.ts) ще з ітерації P.

**Наслідки.** Одна кодова база відображення; логіку взаємодії з віджетів переносимо в main.ts поступово, за потреби. Прототипи у `src/ui/` старіють і згодом можуть бути вилучені з репо (новим ADR). Зміна рішення — новим ADR (Supersedes).
