# 0056. Автоматичне видалення головних гілок PR після мержу

- Статус: accepted (налаштування репо вже увімкнено власником 2026-10-16; фіксується ADR + правкою docs у одному PR — урок ADR-0028)
- Дата: 2026-10-16
- Доповнює: ADR-0028 (доставка гілка + PR, мерж merge-комітом), ADR-0052 (апрув і теги в сесії)
- Автор: Vibe Work (увімкнення налаштування — власник, Work-сесія 2026-10-16)

## Контекст

ADR-0028 запровадив доставку гілка + PR; видалення головної гілки PR лишалось ручним кроком після мержу. Практика Фаз 7–9 показала, що ручний крок пропускається: станом на 2026-10-16 у репо накопичилось 31 застаріла гілка, і всі — головні гілки змержених PR. Урок ADR-0028: зміна налаштувань репо фіксується ADR + правкою AGENTS.md/workflow.md у тому ж PR. GitHub надає нативне налаштування «Automatically delete head branches» (Settings → General → Pull Requests): головна гілка PR видаляється одразу після мержу.

## Рішення

Власник увімкнув налаштування репо «Automatically delete head branches». Тепер процес після мержу (крок 5 циклу ядра) такий: `git checkout main && git pull --ff-only`; віддалену головну гілку PR GitHub уже видалив; локальну гілку й віддалені посилання чистимо `git branch -d` / `git fetch --prune`. Ручне видалення віддалених гілок з процесу зникає.

## Наслідки

- Застарілі головні гілки більше не накопичуються: список гілок репо = `main` + гілки в роботі.
- Головна гілка видаляється і для PR, закритих без мержу — перед повторним використанням гілки її треба перепушити.
- Налаштування репо зафіксовано цим ADR; зміна — лише через новий ADR із полем Supersedes.

## Альтернативи

- Ручне видалення після кожного мержу (status quo) — відкинуто: 31 пропущена гілка за три доби роботи.
- GitHub Action для чищення гілок — відкинуто: зайва залежність (ADR-0012) при нативному налаштуванні репо.
