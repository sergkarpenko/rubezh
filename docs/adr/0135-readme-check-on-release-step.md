# 0135. Звірка `README.md` і «Як грати» з кодом — пункт кожного реліз-кроку

- Статус: accepted (мерж PR власником = «схвалюю» — конвенція ADR-0023/0030/0052)
- Дата: 2026-11-24
- Доповнює: ADR-0054 п. 2 (реліз-крок), ADR-0133 (`README.md` під гейтом prettier), ADR-0096 (довідники агентів)
- Автор: Claude Code (Т.166, рішення власника кнопкою «А. Пункт процедури»)

## Контекст

Реліз-крок (ADR-0054 п. 2) піднімає `version`, пише нотатки Release і чекає валідації власника. Звірки гравцевих текстів із кодом у процедурі немає. Вона жила лише уроками: ретроспектива Фази 11 (П11.9 — README відстав на п'ять кроків: фічі фази, найм за множником, клавіші M/G, кількість тестів) дала правило «у реліз-кроці перевіряти README/сторінку «Як грати» на відповідність changelog фази»; ретроспектива Фази 12 (П12.8 — «Як грати» без клавіш M/G і з «грошовою одиницею» всупереч глосарію) його підтвердила; на реліз-кроці Т.77 (v0.7.0) звірка знайшла відсутню клавішу V у «Як грати» і в README. Тричі з трьох дрейф знаходився лише тому, що сесія згадала урок.

Механічний гейт охопив би лише частину тексту: у `README.md` немає ні версії, ні числа тестів; звірити скриптом можна числа економіки (`src/core/economy.ts`), гарячі клавіші (`src/ui/input.ts`) і перелік обов'язкових чеків — опис механік, екранів і вигляду гейт не бачить.

## Рішення

1. Кожен реліз-PR (крок «Реліз vN.N.N», ADR-0054 п. 2) звіряє з кодом своєї гілки **кожне речення** кореневого `README.md` і екрана «Як грати» (`src/ui/help.ts`), а не лише пункти changelog фази.
2. Джерела звірки: числа економіки, ціни, множники пресетів і рахунку — константи ядра (`src/core/`); гарячі клавіші — обробники клавіш у `src/ui/input.ts`; перелік обов'язкових чеків `main` — налаштування захисту гілки (`gh api repos/sergkarpenko/rubezh/branches/main/protection/required_status_checks`); механіки й екрани — код і записи кроків фази в `docs/workflow.md`.
3. Знахідки виправляються в тому ж реліз-PR. Опис реліз-PR має розділ «Звірка README і «Як грати»» — перелік знахідок і виправлень або «розбіжностей не знайдено» з переліком звірених джерел; аудитор PR (ADR-0094, ADR-0104) перевіряє цей розділ.
4. Пункт — у «Рішеннях» `docs/workflow.md` поруч із правилом версіонування; робочий чекліст — у `docs/agents/common.md`. Нового гейта CI немає; workflow і скрипти без змін.
5. Між реліз-кроками чинне правило довідника «Оновлення документа «за кодом»» (`docs/agents/common.md`): крок, що міняє описане в `README.md`, звіряє зачеплений текст сам.

## Наслідки

- Звірка стає кроком процедури, а не пам'яттю сесії: реліз-PR без розділу звірки видно в описі й на аудиті.
- Реліз-крок довшає на звірку двох текстів (≈ 14 КБ `README.md` і вікно «Як грати»); реліз-кроки рідкі — раз на фазу.
- Дрейф між релізами гейт не ловить; умова перегляду — якщо реліз-звірка знову знайде числа чи клавіші, що відстали, вирішити про гейт окремим ADR (ADR-0018 для кроку в CI).

## Альтернативи

- Гейт у CI — скрипт звіряє числа економіки, гарячі клавіші й перелік чеків у `README.md` на кожному PR — відхилено власником: ловить лише частину тексту, а крок у CI — зміна workflow (ADR-0018).
- Пункт процедури і гейт разом — відхилено власником: більший PR, гейт з тієї ж причини.
- Лишити правило в «Уроках» `docs/workflow.md` — так було з П11.9; урок не є кроком процедури реліз-PR.
