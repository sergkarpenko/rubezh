# 0009. Онлайн-превью: GitHub Pages + GitHub Actions

- Статус: accepted
- Дата: 2026-10-13

**Контекст.** Ядро гри має два шари відображення: React-віджети (прототипи, у репо — довідковий знімок у `src/ui/`) та демо-сторінку `src/main.ts` (ванільний TS + Canvas 2D). Постала потреба в постійно доступній вітрині актуального стану проєкту: власник валідує ітерації в браузері без локального запуску, а гру можна показати за одним посиланням. Обмеження: хобі-проєкт без бюджету і серверів; стек — браузер, без фреймворків (ADR 0001/0007).

Розглянуті альтернативи:

- StackBlitz / Codespaces — хмарні IDE в браузері: значно важчі, ніж потрібно для перегляду (достатньо статичної сторінки), потребують облікових записів, актуальність залежить від ручного оновлення середовища; стабільного URL «поглянути» не дають.
- Netlify / Vercel / VPS — деплой поза GitHub: додаткові облікові записи й конфігурація, частина інфраструктури поза джерелом правди.
- Лише локальний запуск (`npm run dev`) — валідація людьми ускладнена, показати неможливо.

**Рішення.** Ми використовуємо GitHub Pages як хостинг превью та GitHub Actions як пайплайн збірки. Workflow `.github/workflows/preview.yml`: при пуші в main (та вручну через workflow_dispatch) виконується `npm install` → `npm test` → `vite build` → deploy-pages (permissions: `pages: write`, `id-token: write`; concurrency «pages»). Vite збирається з `base: '/rubezh/'`. Превью — самостійний `src/main.ts` (не React-віджет): геосцена (час, радар, НЛО), ростер (перма-смерть), журнал лише виявлених НЛО; тактичний бій відтворюється автоматично двома ботами (демо-бот гравця `src/bot.ts` + ШІ прибульців `src/core/ai.ts`) з туманом війни з погляду гравця. Логіка превью — лише виклики ядра без змін. Інтерактивний бій у превью — майбутня ітерація. Єдиний ручний крок налаштування: Settings → Pages → Source = «GitHub Actions». URL: https://sergkarpenko.github.io/rubezh/

**Наслідки.** Кожен пуш у main проходить ланцюжок тести → збірка → деплой: червоний CI означає, що превью не оновиться, і зламаний стан не потрапить на сторінку. Превью оновлюється автоматично після кожного коміту; коректність стану підтверджує власник у сесійному процесі (docs/workflow.md). Хостинг і пайплайн безкоштовні для публічного репозиторію. Ціна: частина відображення (bot.ts) існує лише для демо — до інтерактивного бою у превью. Зміна хостингу чи пайплайна — новим ADR (Supersedes).
