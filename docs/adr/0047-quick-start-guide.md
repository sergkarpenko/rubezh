# ADR-0047: Швидкий старт для нових сесій

**Статус:** Proposed  
**Дата:** 2026-10-15  
**Автор:** Vibe Code  
**Замінює:** -  
**Суперседе:** -  

---

## Контекст

Для прискорення початку роботи нових сесій та зменшення кількості помилок, необхідно мати чіткий алгоритм дій, який кожен агент повинен виконувати на початку сесії. Це особливо важливо для AI-агентів, які не мають контексту попередніх сесій.

## Рішення

Впровадити уніфікований алгоритм "Швидкий старт" для всіх сесій:

### Алгоритм для будь-якої сесії:
```bash
# Крок 0: Оновити локальні дані (ОБОВ'ЯЗКОВО!)
git pull origin main

# Крок 1: Ознайомитися з контекстом
cat docs/workflow.md
cat AGENTS.md
ls docs/adr/ | tail -10

# Крок 2: Перевірити поточний стан
git status
git log --oneline -5
git tag -l | sort -V | tail -5

# Крок 3: Вибрати завдання
# - Для Vibe Work: "p8.5" => створити план
# - Для Vibe Code: "p8.5" => реалізувати план
```

### Для Vibe Work (планування):
```bash
# 1. Отримати промпт "pX.Y"
# 2. Оновити локальні дані
# 3. Створити план в docs/plans/pX.Y.md
# 4. Створити ADR (якщо потрібно)
# 5. Оновити workflow.md
# 6. Зробити коміт та PR
```

### Для Vibe Code (реалізація):
```bash
# 1. Отримати промпт "pX.Y"
# 2. Оновити локальні дані
# 3. Перевірити наявність docs/plans/pX.Y.md
# 4. Реалізувати код згідно плану
# 5. Тестувати, комітити, робити PR
```

### Шаблон для швидкої перевірки:
```bash
#!/bin/bash
# quick-check.sh

echo "=== Git Status ==="
git status

echo ""
echo "=== Recent Commits ==="
git log --oneline -5

echo ""
echo "=== Recent Tags ==="
git tag -l | sort -V | tail -5

echo ""
echo "=== ADR List ==="
ls docs/adr/ | grep -E "^[0-9]{4}-" | sort -V | tail -10

echo ""
echo "=== Plans List ==="
ls docs/plans/ 2>/dev/null || echo "No plans directory"
```

## Наслідки

### Переваги:
- Швидший старт сесій
- Зменшення помилок через відсутність контексту
- Узгодженість між сесіями
- Легше навчати нових учасників

### Недоліки:
- Додатковий час на початкову перевірку
- Можлива надмірність для досвідчених користувачів

### Мітгація:
- Автоматизувати перевірку через скрипти
- Додати флаги для пропуску кроків для досвідчених користувачів

---

## Альтернативи

1. **Ручна перевірка** - Кожен агент сам вирішує, що перевіряти. Відхилено через неузгодженість.
2. **Автоматична перевірка** - Всі перевірки виконуються автоматично. Відхилено через можливі помилки.
3. **Централізований дашборд** - Спеціальний інтерфейс для перевірки стану. Відхилено через складність реалізації.
