# 0131. Чек `shuffle` — обов'язковий чек гілки `main`

- Статус: accepted (мерж PR власником = «схвалюю» — конвенція ADR-0052)
- Дата: 2026-11-24
- Частково Supersedes: ADR-0128 (п. 3 — «чек `shuffle` не обов'язковий»; п. 4 — «обов'язкові чеки `main` без змін»)
- Доповнює: ADR-0082 (обов'язкові чеки `main`), ADR-0028 (захист гілки `main`), ADR-0094 (умови мержу класу `auto`), ADR-0018 (зміна workflow — з ADR)
- Автор: Claude Code (рішення власника 24.11.2026 на фініші Т.154 кнопкою — «Схвалюю; shuffle обов'язковий (145)»; кандидат процесу 145 — з Т.151)

## Контекст

- ADR-0128 (Т.151) додав джобу `shuffle` у workflow `ci` — `npm test` у перемішаному порядку з сідом `github.run_id % 1000000` — і лишив чек необов'язковим до рішення власника, «коли джоба покаже стабільність».
- Джоба зелена на всіх PR після неї: #464, #465, #466, #467 (кожен пуш — новий сід). Ціна — ≈ 1,5 хв раннера паралельно з `test` (≈ 2,2 хв), тож очікування мержу не подовжує.
- Обов'язкові чеки `main` до цього ADR (`gh api …/branches/main/protection/required_status_checks`, 24.11.2026): `test`, `codecov/patch`, `pr-size`, `e2e`.

## Рішення

1. Чек `shuffle` (джоба `shuffle` workflow `ci`, застосунок GitHub Actions) — обов'язковий чек гілки `main` поруч із `test`, `codecov/patch`, `pr-size`, `e2e`. Налаштування — у захисті гілки (`Settings → Branches`, правило `main`, «Require status checks to pass»): змінює власник або сесія в його браузері з його підтвердженням; зміну через `gh api` із сесії відхиляє класифікатор дій (Т.155).
2. Червоний `shuffle` блокує мерж будь-якого класу: залежність від порядку виправляється в тому ж PR. Пояснення в описі PR класу `auto` за червоного `shuffle` (ADR-0128 п. 3) більше не діє — такий PR не мержиться.
3. Рідкісне падіння на невідомому сіді не обходиться «Re-run»: він дає той самий сід і той самий порядок. Відтворити — командою з журналу джоби, виправити тест; новий пуш дає новий сід.
4. Workflow `ci` — без змін у логіці: оновлено лише коментарі про обов'язковість. Кандидат 27 (чек `check` workflow `iter-tag`) — поза рішенням.

## Відхилені варіанти

- **Лишити необов'язковим:** червоний `shuffle` уже вимагав виправлення або пояснення (ADR-0128 п. 3), але мерж не зупиняв — правило трималось на увазі агента.
- **Крок у джобі `test`:** змінює зміст наявного обов'язкового чека і додає ≈ 30 с до найдовшої джоби; окремий чек дає ту саму силу без цього (як і в ADR-0128).
- **Фіксований сід для обов'язкового чека** (щоб уникнути «випадкових» падінь): перевіряв би один порядок — гейт без користі; падіння на новому сіді — справжня вада тестів, а не шум.

## Наслідки

- Обов'язкових чеків `main` — п'ять; поради про очікування чеків і умови мержу `auto` в `docs/agents/common.md` і пункт 5 циклу кроку в `docs/workflow.md` оновлено. Перелік чотирьох чеків в ADR-0094 п. 3 цим ADR доповнено п'ятим — `shuffle` (ADR не правлять); записи минулих кроків про «чотири чеки» — історія, без змін.
- Перевірка: `gh api repos/sergkarpenko/rubezh/branches/main/protection/required_status_checks` — `shuffle` у переліку `contexts`.
- Зняти чек з обов'язкових — новим ADR, рішенням власника.
