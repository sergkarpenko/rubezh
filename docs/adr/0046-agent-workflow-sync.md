# ADR-0046: Синхронізація робочого процесу між агентами

**Статус:** accepted  
**Дата:** 2026-10-15  
**Автор:** Vibe Code  
**Замінює:** -  
**Суперседе:** -  

---

## Контекст

На даний момент існує розрив між роботою Vibe Work (планування) та Vibe Code (реалізація). Це може призводити до того, що Vibe Code починає роботу без чіткого розуміння вимог або без належного плану. Також відсутній механізм перевірки, чи всі необхідні документи (плани, ADR) створено перед початком реалізації.

## Рішення

Впровадити чіткий механізм синхронізації між агентами:

### 1. Процес Vibe Work:
```
1. Отримати промпт pX.Y
2. git pull origin main
3. Проаналізувати поточний стан (git status, git log, tags)
4. Створити план в docs/plans/pX.Y.md (EARS-format)
5. Створити необхідні ADR в docs/adr/
6. Оновити workflow.md та AGENTS.md (якщо потрібно)
7. Зробити коміт та PR
8. Чекати merge в main
```

### 2. Процес Vibe Code:
```
1. Отримати промпт pX.Y
2. git pull origin main
3. Перевірити наявність:
   - docs/plans/pX.Y.md
   - Відповідних ADR в docs/adr/
   - Оновленого workflow.md
4. Якщо чогось немає - чекати на завершення роботи Vibe Work
5. Реалізувати код згідно плану
6. Тестувати, комітити, робити PR
```

### 3. Перевірка синхронізації:
Перед початком роботи Vibe Code **зобов'язаний** виконати:
```bash
# Перевірити, чи є план
test -f docs/plans/pX.Y.md || { echo "План не знайдено!"; exit 1; }

# Перевірити, чи є ADR для цього етапу
ls docs/adr/ | grep -E "ADR-[0-9]{4}" || { echo "ADR не знайдено!"; exit 1; }

# Перевірити поточний стан git
git status
git log --oneline -5
```

## Наслідки

### Переваги:
- Чітка синхронізація між агентами
- Зменшення ризику роботи без плану
- Покращений контроль версій
- Легше відстежувати прогрес

### Недоліки:
- Додатковий час на перевірку синхронізації
- Можливі затримки, якщо Vibe Work не завершив роботу

### Мітгація:
- Автоматизувати перевірку синхронізації через скрипти
- Впровадити status-checks в GitHub Actions

---

## Альтернативи

1. **Автоматичне чекання** - Vibe Code автоматично чекає на завершення Vibe Work. Відхилено через складність реалізації.
2. **Спільна сесія** - Обидва агенти працюють в одній сесії. Відхилено через обмеження платформи.
3. **Централізований керування** - Один агент керує обома процесами. Відхилено через розподіл відповідальності.
