# 0076. Гейти типів, лінту і формату — у CI, а не лише в pre-commit

- Статус: accepted (мерж PR власником = «схвалюю» — конвенція ADR-0023/0030/0052)
- Дата: 2026-11-10
- Доповнює: ADR-0014 (pre-commit), ADR-0015 (ESLint + Prettier), ADR-0016 (TypeDoc), ADR-0025/0028 (required-чек `test`), ADR-0018 (зміна workflow-файлів — з ADR у точці коміту)
- Автор: Claude Code (запит власника 2026-11-10, задача Т.5b; спостереження — аналіз процесу 2026-11-10)

## Контекст

Урок П7.5 зафіксував принцип: гейт має жити в механізмі репозиторія, а не в увазі агента. Три перевірки якості цьому принципу не відповідали:

1. **Типи тестових файлів не перевіряв ніхто.** Vitest типи не перевіряє (урок П11.3), а TypeDoc — сурогатна перевірка типів у CI — виключає `*.test.ts` (`tsconfig.typedoc.json`). На `a9ff074` повний `npx tsc --noEmit` давав 20 помилок: імпорт неіснуючого типу, застарілий тип результату бою після П15.2, конфлікт декларацій ассетів з `vite/client` тощо (виправлено в Т.5a). Жодна з них не робила червоним ні локальний чекліст, ні CI.
2. **ESLint і Prettier працювали лише у pre-commit** (lint-staged, ADR-0014/0015). Хук обходиться `--no-verify` — і процес це прямо дозволяє у кількох уроках (П10.2, П10.5); коміт, зроблений поза локальним клоном власника (хмарний агент, веб-редактор GitHub), хук не проходить узагалі.
3. **CI ставив залежності `npm install`**, який може тихо оновити lockfile; урок П9.4 («локальні node_modules дрейфують від lockfile») стосується і ранера.

## Рішення

1. Джоба `test` у `.github/workflows/ci.yml` (required-чек захисту `main`) отримує три кроки перед тестами — від найшвидшого:
   - `npx tsc --noEmit` — повна перевірка типів за `tsconfig.json`, **включно з тестами**;
   - `npm run lint` — ESLint (`src/`);
   - `npm run format:check` — Prettier (`src/`, `index.html`).
2. `npm install` у ci.yml замінено на `npm ci` — встановлення строго за `package-lock.json`.
3. Нових залежностей і скриптів `package.json` немає (ADR-0012 не зачіпається): `tsc` — з наявного `typescript`.
4. Pre-commit хук лишається як швидкий локальний зворотний зв'язок; рубежем є CI. `--no-verify` більше нічого не обходить: ті самі перевірки повторює required-чек.
5. Локальний чекліст перед комітом (AGENTS.md): `npm test` → `npx tsc --noEmit` → `npm run docs`.
6. Workflow-и деплою (`preview.yml`, `preview-branch.yml`) цим ADR не змінюються: вони виконуються після мержу або вручну і гейтом PR не є; перехід їх на `npm ci` — окремою задачею після першого живого рану ci.yml (урок П11.5: механіку workflow перевіряє лише живий ран).

## Наслідки

- Помилка типів у тесті, порушення лінту або формату дає червоний чек `test` незалежно від того, хто і звідки зробив коміт.
- Джоба довша на кілька секунд (tsc на ~25 тис. рядків, eslint, prettier).
- `npm ci` падає, якщо `package.json` і lockfile розійшлися, — це бажана поведінка: розсинхрон стає видимим у PR, який його вніс.
- Скоуп лінту і формату не розширюється (`scripts/`, `e2e/` — відкритий хвіст П8.5, окреме рішення власника).
- Перший живий ран — на PR цієї задачі: він сам проходить нові кроки.
- Зміна складу гейтів — лише через новий ADR.

## Альтернативи

- Лишити як є (pre-commit + TypeDoc) — відкинуто: 20 помилок типів у main показали, що рубежу немає.
- Окремий workflow `lint.yml` з власним чеком — відкинуто: новий required-чек потребує дії власника в Settings → Branches; кроки в наявній джобі `test` стають обов'язковими одразу.
- Додати скрипт `typecheck` у `package.json` — відкладено: зміна `package.json` (правило 1b, ADR-0012) без потреби; `npx tsc --noEmit` достатньо.
