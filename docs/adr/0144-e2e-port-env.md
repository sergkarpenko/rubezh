# 0144. Порт прев'ю сценарію e2e — зі змінної оточення `E2E_PORT`

- Статус: accepted (мерж PR власником = «схвалюю» — конвенція ADR-0052)
- Дата: 2026-11-25
- Доповнює: ADR-0080 (сценарій приймання, `playwright.e2e.config.ts`), ADR-0140 (кореневі конфіги Playwright під гейтами), ADR-0139 (шрифт e2e), ADR-0018 (workflow без змін)
- Автор: Claude Code (рішення власника 25.11.2026 на фініші Т.177 кнопкою — «Порт e2e з оточення (49) (Рекомендовано)»; кандидат процесу 49)

## Контекст

- `playwright.e2e.config.ts` тримав порт власного прев'ю сталою `PORT = 4173` (`vite preview --port 4173 --strictPort`, `reuseExistingServer: false`). У контейнері сесії порт один на всіх: e2e субагента-аудитора, прев'ю сесії і її власний e2e одночасно дають «Port 4173 is already in use» (`docs/agents/ui.md`, Т.43; аудиторові радили не запускати e2e взагалі).
- Обхід через `E2E_URL` потребує окремо зібраної і піднятої збірки; змінити сам порт без правки конфіга було неможливо.
- Звірка на `main` = `90cf4ac`: порт 4173 у кореневих конфігах і workflow згадано лише в `playwright.e2e.config.ts`; workflow `ci` (джоба `e2e`) порту не задає; `playwright.config.ts` (домен-смок прев'ю) власного сервера не піднімає.

## Рішення

1. `E2E_PORT` — порт власного прев'ю сценарію (команда `webServer`, його `url` і типовий `baseURL`). Не задано або порожнє — 4173, як раніше: CI і чинні команди довідників не міняються.
2. Значення не з самих цифр (з нулем попереду теж) або поза 1–65535 — помилка конфіга до старту з назвою змінної і значенням (`E2E_PORT має бути цілим числом 1–65535, отримано «…»`), а не тихий перехід на 4173: типовий порт міг бути зайнятий чужою збіркою.
3. `E2E_URL` і далі має пріоритет: із ним сервер не стартує і порт не використовується, але значення `E2E_PORT` перевіряється й тоді — неправильне в оточенні видно одразу. `--strictPort` і `reuseExistingServer: false` лишаються — зайнятий обраний порт так само падає з «already used», а не береться чужий сервер.

## Наслідки

- Перевірка (Т.178): порт 4173 зайнято стороннім сервером — прогін без змінної падає з «Port 4173 is already in use», з `E2E_PORT=4190` — 6 сценаріїв зелені; `abc`, `0`, `0080`, `70000`, `4173.5`, ` 4180` — помилка конфіга; порожнє — типовий порт.
- Аудитор у контейнері сесії може запускати e2e на своєму порту з окремої копії репозиторію (збірка `dist/` і `dist/e2e-results` — у клоні, два прогони в одному клоні перезаписали б їх) (порада — `docs/agents/ui.md`, `docs/agents/common.md`); прев'ю на 4174–4176 для вимірів — як і раніше.
- Workflow, `package.json`, `playwright.config.ts`, сценарії і код гри без змін; клас PR — `approve` (кореневий конфіг Playwright, ADR-0140).
- Відхилено: вільний порт автоматично (`get-port` чи `server.listen(0)`) — нова залежність або асинхронний конфіг, а номер порту треба знати наперед для `E2E_URL` поломок і для розподілу портів між сесією й аудитором; `reuseExistingServer: true` — прогін узяв би чужу збірку (причина ADR-0080); прапорець CLI замість змінної — Playwright не передає власні аргументи в конфіг, а змінні `E2E_URL` і `E2E_CHROME` уже задають решту оточення сценарію.
