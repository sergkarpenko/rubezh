# 0034. Гейт покриття на PR — codecov/patch як required status check

- Статус: proposed
- Дата: 2026-10-14
- Supersedes: (частково доповнює ADR-0017/0025/0028)

## Контекст

ADR-0017 встановив поріг 80% покриття ядра локально (`npm run test:coverage` у ci.yml), а Codecov (ADR-0009/0020) рахує `codecov/patch` на кожен PR. Але ціль patch-покриття — автоматична (auto-target Codecov: середнє останніх комітів, на момент П7.5 — 99.29%), і `codecov/patch` не є required status check (ADR-0025: обов'язковий лише `test`). Наслідок (PR #48, П7.5): patch 95.23% не заблокував мердж — прогалину у `src/core/save.ts` (гілки П7.4) помітили лише вручну, після звернення власника з бейджем Codecov. AI-агент (ADR-0023) бачить чеки лише в межах сесії — «вухо» 24/7 має бути механізмом репозиторія, а не агентом. Плаваюча auto-target ціль непередбачувана: дрібний фікс UI може провалити 99%+ планку, а точна цифра невідома до завершення CI.

## Рішення

Ми фіксуємо поріг patch-покриття у конфігурації Codecov у репозиторії та піднімаємо його до механічного рубіжу мерджа:

1. **`codecov.yml` у корені репо**: `coverage.status.patch.default.target: 95%`, `threshold: 0%`, `only_pull_requests: true` (гуарди ci.yml/preview.yml не змінюємо — ADR-0018).
2. **`codecov/patch` — required status check** у branch protection main (доповнює ADR-0025: `test` + `codecov/patch`).

Власник ухвалив поріг 95% (сесія 2026-10-14, «Схвалюю, 95%»): стримує лише суттєві прогалини, не ламає дрібні фікси шару відображення (main.ts/render.ts мають нижче глобальне покриття, але ядру 80%+ гарантує ci.yml — ADR-0017). Поріг у конфізі детермінований і видаваний у репо, а не «плаває» в auto-target Codecov.

## Наслідки

PR із patch-покриттям < 95% фізично не змерджиться — гейт працює 24/7 без участі агента чи власника; AI-агент при наступній сесії бачить червоний чек у PR, читає звіт Codecov і фіксить покриття до зеленого (цикл з workflow.md п.5: «червоний CI = стоп»). Ціна: PR з великим дифом ядра вимагає майже повного покриття нових рядків (95% з ~0 допуску); зміна порогу — правка `codecov.yml` + цей ADR (новий ADR з Supersedes). Додавання required check — дія власника в Settings → Branches (поза кодом, як і ADR-0025).
