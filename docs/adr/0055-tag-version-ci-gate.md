# 0055. CI-гейт звірки реліз-тега ↔ version у package.json

- Статус: accepted (подано разом з планом Фази 10; мерж PR власником = «схвалюю» — конвенція ADR-0023/0030/0052)
- Дата: 2026-10-16
- Доповнює: ADR-0054 (п.6 — гейт був відкладеним кандидатом), ADR-0018 (workflow-файли — лише з ADR у точці коміту), ADR-0034 (урок П7.5: гейт живе в механізмі репо, а не в увазі агента)
- Автор: Vibe Work (рішення включити у Фазу 10 — власник, сесія планування П10.1 2026-10-16)

## Контекст

ADR-0054 затвердив semver із сейв-контрактом і реліз-крок «Реліз vN.N.N»: агент піднімає version у package.json у реліз-PR, тег ставиться на merge-коміт після валідації власника. П.6 ADR-0054 відкладав гейт звірки «тег ↔ version» як кандидат на майбутнє Покращення за окремим рішенням власника (прецедент Т.1: спершу чесна методика, потім автоматизація гейту). Методика пережила перший реліз (v0.1.0, 2026-10-16); власник ухвалив включити гейт у Фазу 10 (сесія планування 2026-10-16). Ризик без гейту: помилкове якорення тегу (урок П8.5) або забутий bump порушують контракт «версія на екрані = реліз», і це видно лише людській увазі.

## Рішення

Workflow `.github/workflows/tag-version.yml` (чек `tag-version`), тригер — пуш тегів `v*`:

- чекаут тегованого коміту;
- читання `version` з package.json тегованого коміту;
- порівняння з іменем тегу (vX.Y.Z ↔ X.Y.Z); розбіжність → червоний ран з українським повідомленням у лог.

Реалізація без нових залежностей (ADR-0012) — стандартні інструменти образу раннера. Гейт не блокує Pages-deploy (релізний тег ставиться після валідації власника, сторінка вже задеплоєна): його мета — консистентність контракту ADR-0054 і швидке виявлення помилкового тегу чи забутого bump.

## Наслідки

- Тег vN.N.N гарантовано відповідає version у package.json тегованого коміту; помилкове якорення тегу або забутий bump видно одразу червоним раном.
- Один новий workflow-файл; супровід — як у інших чеків (Dependabot-бампи actions — за ADR-0024).
- Зміна методики — лише через новий ADR із полем Supersedes.

## Альтернативи

- Ручна звірка у реліз-сесії — відкинуто: увага агента скінчена, CI — ні (урок П7.5).
- Гейт на merge у main — відкинуто: main не несе релізного тегу до валідації власника; перевірка мала б бути або завжди зеленою (до реліз-PR version не змінюється), або блокувати docs-PR.
- release-please-стайл автоматизація (CI сам ставить теги і публікує Release) — відкинуто в ADR-0054: суперечить валідації власником.
