# 0105. `vibe-audit`: стабільний формат відповіді — повтор «лише блок JSON» у тій самій сесії

- Статус: accepted (мерж PR власником = «схвалюю» — конвенція ADR-0018/0052)
- Дата: 2026-11-20
- Доповнює: ADR-0102 (аудит через Vibe CLI, п. 4 — формат знахідок і коментар «Аудиту не було»), ADR-0104 (`vibe-audit` — єдиний аудитор Mistral), ADR-0018 (workflow без змін)
- Автор: Claude Code (рішення власника 20.11.2026 на фініші Т.87, кнопкою «87: формат vibe-audit (Recommended)»; задача Т.88, кандидати 87 і 95)

## Контекст

`scripts/audit-vibe-cli.mjs` читає знахідки з останнього блоку ```` ```json ```` у відповіді Vibe. Модель іноді закінчує відповідь без нього (другий прогін на `866668f` PR #397, спостереження сесії після мержу Т.82): тоді коментар — «Аудиту не було», хоча прогін ≈ 12 хв уже витратив ліміт плану Vibe і модель усе перевірила.

Кандидат 87 називав два способи: `--output json` або повтор одним ходом через `--continue` / `--resume`. Перевірка на Vibe 3.1.3 локально (Т.88; підставний сервер моделі, сумісний з OpenAI, у `config.toml` провайдер з `api_base` на `127.0.0.1`):

- `--output json` друкує перелік повідомлень сесії (`role`, `content[].text`, `turnId` …) — це обгортка виводу, а не формат відповіді моделі: текст останнього повідомлення той самий, що в `--output text`, і блоку JSON у ньому так само може не бути.
- `export.json` (`--output-dir`) має `session_id`. `vibe --resume <session_id> --prompt-file … --output text` у headless-режимі продовжує ту саму сесію: у запит до моделі йдуть системний промпт, перше повідомлення, попередня відповідь і нове повідомлення; stdout — лише нова відповідь; код 0. Невідомий `session_id` — код 1, `export.json` з `outcome: usage_error`.
- `--model` і `--thinking` діють лише на нові сесії (довідка `vibe --help`): сесія з `--resume` лишається на своїй моделі.
- `--continue` обирає «останню сесію цього термінала в цій теці» — неявно; `--resume <id>` називає сесію явно.

## Рішення

1. **Повтор у тій самій сесії:** якщо у відповіді Vibe немає блоку JSON зі знахідками (код 0) або Vibe зупинився на ліміті (код 3), а в `export.json` є `session_id`, скрипт один раз запускає `vibe --resume <session_id>` з промптом «поверни лише блок JSON у форматі з першого повідомлення, без нових перевірок і інструментів» (`retryPrompt()`).
2. **Межі повтору — `RETRY`:** 2 ходи, $0,5, 300 с (другий хід — на випадок, якщо модель ще раз викличе інструмент); запис файлів вимкнено, як і в першому прогоні (`--disabled-tools write_file`, `edit` з `--auto-approve`). `--model` і `--thinking` не передаються.
3. **Вихідні файли повтору — `VIBE_OUTPUT_DIR/retry/`** (export.json першого прогону не перезаписується), промпт — `VIBE_OUTPUT_DIR/retry.md`.
4. **Коментар:** знахідки з повтору звіряються з цитатами так само (ADR-0102 п. 4); під ними — рядок «Блок JSON — з повтору …», у рядку прогону — обидва прогони. Повтор без JSON або з кодом, відмінним від 0 і 3, — «Аудиту не було» з причиною першого прогону і «повтор … теж без нього». Без `session_id` повтору немає — як раніше.
5. **`--output` лишається `text`:** `--output json` формату відповіді моделі не стабілізує (див. «Контекст»).
6. **Ручний `probe` без `VIBE_OUTPUT_DIR` (кандидат 95):** не падає — друкує результат, `probe.txt` пише лише коли змінну задано.
7. Workflow `.github/workflows/vibe-audit.yml` без змін.

## Наслідки

- Прогін без блоку JSON більше не марний: модель не повторює роботу, а лише форматує вже перевірене (у сесії — вся попередня розмова, тож повтор коштує вводу всієї сесії; кеш Vibe його здешевлює).
- Максимальна ціна пушу зростає на $0,5, а тривалість — на 5 хв (ліміт джоби — 45 хв, перший прогін — до 25 хв + 2 хв запасу).
- Самоперевірка скрипта — з перевірками повтору (аргументи, межі, тека, коди 1 і 3, без `session_id`) і ручного `probe`.
- Перший прогін наживо — на PR цього кроку (якщо модель дасть JSON з першого разу, повтор у CI не перевіриться — тоді він перевірений лише локально на справжньому Vibe 3.1.3 з підставною моделлю).

## Альтернативи

- **`--output json`** — відхилено: див. «Контекст», п. 5.
- **`--continue`** — відхилено: неявний вибір сесії; `--resume <id>` з `export.json` називає її явно.
- **Новий прогін з нуля** — відхилено: повторює ≈ 12 хв роботи і ціну.
- **Розбирати відповідь без блоку (пошук знахідок у прозі)** — відхилено: знахідка без поля `quote` не звіряється з файлами (ADR-0102 п. 4).
