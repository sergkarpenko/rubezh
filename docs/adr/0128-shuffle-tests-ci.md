# 0128. Тести в перемішаному порядку — окрема джоба `shuffle` у CI

- Статус: accepted (мерж PR власником = «схвалюю» — конвенція ADR-0052)
- Дата: 2026-11-24
- Доповнює: ADR-0076 (гейти в джобі `test`), ADR-0082 (обов'язкові чеки `main`), ADR-0113 (`bash` з `pipefail`), ADR-0018 (зміна workflow — з ADR)
- Автор: Claude Code (Т.151; крок — кандидат процесу 106, вибір власника кнопкою на фініші Т.150; технічний спосіб обрала сесія)

## Контекст

- `npm test` (vitest) іде у фіксованому порядку. Тест, що лишає по собі стан (стаб глобального об'єкта, фейк-таймери, присвоєння прототипу), у такому порядку непомітний: у Т.149 `vi.unstubAllGlobals()` у блоці Т.143 знімав стаб rAF П6.16, і під `--sequence.shuffle` наступні блоки `src/main.ui.test.ts` падали (сіди 1, 2, 42, 1234 і на `main`).
- Т.149–Т.150 виправили знайдене; після Т.150 увесь `npm test` зелений під `--sequence.shuffle` на 34 сідах (повний прогін ≈ 50 с). Без гейта нова залежність від порядку знову лишиться непомітною до випадкового прогону.

## Рішення

1. У workflow `ci` — нова джоба `shuffle` (`.github/workflows/ci.yml`): `npm ci`, далі `npx vitest run --sequence.shuffle --sequence.seed=<сід>` — ті самі файли й налаштування, що `npm test`, лише порядок інший. Перемішуються і файли, і тести всередині файлів.
2. Сід — `github.run_id % 1000000`: кожен новий пуш у PR дає новий порядок (з часом покриває багато сідів), а «Re-run» тієї самої джоби — той самий порядок. Крок друкує сід і команду відтворення в журнал і в підсумок прогону (`GITHUB_STEP_SUMMARY`).
3. Чек `shuffle` — не обов'язковий для `main`: червоний не блокує мерж, але видно в PR. Червоний `shuffle` за зеленого `test` означає залежність від порядку — виправити в тому ж PR або записати кандидатом; мерж PR класу `auto` за червоного `shuffle` — лише з поясненням в описі PR.
4. Обов'язкові чеки `main` і джоби `test` та `e2e` — без змін; нової залежності немає.

## Відхилені варіанти

- **Крок у джобі `test`** (без нового `npm ci`): `test` — обов'язковий чек, тож рідкісне падіння на невідомому сіді блокувало б мерж і змінювало б зміст обов'язкового чека — рішення про обов'язкові чеки ухвалює власник (поруч — кандидат 27). Окрема джоба коштує ≈ 30 с `npm ci` на раннері і запускається паралельно, тож не подовжує очікування.
- **Фіксований сід:** перевіряє один і той самий порядок — після першого зеленого прогону нових залежностей майже не ловить.
- **Випадковий сід vitest без друку** (`--sequence.shuffle` без `--sequence.seed`): падіння не відтворюється ні «Re-run», ні локально.
- **Кілька сідів за прогін** (матриця): ×N хвилин раннера на кожен пуш; новий сід на кожному пуші дає те саме покриття з часом.
- **Обов'язковий чек одразу:** лише рішенням власника, коли джоба покаже стабільність (кандидат на наступні кроки).

## Наслідки

- Перевірка кроку: `npm test` у перемішаному порядку локально на сіді, що дає формула для типового номера прогону, — зелений; джоба `shuffle` зелена на PR кроку (сід — у підсумку прогону).
- Червоний `shuffle` відтворюється локально командою з журналу джоби (`docs/agents/common.md`, пункт «Тести сторінки»).
- Зміна обов'язковості чека — новий ADR.
