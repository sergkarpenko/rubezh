# 0094. PR, що не чіпає гру, агент мержить без «схвалюю» — після зелених чеків і аудиту

- Статус: accepted (мерж PR власником = «схвалюю» — конвенція ADR-0018/0052)
- Дата: 2026-11-14
- Частково Supersedes: ADR-0052 п. 2 («без явного апруву мерж заборонений») і ADR-0057 (перелік PR, що завжди потребують апруву: тести, звіти й записи кроків у PR класу `auto` більше не потребують) — для PR класу `auto`; для решти PR обидва чинні
- Доповнює: ADR-0018 (зміна workflow-файлу — з ADR); ADR-0077 (workflow `pr-size`); ADR-0093 (тег кроку після мержу)
- Автор: Claude Code (рішення власника 2026-11-14: «власник — вузьке місце», кандидат 22 «PR без „схвалюю“»; відповіді власника кнопками в сесії Т.35; задача Т.35)

## Контекст

ADR-0052 вимагає явного «схвалюю» власника на кожен змістовний PR. За журналом кроків Т.15–Т.33 очікування цієї відповіді тривало від 3 хвилин до 9 годин; пауза понад годину ще й здорожчує сесію (перезапис кешу). Водночас частина кроків гру не змінює: звіти аналізу симуляцій (Т.20, Т.23, Т.25, Т.27), огляд UX (Т.30), скрипт симуляцій (Т.21), тести на прогалини (Т.11, Т.12, Т.14). У таких PR власник схвалював результат, який уже перевірили чеки, і жодного разу не відхилив.

З Т.34 кожен PR кроку до мержу читає аудитор — окрема модель без контексту сесії (експеримент Т.34–Т.36). Це друга незалежна перевірка поруч із чеками, і на неї може спертися мерж без власника.

Рішення власника (2026-11-14, сесія Т.35):

- «не гра» — `docs/`, `scripts/` і тести; `.github/` до переліку не входить;
- «аудит без знахідок» — немає невиправлених: підтверджені знахідки виправлено другим комітом, відхилені перелічено з причиною в описі PR.

## Рішення

1. **Два класи PR.** Клас `auto` — PR, у якому кожен змінений файл належить до «не гри» (п. 2). Клас `approve` — решта. Клас визначає `scripts/pr-class.sh <base> <head>`; останній рядок його виводу — `КЛАС: auto` або `КЛАС: approve`.
2. **«Не гра»:**
   - `docs/**`, крім `docs/adr/**` (рішення), `docs/prototypes/**` (архів, зміна заборонена) і `docs/workflow.md` вище розділу «Поточний статус проєкту» (принципи, цикл зміни, теги, уроки, рішення — правила процесу); записи кроків нижче цього розділу — «не гра»;
   - `src/**/*.test.ts` і `e2e/**` — додані або змінені файли; видалений або перейменований файл тестів — `approve`;
   - `scripts/**`, крім скриптів CI і хуків: сам `scripts/pr-class.sh`, `scripts/pre-commit.sh` і кожен скрипт, чиє ім'я згадано в `.github/`, `.husky/`, `package.json` або `scripts/pre-commit.sh` — у базі чи в гілці PR;
   - файл тестів (`*.test.*`, `*.spec.*`) у `docs/` чи `scripts/` — `approve`: vitest запускає його разом з рештою.
   Усе інше — `approve`: код гри (`src/` без тестів, `index.html`, ассети), `AGENTS.md`, `README.md`, ADR, `.github/`, `package.json`, конфігурація. Порожній диф, не звичайний файл (символьне посилання, підмодуль) і помилка git під час пошуку згадок — `approve`.
3. **PR класу `auto` агент мержить сам, без «схвалюю»,** коли виконано все:
   - клас `auto` показала версія скрипта зі свіжого `main` (після `git fetch`; не з гілки PR) на останньому коміті PR;
   - обов'язкові чеки `main` зелені на останньому коміті (`test`, `e2e`, `pr-size`, `codecov/patch`);
   - PR пройшов аудит (п. 4), і невиправлених знахідок немає;
   - у PR немає нового правила гри, тексту UI чи рішення, яке за правилами ухвалює власник.
4. **Аудит.** Читач без контексту сесії, за змоги інша модель; отримує диф PR, звіт кроку, `AGENTS.md` і `docs/workflow.md`; нічого не змінює. Кожну знахідку сесія перевіряє. Підтверджені виправляє наступним комітом у той самий PR; відхилені перелічує в описі PR з причиною. Опис PR класу `auto` містить розділ «Аудит»: хто аудитор, скільки знахідок, скільки підтверджено, що виправлено, що відхилено і чому. Якщо виправлення змінило клас PR на `approve` — потрібне «схвалюю».
5. **Сумнів = `approve`** (як в ADR-0057). Без аудиту мержу без «схвалюю» немає: якщо експеримент з аудитом власник не продовжить, клас `auto` перестає діяти до нового рішення.
6. **Чек.** Workflow `pr-size` отримує два кроки: самоперевірка `scripts/pr-class.sh --self-test` і «Клас PR» (`--ci`) — клас у журналі й підсумку прогону. Крок «Клас PR» запускає версію скрипта з бази PR, якщо вона там є. Клас `approve` чек не валить: це довідка, а не гейт. Червона самоперевірка або помилка скрипта валить чек `pr-size` — обов'язковий чек `main` — будь-якому PR, як і помилка `scripts/pr-size.sh`.
7. **Після мержу** агент повідомляє власника в чаті: номер PR, клас, підсумок аудиту. Власник може відкликати зміну звичайним шляхом — новим PR.
8. **Тег кроку** (ADR-0093) для PR класу `auto` ставиться так само, за рядком `Iter-Tag:`. Валідацією людини для такого тегу є це рішення власника, а не окреме «схвалюю».
9. PR класу `approve` — без змін: мерж лише після «схвалюю» (ADR-0052). Механічні PR за ADR-0057 — без змін.

## Наслідки

- За історією `main` (60 останніх мержів, Т.6–Т.34) клас `auto` отримали б 7 з 22 змістовних PR кроків Т.15–Т.34: PR #294, Т.20, Т.21, Т.23, Т.25, Т.27, Т.30 (`docs/reports/t35-pr-class.md`). PR з тестами Т.11, Т.12, Т.14, Т.15b — `approve`, бо дописували урок у розділ «Уроки» `docs/workflow.md`; урок у записі кроку класу не міняє. На цих кроках у власника лишаються тільки відповіді на питання до реалізації.
- Власник дізнається про мерж після нього. Те, що раніше ловило «схвалюю», тепер мають ловити чеки й аудитор; частка підтверджених знахідок аудиту — у журналі кроків.
- Скрипт бачить шляхи, а не зміст, і стереже від помилки, а не від зловмисності: сесія й так має право мержу. Тести і скрипти — це код, який виконує CI, зокрема `npm test` перед збіркою і деплоєм у workflow `preview`; тест, що пише у файли гри, або послаблений тест скрипт не відрізнить. Це завдання аудитора: чи не послаблено тест і чи не пише код «не гри» поза тимчасову теку.
- Крок «Клас PR» у CI — довідка: PR, що змінює сам workflow, може її спотворити, але такий PR має клас `approve` за версією скрипта з `main`, яку сесія запускає перед мержем.
- Сам цей PR — клас `approve` (ADR, `AGENTS.md`, workflow, скрипт CI): мержиться після «схвалюю».

## Альтернативи

- **Статус-кво** — відкинуто власником: очікування «схвалюю» на кроках без зміни гри нічого не додає до чеків і аудиту.
- **«Не гра» = усе поза `src/`** (перша редакція кандидата 22) — відкинуто: `.github/`, `package.json` і скрипти CI визначають самі чеки, на які спирається мерж без власника; `AGENTS.md` і ADR — правила.
- **`.github/` у «не грі»** — не обрано власником (питання кнопками, 2026-11-14).
- **Аудит без жодної знахідки** як умова — не обрано власником: у Т.34 аудит дав десять знахідок, і всі виправлено за один коміт; така умова майже завжди повертала б «схвалюю».
- **GitHub auto-merge або джоба, що мержить сама** — відкинуто: мерж лишається дією сесії після аудиту, якого CI не бачить; до того ж це зайве право workflow на запис (те саме заперечення, що в ADR-0057).
- **Клас як обов'язковий чек, що блокує мерж** — відкинуто: клас `approve` — нормальний стан більшості PR, а не помилка.
