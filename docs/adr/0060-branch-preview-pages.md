# 0060. Прев'ю гілок на Pages до мержу

- Статус: accepted (подано разом з реалізацією П11.5 у одному коміті — ADR-0018; мерж PR власником = «схвалюю» — конвенція ADR-0023/0030/0052)
- Дата: 2026-10-17
- Доповнює: ADR-0009 (онлайн-прев'ю: GitHub Pages + Actions — основна схема деплою не змінюється), ADR-0018 (workflow-файли — лише з ADR у точці коміту), ADR-0028 (доставка гілка + PR), ADR-0052 (мерж за явним апрувом), ADR-0056 (автовидалення головних гілок PR)
- Автор: Vibe Work (рішення власника — план Фази 11, крок П11.5; хвіст П9.1)

## Контекст

Візуальні кроки (арт, UI) після мержу видно лише на основному деплої main — валідувати власником доводиться постфактум (П6.2, П10.6). Для П11.6 (UI «Дослідження і цех») план вимагає візуальну валідацію до мержу: потрібна сторінка гілки за відомим URL. Pages-деплой у ADR-0009 — сайт з одного артефакта (`actions/deploy-pages` замінює весь сайт), часткового деплою в підкаталог механізм не дає. `vite.config.ts` механічно заборонений (AGENTS.md): base гілки задається прапорцем CLI `vite build --base=...`, не конфігом.

## Рішення

Workflow `.github/workflows/preview-branch.yml` (ім'я — `preview-branch`), тригер — лише `workflow_dispatch` з обов'язковим входом `branch`:

- два чекаути: `origin/main` (корінь артефакта) і гілки прев'ю;
- корінь — той самий ланцюжок, що й `preview.yml` (`npm install` → `vite build` → TypeDoc), тож живий корінь і `/api/` байт-у-байт не відрізняються від деплою main (білд детермінований: імена ресурсів — контентні хеші Vite);
- гілка — `vite build --base=/rubezh/preview/<slug>/` (CLI-прапорець поверх `/rubezh/` з vite.config.ts; slug = ім'я гілки з `/` → `-`); тести/покриття/Codec у прев'ю не запускаються — лише білд;
- артефакт «корінь (main) + `/preview/<slug>/`» деплоється тим самим механізмом (`upload-pages-artifact` + `deploy-pages`), URL — у notice-рані, summary рану та environment-url джоба деплою: `https://sergkarpenko.github.io/rubezh/preview/<slug>/`;
- `branch = main` — червоний ран (прев'ю main не має сенсу);
- concurrency — той самий рубіж `pages`, `cancel-in-progress: false`: прев'ю чекає завершення деплою main; якщо паралельно прийшов пуш у main, деплой main (cancel-in-progress: true у preview.yml) скасовує запущене прев'ю — пріоритет за основним сайтом, прев'ю перезапускається вручну.

Чистка: артефакт щоразу збирається заново з «свіжий main + лише обрана гілка», тож повторне прев'ю тієї ж гілки заміщує старе, прев'ю інших гілок зникають; перший же пуш у main (preview.yml деплоїть тільки main) повертає сайт до стану без прев'ю. Теги/реліз-гейти (ADR-0055) не зачіпаються: прев'ю не чіпає теги, артефакт прев'ю не потрапляє в main.

## Наслідки

- Власник бачить гілку за URL до мержу — візуальні критерії (П11.6) валідуються на прев'ю; мерж — за явним апрувом (ADR-0052), гарбідж-гілки після мержу видаляються (ADR-0056).
- Прев'ю недовговічне: живе до наступного деплою main або наступного прев'ю іншої гілки — це кадрова перевірка, не архів.
- Один новий workflow-файл; без нових залежностей (ADR-0012) і без змін preview.yml/ci.yml; білди в прев'ю дублюють інсталяцію main (близько двох `npm install`) — прийнятна ціна за ізоляцію від основного деплою.
- Зміна методики — лише через новий ADR із полем Supersedes.

## Альтернативи

- Прев'ю в Pull Requests-коментарях (Netlify/Vercel) — відкинуто: нова залежність і зовнішній сервіс (ADR-0012, ADR-0009).
- Pages з гілки (deploy from branch) — відкинуто: міняє схему ADR-0009 (Source: GitHub Actions) і ламає основний деплой.
- Деплой лише підкаталогу `/preview/<гілка>/` без кореня — відкинуто: `deploy-pages` не вміє часткового деплою, артефакт без кореня прибрав би живий сайт.
