# 0016. Генерація документації коду — TypeDoc

- Статус: accepted
- Дата: 2026-10-13

**Контекст.** Крок П11 плану Фази 2: документація API ядра. Код `src/core/` вже несе українські doc-коментарі з посиланнями на ADR (вимога AGENTS.md), але вони видно лише в редакторі — згенерованої довідки по публічному API (типи, функції бойового ядра, геосцени, місії, ростеру) немає. Альтернативи: JSDoc (без HTML-виводу, не читається без редактора); ESDoc (закинутий, ESM-підтримка слабка); DocFX (стек .NET, сторонній); власні скрипти-генератори (дублювання роботи). Залежність додано за процесом ADR-0012 (авторизація власника: вказівка «роби п11» у сесії 2026-10-13).

**Рішення.** Ми використовуємо TypeDoc: dev-залежність `typedoc`, конфіг `typedoc.json` (entryPoints: `src/core` з `entryPointStrategy: expand`, плюс `src/main.ts` і `src/bot.ts`; вивід — `dist/api/`). Вивід усвідомлено в `dist/`: каталог уже в `.gitignore` (без нових винятків у забороненому файлі), документація — генерований артефакт і в git не потрапляє; побічний ефект — `vite build` очищає `dist/`, документація перегенерується командою `npm run docs`. Скрипт у package.json: `"docs": "typedoc"`. CI-кроку генерації немає (`.github/workflows/` змінювати заборонено) — документація генерується локально за потреби; публікація API-довідки на Pages — кандидат у Фазу 3 окремим рішенням.

**Наслідки.** Публічне API ядра має переглядану HTML-довідку з українських коментарів; розбіжність «коментар у коді» ↔ «документація» зникає, бо джерело одне. Вплив на вагу бандлу: нуль — dev-only, у збиранку Vite не потрапляє. Ціна: один новий dev-пакет; документація не комітиться (перегенерація за потреби, ~2-3 с); TypeDoc рендерить лише TSDoc-коментарі — старі `//`-коментарі в тілах у довідку не потрапляють (прийнятно: вони для читання коду). Зміна рішення — новий ADR із полем Supersedes.
