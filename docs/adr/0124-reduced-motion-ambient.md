# 0124. Системне «менше руху» вимикає JS-цикл ambient бою і геосцени

- Статус: accepted (мерж PR власником = «схвалюю» — конвенція ADR-0052)
- Дата: 2026-11-23
- Доповнює: ADR-0073 п. 2–3 (гейти ambient-циклу, тумблер «Анімація»), ADR-0121 п. 7 (дихання бійців), ADR-0116 (анімація стартового екрана — CSS, «менше руху»), ADR-0115 (переходи кнопок, «менше руху»), ADR-0029 (idle → 0 перерисовок)
- Автор: Claude Code (Т.143; рішення власника кнопкою — дослівно в записі Т.143 у `docs/workflow.md`)

## Контекст

- Системне налаштування «менше руху» (`prefers-reduced-motion: reduce`) на `main` гасить лише CSS: анімацію стартового екрана (ADR-0116) і переходи кнопок (ADR-0115). JS-цикл ambient-шару (`src/ui/ambient.ts`: пульс кантів стін, підсвічування поранених, дихання бійців, розгортка радара геосцени) за увімкненого тумблера «Анімація» працює далі — гравець, який попросив систему про менше руху, бачить постійний рух на полі бою (знайшов аудит PR #450, Т.137; звірено з кодом на старті Т.143).
- Рішення власника (Т.143, кнопкою): обсяг «А. Усе три» — разом із гейтами e2e поля бою «менше руху» вимикає JS-ambient, як вимкнена «Анімація».

## Рішення

1. **Гейт «менше руху»** — у рушії ambient-шару: залежність `reducedMotion()` у `AmbientDeps` (немає — «менше руху» не ввімкнено). Ефекти грають, лише коли тумблер увімкнено і «менше руху» не ввімкнено: кадр циклу, `start`, `paintBattle`, `paintGeo` і `breath` перевіряють обидві умови — 0 кадрів і 0 ефектів, як із вимкненим тумблером (ADR-0029).
2. **Тумблер не змінюється:** стан «Анімація», його підпис у «Налаштуваннях» і ключ `rubezh.settings.ambient` лишаються як були — «менше руху» лише гейт поверх них; зняли «менше руху» — цикл знову грає, якщо тумблер увімкнено.
3. **Зміна без перезавантаження:** `src/main.ts` слухає медіазапит `(prefers-reduced-motion: reduce)` (подія `change`): метод `Ambient.motionChanged()` зупиняє або поновлює цикл (ті самі гейти, що й старт), відкритий бій чи геосцена перемальовуються одразу — без ефектів ambient. Без `matchMedia` (jsdom) — гейт вимкнено.
4. **Поза рішенням:** подієві анімації (рух, постріл з віддачею, спалахом і іскрами, розчинення загиблого, скан-радар тіку) — не ambient-цикл, лишаються як є; їх «менше руху» не торкається (кандидат на наступні кроки).
5. **Гейти:** тести модуля — «менше руху» з початку (0 кадрів, 0 операцій канви, дихання 0, тумблер і сховище не змінено), увімкнулось посеред гри (кадр зупиняє планування, `motionChanged` знімає кадр одразу), вимкнулось (`motionChanged` поновлює, з вимкненим тумблером — ні); тест сторінки — подія `change` медіазапиту перемальовує канву бою один раз; e2e — у спокої бою з `emulateMedia({ reducedMotion: 'reduce' })` за 400 мс жодного `requestAnimationFrame`, знято — цикл знову планує кадри (поломка: гейт у `src/main.ts` вимкнено — червоний «“менше руху” — 0 кадрів ambient»).

## Наслідки

- Гравець із системним «менше руху» бачить поле бою і геосцену без постійного руху за будь-якого стану тумблера «Анімація».
- Підпис тумблера «Анімація: увімк» за ввімкненого «менше руху» не каже, що ефекти погашено системою, — текст UI обирає власник (кандидат).
- Новий постійний ambient-ефект (ADR-0073 п. 5) автоматично під тим самим гейтом.
