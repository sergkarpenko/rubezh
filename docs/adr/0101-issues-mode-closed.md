# 0101. Режим Issues закрито: Mistral — лише аудитор PR

- Статус: accepted (мерж PR власником = «схвалюю» — конвенція ADR-0018/0052)
- Дата: 2026-11-20
- Частково Supersedes: ADR-0100 п. 4 (режим Issues) і п. 5 (контрольні точки — виконано, КТ-2 не пройдено); п. 1–3 ADR-0100 (згортання схеми «Vibe — виконавець за планом Claude», заморожені шаблон і скрипти) чинні
- Доповнює: ADR-0097 (два аудитори PR), ADR-0096 (довідники агентів), ADR-0018 (зміна `.github/` — з ADR у точці коміту)
- Автор: Claude Code (рішення власника 20.11.2026 у Т.80 і на старті Т.81; задача Т.81)

## Контекст

ADR-0100 відкрив режим Issues як експеримент: вузька задача поза грою — GitHub issue з міткою `vibe` за шаблоном `.github/ISSUE_TEMPLATE/vibe.md`, Mistral Vibe Code бере її сам, сесія Claude приймає PR пачкою з одним колом виправлень. Контрольні точки (п. 5): КТ-1 — після першої пачки, КТ-2 — після другої; КТ не пройдено → режим закривається рядком нового ADR, Mistral лишається лише аудитором у CI.

- **Пачка 1** (issue #377–#379, PR #381–#383): змержено 3 з 3, КТ-1 пройдено.
- **Пачка 2** (issue #385–#387, PR #389–#391): змержено 2 з 3 (#391, #390); #389 закрито — коло виправлень перейменувало наявний тест, задачу повернуто в кандидати. Приймання пачки ≈ 1,57 млн + субагент ≈ 107 тис. Увесь експеримент ≈ 5,7 млн при стелі ≈ 5 (документ стану сесії).
- Рішення власника (20.11.2026, Т.80, кнопкою, дослівно): «Не пройдено: Mistral — лише аудитор».
- Рішення власника (20.11.2026, старт Т.81, кнопкою, дослівно) про шаблон issue і мітку: «Прибрати»; про аудитора Mistral після відповідей API 402 на PR #394: «Так, поправлю план».

## Рішення

1. **Режим Issues закрито.** Нових issue для агентів (мітка `vibe`) немає; Mistral Vibe Code задач у репозиторії не бере. Код кроків гри і тести пише сесія, яка веде крок (ADR-0100 п. 1).
2. **Mistral лишається лише аудитором PR** — джоба `mistral-audit` (ADR-0095, ADR-0097, ADR-0098, ADR-0099) без змін: два аудитори на кожному PR кроку. Збій API (зокрема 402 — оплата) — як і раніше, зелений чек і коментар «Аудиту не було»; власник поправляє план Mistral, аудитор не вимикається.
3. **Шаблон issue прибрано:** файл `.github/ISSUE_TEMPLATE/vibe.md` видалено цим PR (зміна `.github/` з ADR у точці коміту — ADR-0018); текст лишається в історії: `git show iter-T.80:.github/ISSUE_TEMPLATE/vibe.md`. Мітку `vibe` на GitHub видаляє сесія після мержу; закриті issue #377–#379 і #385–#387 мітку втрачають, номери й обговорення лишаються.
4. **Довідник `docs/agents/common.md`:** розділи «Задача з issue», «Запуск Mistral Vibe Code Web на issue» і «Лише для Mistral Vibe Code» згорнуто до посилання на цей ADR; повний текст — `git fetch --depth=1 origin tag iter-T.80 && git show iter-T.80:docs/agents/common.md`.
5. **`AGENTS.md`:** у ролі Vibe Code доручення брати issue з міткою `vibe` замінено рядком про закриття режиму (знахідка 9 аудитора Т.80); рядок цього ADR — у таблиці ADR.
6. Заморожені шаблон плану `docs/plans/TEMPLATE-vibe.md`, плани `t39`–`t73` і скрипти `scripts/vibe-*` (ADR-0100 п. 2) — без змін, матеріал для занять. Кандидат «режим Issues, спосіб 2» (Action → Vibe CLI) знято разом із режимом.
7. Workflow-файли, скрипти CI і `package.json` цим ADR не змінюються.

## Наслідки

- Робота Mistral у проєкті — один зовнішній аудит на пуш у PR; окремих кроків «для Vibe» немає.
- Задачі поза грою, які були б issue (тести пастки фокусу з #389), — звичайні кандидати на кроки сесії Claude.
- Повернення Mistral до написання коду — лише новим ADR з іншим способом (наприклад, Mistral Studio — кандидат 80), не відновленням цього режиму.

## Альтернативи

- **Заморозити шаблон і мітку як матеріал для занять** — відхилено власником («Прибрати»): заморожений шаблон у `.github/ISSUE_TEMPLATE/` GitHub і далі пропонує під час створення issue; для занять текст доступний з тегу.
- **Вимкнути аудитора Mistral через 402** — відхилено власником («Так, поправлю план»).
- **Третя пачка під КТ-2 з уточненим шаблоном** — не розглядалась: ADR-0100 п. 5 прямо закриває режим за непройденої КТ.
