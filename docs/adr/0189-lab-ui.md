# 0189. UI лабораторії: найм за спеціалізацією, «Модулі бази», «Казан алхіміка», «Еліксир чемпіона», плитка «Стимул», «Як грати» з вкладками (п22.7)

- Статус: accepted (мерж PR власником = «схвалюю» — конвенція ADR-0052)
- Дата: 2026-11-28
- Доповнює: ADR-0182 (п. 13, 16; EARS 4–5), ADR-0187 (техноманти, модулі, казан, витратники), ADR-0188 (трофей `champion`), ADR-0168 (вікно спорядження), ADR-0119 (смуга загону), ADR-0066 (тулбар), ADR-0157 (панель «Мета кампанії», «Як грати»), ADR-0135
- Автор: Claude Code (п22.7, Т.234; рішення власника 28.11.2026 кнопками — чотири питання одним колом)

## Контекст

ADR-0182 п. 16: штат техномантів (спеціалізація, рівень, ефект), панель модулів, казан алхіміка з рецептами, витратники у вікні спорядження і смузі загону, «Як грати» — рядки дерева, розміру загону, техномантів, виводків і чемпіонів. ADR-0182 п. 13: рідкісний трофей чемпіона — «для сильнішого витратника».

Факти коду на `main` `0f36305` (п22.6):

- Ядро п22.5 без UI: `hireScientist(…, spec)`, `scientistLevel`, `scientistPoints`, `bestLevel`; `MODULES`, `modulePrice`, `buyModule` (`src/core/base.ts`, «Стенд» — лише після протоколу «Розширення лабораторії»); `brewItem`, `canBrew`, черга `workshop.brew`, рецепти `stim` / `shield`; `useStim`, `stimBlock` — у бою кнопки немає.
- У панелі «Дослідження» — одна кнопка «Вербувати техноманта (100)» (наймає дослідника), рядок штату — бюст, ім'я, «Звільнити».
- Трофей `champion` (ADR-0188 п. 8) — необов'язкове поле `TrophyStore`; `missingTrophies` / `spendTrophies` ітерують лише `ENEMY_ORDER`.
- «Як грати» — 731 px на 1366 × 768 (гейт e2e — вікно − 32 = 736); п'ять нових рядків не вміщуються.
- Тулбар бою — 10 плиток стовпчиком, на 1366 × 768 низ тулбара 720 px.

## Рішення

### Рішення власника (кнопками, назва варіанта дослівно; відхилені — у розділі «Альтернативи»)

1. **Лабораторія — «А. У чинних панелях (Рекомендовано)»:** «Дослідження» — три кнопки найму «Дослідник / Алхімік / Механік (100)»; рядок штату «Ім'я · Алхімік 2 · варить «Стимулятор», «Щит»» (дослідник — «+2 очки за добу», механік — «Кузня» −20 % часу), «до рівня 3 — ще 2 протоколи»; під штатом блок «Модулі бази» — рядок на модуль з ефектом і кнопкою «Купити — 160 кр.» / «Рівень II — 200 кр.» («Стенд» — з причиною «спершу протокол «Розширення лабораторії»»). «Кузня»: блок «Казан алхіміка» — рецепти з ціною й трофеями, кнопка «Зварити», черга казана (опис кнопки).
2. **Чемпіон — «А. «Еліксир чемпіона» (Рекомендовано)»:** один витратник = «Стимулятор» (+3 AP за 0 AP) і «Щит» (поглинає перше влучання) разом; рецепт — 1 трофей «чемпіон» + 60 кр., варить алхімік рівня 3; `missingTrophies` / `spendTrophies` навчаться ключа `champion`, у «Меті кампанії» — «чемпіон N» у рядку трофеїв (опис кнопки; числа — кандидати, probe п22.8).
3. **Бій — «А. Плитка «Стимул» (Рекомендовано)»:** вікно спорядження — «+ видати: стимулятор / щит / еліксир», як гель і граната; смуга загону — значки ⚡ (стимулятор) і ◈ (щит) біля AP, гаснуть після використання; тулбар бою — плитка «Стимул» (0 AP, клавіша S) між «Гранатою» і «Роллю»; журнал — «» Ім'я: «Стимулятор» +3 AP», «◈ Ім'я: «Щит» поглинув влучання»; над бійцем — «щит» замість «−0»; «⚑ Модуль бази: …», «⚑ Казан: вариться / зварено …» — як уже в коді (опис кнопки).
4. **Довідка і PR — «А. Вкладки; один PR (Рекомендовано)»:** вкладки «Основи» (як зараз) і «Розвиток» — рядки: шлях бійця, загін 3 → 4 → 5 (+1 ворог за бійця понад трьох), техноманти (спеціалізації, рівні, модулі), казан і витратники, виводки й чемпіони; числа — з констант ядра; один PR з міткою `size-deviation` (опис кнопки).

### Технічні рішення сесії

5. **Ядро — трофей `champion`:** `missingTrophies` додає «чемпіон N з M» останнім (`CHAMPION_TROPHY_NAME`), `spendTrophies` списує поле лише за ціною з ним — партія без чемпіонів і її сейв без поля, як у п22.6.
6. **Ядро — «Еліксир чемпіона»:** `BrewItemId` `'elixir'`, `BREW_LEVEL.elixir` 3, каталог `{ cost 60, ticks 16, trophies { champion: 1 }, brewed }` (алхімік рівня 3 — удвічі менше тиків, як інші рецепти); склад — ключ `elixir`; слот `SoldierEquipment.elixir`. У бою `deployConsumables` ставить юнітові `stim` і `shield` (дії й щит — чинні `useStim` / `useShield`) і позначку `UnitItems.elixir`; після бою еліксир лишається, лише коли обидві частини не витрачено, інакше зникає (правило «витратник, вжитий у бою, зникає»). Разом зі «Стимулятором» чи «Щитом» еліксир не видається (`equipItem` — throw в обидва боки; вікно спорядження такої кнопки не показує) — інакше витрата однієї частини неоднозначна. Загиблий — еліксир у рядку втрати, як граната.
7. **Найм:** кнопка «Дослідник» лишає id `btn-hire-scientist` (гейти e2e і тести Т.128), решта — `btn-hire-alchemist`, `btn-hire-mechanic`; причина «Недостатньо кредитів» — один рядок під рядком кнопок. Тексти ефектів (`specEffectText`, `nextLevelText`, `moduleEffectText`) — з констант ядра (`MECHANIC_TICKS_CUT`, `BOILER_TICKS_CUT`, `BREW_LEVEL`, `LEVEL_THRESHOLDS`). Рядок штату: «Звільнити» праворуч від імені, спеціалізація й ефект — рядком нижче (колонка ≈ 270 px).
8. **Казан:** блок `#cauldron` під замовленнями «Кузні»: «Казан алхіміка I / II · варіння: … · у черзі ще N», рядок складу трьох витратників, рядок на рецепт (ціна, трофеї, тики з найкращим алхіміком, потрібний рівень, ефект) з кнопкою «Зварити» в `.order-line`; причина — `brewBlockReason` у порядку перевірок `brewItem`.
9. **Вікно спорядження:** витратники казана — окремим переліком `BREW_EQUIP` лише у вікні спорядження; `EQUIP_ITEMS` ростера, лічильник вкладки «Загін» і «Наступний крок» без змін — висота картки ростера (гейти e2e) не росте.
10. **Смуга загону:** `SquadCardView.stim` / `.shield` (є / витрачено / без поля); значки — абсолютно в правому нижньому куті картки (висота картки без змін), у підписі — «· стимулятор · щит витрачено».
11. **Плитка «Стимул»:** `ToolbarActionId` `'stim'`, клавіша S, ціна «0 AP», іконка кодом (ампула з блискавкою); видно лише в бою, де стимулятор (і з еліксиру) узяв хтось із загону — бій без них має ті самі 10 плиток; причина недоступності — `stimBlock` ядра, під плиткою «витрачено» / «немає». Вимір: з 11 плитками на 1366 × 768 низ тулбара 784 px (за вікном), тож з видимою плиткою «Стимул» на ширині ≥ 900 px проміжок 6 → 3 px — 754 px; на 1024 × 560, 900 × 520, 1100 × 540 — 449 / 484 / 449 px.
12. **«щит» над бійцем:** влучання пострілу з шкодою 0 буває лише від «Щита» (броня лишає ≥ 1) — `animsFromEvents` дає число 0, `render.ts` пише «щит»; фатальний постріл — без змін.
13. **«Мета кампанії»:** `trophiesText` — «… · око 0 · чемпіон 0» завжди.
14. **«Як грати»:** вкладки — у рядку заголовка (`.help-head`, кнопки 12 px), висота «Основ» — 731 px, як до кроку; «Розвиток» — 476 px (1366 × 768 і 1024 × 768); кожне відкриття — з «Основ». `.help-box` — `margin: auto`: на телефоні довідка вища за вікно, і центрування flex зрізало верх (з вкладками — недосяжні кнопки).
15. **Золотий сейв:** новий еталон — склад має ключ `"elixir":0` (+11 символів, траєкторія та сама): 106 104 → 106 115, FNV-1a 2489726208 → 194120959.

## Наслідки

- EARS 4–5 Фази 22 — у грі: найм за спеціалізацією, рівень і ефект у штаті, модулі, казан, витратники в бою.
- Панель «Дослідження» вища на ≈ 480 px (три кнопки найму — 138 px, «Модулі бази» — 339 px на новій партії); гейти e2e міряють їх окремо (≤ 160 і ≤ 380), гейт Т.100 — на решті.
- Бот казана, модулів і найму спеціалізацій не вчить — п22.8 (ADR-0182 п. 17); еліксир у боті — недосяжний (`soldierEquipKey` кидає, як для `stim` / `shield`).
- Числа рецепта еліксиру — кандидати, probe п22.8.
