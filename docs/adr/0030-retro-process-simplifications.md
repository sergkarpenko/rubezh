# ADR-0030: Процесні спрощення — ретроспектива Фази 6a і планування 6b

## Статус

proposed (власник схвалив рішення 2026-10-14 — «схвалюю всі 6»; мерж PR = формальна фіксація, конвенція цього ADR)

## Контекст

Ретроспектива 2026-10-14 (Work-сесія) за ланцюжком Фаза 6a → П6.6 → ADR-0028 → план 6b. Конвеєр ADR-0023 працює (ADR-0029 — від дизайн-питань до змерженого плану за одну сесію), але з надмірностями:

- ADR-0028 з'їв два PR (proposed → accepted) — дубльована робота лише для зміни статусу.
- П6.6 — 4 PR на один маленький багфік шару відображення (план-PR → фікс-PR → ADR-PR → закриття).
- Баг П6.6 (артефакти заступи) пройшов повз візуальну валідацію П6.5: «подивитись, чи ок» не ловить стан-залежні дефекти — потрібен фіксований сценарій.
- Ретроспектива — поки ad hoc (ADR-0028 вийшов з неї випадково-добре, але не запланований).
- У критеріях П6.8 немає вимоги плавності анімацій (лише idle → 0 перерисовок) — а це головний ризик 6b.

## Рішення (схвалено власником 2026-10-14, «схвалюю всі 6»)

1. **Один PR на ADR.** Проєкт подається у гілці зі статусом «proposed (мерж PR власником = «схвалюю» → accepted)»; мерж PR = прийняття рішення — окремий PR для зміни статусу не потрібен. Прийняття фіксується рядком «Виконано» у плані фази. Доповнює ADR-0023/0028, нічого не скасовує. Приклад: ADR-0029.
2. **Малі багфікси шару відображення без архітектурних наслідків (без ADR): план-рядок у workflow.md і фікс — в одному PR**, без окремого план-PR (антиприклад: П6.6 — 4 PR). Багфікси з архітектурою — як раніше, за повним циклом ADR-0023.
3. **Стандартний smoke-сценарій візуальної валідації** — обов'язковий мінімум кроку валідації: вибрати юніта → рух (тап-тап) → постріл у видиму ціль → заступа → рух → кінець ходу (хід прибульців) → до результату бою; геосцена: +1 тік, +1 доба, сейв → лоад; консоль без помилок.
4. **Ретроспектива — постійний останній крок кожної фази** (уроки + процесні пропозиції), не ad hoc.
5. **Критерії кроків з анімацією завжди включають плавність на цільових пристроях** (десктоп + iPad Pro): без фрізів і пропусків кадрів, не лише «idle → 0 перерисовок».

## Альтернативи

- Залишити два PR на ADR (статус явний у файлі) — відкинуто: дублювання, мерж і так є актом прийняття.
- Валідація без чеклиста — відкинуто: П6.6 показав, що «на око» пропускає стан-залежні дефекти.

## Наслідки

- Правки workflow.md (принципи, цикл кроків 5 і 7, розділ «Рішення», критерії П6.8) — у тому ж PR.
- Менше docs-PR на фазу, швидший цикл багфіксів, передбачувана валідація.
- Хвіст Фази 3 (теги iter-3.1–3.4, phase3-complete) — власник проставляє локально за мапінгом з опису цього PR.
