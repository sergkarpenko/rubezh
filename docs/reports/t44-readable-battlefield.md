## PR 1. Декор, туман, квадрати (`feat/t44-1-decor-fog`)

### Що зроблено

- **Декор (знахідка 2, ADR-0072)**: ключі `METRO_DECOR_COL` перейменовано `лампа`→`світло`, `голограма`→`решітка` (колонки 1 і 2 тайлу `assets/metro-tiles.png` без змін; колонки 0 і 3 — як раніше). Ассет **не** змінювався. Розклад `decorCol` (детермінований `cellHash % 37`: 0, 1, 2) і малювання 1:1 без змін. `METRO_DECOR_COL`/`decorCol` перенесено з `src/render.ts` у чистий модуль `src/core/render-core.ts` (e2e у Node не може імпортувати `render.ts` — той імпортує ассети `.png/.webp`); у `render.ts` лишено реекспорт, тести `render.sprites.test.ts` використовують нові назви й додатково фіксують колонки 1/2/3 буквально (`світло=1, решітка=2,ulamки=3`).
- **Туман (знахідка 9)** у `drawNightTerrain` (`src/render.ts`), порядок шарів за планом: фон/стіни/декор → **знебарвлення** невидимих клітинок (`globalCompositeOperation='saturation'`, `fillStyle='#808080'`, per-cell `fillRect`, `save/restore`) → `TILE_FOG` без змін → **штрихи** (діагоналі кроком 8 px, що не заходять за межу клітинки; `strokeStyle='rgba(150,170,190,0.16)'`, `lineWidth=1`) → `FOG_EDGE` без змін → **межа** «видима клітинка — невидимий сусід» (4 напрямки) + край поля, один `beginPath`…`stroke`, `strokeStyle='rgba(125,215,255,0.6)'`, `lineWidth=2`. Чиста функція `fogBorderSegments(cells)` — у `src/core/render-core.ts`, координати в сітці клітинок `{x1,y1,x2,y2}`; поза картою — туман, тому край поля дає сегмент. Юніти в тумані лишаються прихованими (ADR-0006) — без змін.
- **Стартові квадрати (знахідка 27)**: червоний `ALIEN_SPAWN` `rgba(255,107,107,0.5)` і синій `SQUAD_SPAWN` уже були в `src/ui/battle.ts` — код не мінявся, додано тест у `src/ui/battle.test.ts` (кольори, координати `strokeRect`, порядок: поверх терену/туману, але під юнітами).
- **e2e-гейт** у `e2e/acceptance.scenario.ts` (крок «запуск місії», видимість із `e2e/mirror.ts`): пікселі канвасу `#battle` (960×960, клітинка 48) через `getImageData`; для центральної ділянки 24×24 px клітинки — середній per-pixel `max(R,G,B)−min(R,G,B)`: у невидимих клітинках без стіни/декору/видимого сусіда **≤ 9**, у видимих **> 9**.

### Що не вдалося / відхилення (чесно)

- **e2e-гейт, перша ітерація падала** (fogMax=91 при метриці «глобальний hi−lo по всій ділянці 24×24»). Діагностика пробним сценарієм: (а) ambient wall-pulse малює cyan-рамку на **всіх** blocked-клітинках, зокрема невидимих, поверх туману — тому план і передбачає вибірку «без стіни»; (б) `FOG_EDGE` (незмінний шар плану) заливає межові невидимі клітинки `rgba(11,18,32,0.4)` — їхній середній spread ≈ **12,5**, тому гейт бере **чистий туман** (невидимі клітинки без стіни, декору й видимого сусіда): виміряно ≈ **6** (на прототипі 5,8; без знебарвлення 13,6–18,3). Пороги плану (≤ 9 / > 9) не послаблено.
- Метрика гейта — саме «середня per-pixel max−min» по центральних 24×24 px (а не максимум): per-pixel максимум на лініях штриховки доходить до 12 через антиаліасинг, середнє ≈ 6.
- `decorCol`/`METRO_DECOR_COL` довелося перенести до `render-core.ts`, щоб e2e міг обчислити декор-клітинки (див. вище); поведінка не змінилась.
- Червоні стартові квадрати вже існували — без змін коду, лише тест.
