# Т.82 — проба аудиту PR через Mistral Vibe CLI в CI (ADR-0102)

Дата: 20.11.2026. PR #397. Модель сесії — Opus 5.5 medium.

## Навіщо

`mistral-audit` з 20.11 ≈ 13:31 UTC отримує 402 `billing_wallet_depleted`: прямі виклики API на плані Team оплачуються з гаманця ($0), бюджет плану покриває лише Vibe Code. Питання кроку: чи працює аудит ключем Vibe у CI, хто його оплачує і чи дає він знахідки понад аудитора для мержу.

## Що зроблено

- Секрет `MISTRAL_VIBE_API_KEY`: ключ Vibe скопійовано кнопкою в Code › Extensions і вставлено в поле секрету GitHub у Chrome власника; значення сесія не бачила. Окремого ключа типу Vibe адмінка не створює («New key» дає ключ Studio).
- `.github/workflows/vibe-audit.yml`, `scripts/audit-vibe-cli.mjs` (самоперевірка: чисті функції, межі числами і повний прохід `audit()` на тимчасовому git-репозиторії з підставними GitHub і Vibe).
- Навмисні поломки скрипта — власною обгорткою сесії «назва, було, стало» над копією скрипта (в PR не входить, як і в попередніх кроках): звіряти цитату з усім дифом замість частини дифа файла, вимкнути вирізання ключа, лишити `GITHUB_TOKEN` у Vibe, читати цитати з робочої теки, вважати код 3 успіхом, прибрати `--disabled-tools`, прибрати `try` навколо аудиту, ігнорувати збій встановлення — 8 з 8 спіймано самоперевіркою (25 перевірок).

## Що з'ясовано про Vibe CLI 3.1.3 (підставний сервер, локально)

- Неінтерактивний режим: `--prompt-file`, `--output text` — у stdout лише остання відповідь; `--output-dir` пише `export.json` (`outcome`, `stop_reason`, `error`, `usage`, `cost_usd`, `steps`).
- `bash` без `--auto-approve` відхиляється («Tool execution denied by approval callback»); `write_file` без `--auto-approve` проходить; `--disabled-tools write_file/edit` діє лише з `--auto-approve`; `[tools.*] permission` у `config.toml` на це не впливає. Вбудована модель `mistral-large-4-0` (ціни у Vibe $0,7 / $2,1 за млн), типовий рівень міркувань — `high`.
- `bash` бачить змінні оточення, зокрема ключ — тому ключ вирізається з коментаря, а `GITHUB_TOKEN` у Vibe не передається.

## Прогін наживо (PR #397, коміт `0d7682e`)

- Перший коміт (`192a95a`): чека `vibe-audit` на PR не було — `${{ runner.temp }}` в `env` джоби робить файл недійсним (прогін `push` «failure» без джоб; `actionlint` це показує).
- **Прямий виклик API ключем Vibe: 200.** У панелі Mistral (Admin › Usage) цей запит записано як `mistral-large-latest`, **Billable, Vibe Code** — тобто ключ Vibe оплачується з плану Vibe і поза CLI.
- **Аудит Vibe:** код 0, `finished`, 19 кроків, ≈ 12,3 хв (15:40:43 → 15:53:04 UTC); токени — ввід 948 325 (з них з кешу 872 448), вивід 15 282. `cost_usd` у `export.json` — 0 (Vibe не рахує ціну для плану). Оцінка за цінами Large 4 у Vibe ($0,7 / $0,07 кеш / $2,1 за млн): ≈ 0,053 + 0,061 + 0,032 ≈ **$0,15 за прогін**. Панель Code › Extensions: «Monthly usage» 11,43 % → 11,45 % від $600 (≈ $0,12) — оплата з плану підтверджена. Admin › Usage: `mistral-large-4-0` Vibe Code — 2,47 тис. → 2,49 тис. запитів.
- Vibe сам прочитав `AGENTS.md`, звіт і ADR, перевірив числа PR командами (`npm test`, `pr-size.sh`, `pr-class.sh`, самоперевірку) і дав 3 знахідки; скрипт жодної не відкинув.
- **`mistral-audit` на цьому PR відповів** (коментар на `0d7682e`, 2 знахідки; в Admin › Usage `mistral-large-latest` Completion — 136 → 138), хоча кредити гаманця — $0,00 і автопоповнення вимкнено. Причину сесія не з'ясовувала: можливо, Mistral дозволяє короткий мінус; за ADR-0102 п. 8 це не змінює проби.

## Аудит

| Аудитор | Знахідок | Підтверджено | Відхилено | Унікальних підтверджених |
| --- | --- | --- | --- | --- |
| Opus (субагент, перший коміт) | 9 | 9 (п. 2 — частково) | 0 | 9 |
| Vibe CLI (Large 4, коміт `0d7682e`) | 3 | 3 | 0 | 2 (цитата з дифа іншого файла; неточність опису PR про код 3); третя — фрагмент ключа — і в Mistral |
| Mistral API (`mistral-audit`, коміт `0d7682e`) | 2 | 1 (фрагмент ключа) | 1 | 0 |

- Opus: усі 9 виправлено другим комітом (найважливіше — збій без коментаря на теці замість файла, неточна безпека в ADR, червоний чек на збої встановлення). Знахідка 2 — частково: ключ Vibe з `bash` видно і далі, ризик записано в ADR-0102 п. 5.
- Vibe 1: `verifyFindings` звіряв цитату з усім дифом PR — знахідку на файл A з цитатою з дифа файла B приймав. Виправлено: цитата з дифа — лише з частини дифа того самого файла (`diffByFile`), перевірка в самоперевірці.
- Vibe 2 / Mistral 1: останні знаки ключа Vibe в ADR і записі кроку — прибрано (у PR-описі теж).
- Vibe 3: опис PR узагальнював «код 3 — коментар «Аудиту не було»», а так лише без відповіді — опис виправлено.
- Mistral 2 відхилено: «8 з 8 поломок немає в дифі» — обгортка поломок за `docs/agents/common.md` («Скрипти CI і workflow») — інструмент сесії, у PR не входить; звіт тепер це каже прямо.

**Контрольна точка ADR-0102 п. 8:** PR 1 з 5 — Vibe дав 2 унікальні підтверджені знахідки.

## Висновки для власника

1. Ключ Vibe працює і для прямого API, і для CLI, оплата — з плану Vibe (Vibe Code). Отже `mistral-audit` можна перевести на секрет `MISTRAL_VIBE_API_KEY` однією зміною workflow — без поповнення гаманця (рішення — власник; окремий крок класу `approve`).
2. Vibe CLI в CI як аудитор із доступом до всього репозиторію і команд дав на першому PR знахідку в коді, якої не дав Opus. Ціна ≈ $0,15 і ≈ 12 хв на прогін.
