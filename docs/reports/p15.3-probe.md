# П15.3 — probe-регресія траєкторій партій без евакуації

**Дата:** 2026-10-26
**Крок:** П15.3 «ШІ і party-bot» (Фаза 15, ADR-0075). Probe — регресія, не баланс: мета — довести, що формальні тести EARS 5–6 не змінили жодної чинної траєкторії партій без евакуації (байт-у-байт).
**Звірка виконана ДО коміту** (урок П11.8).

## Методика

Диф П15.3 — виключно тести (`*.test.ts`: ai, combat, ai-bot, squad) + цей звіт; код ядра (`src/core/*.ts` без `.test.ts`) не змінюється. Тому очікуваний вердикт — повна ідентичність; probe підтверджує його формально.

- **Знімки:** `simulateParty(seed, preset)` — повний горизонт (30 діб, дефолт) — `JSON.stringify` усього `PartySimResult` (рахунок, усі лічильники, криві money/ready/scientists по днях, completedProjects у порядку завершення).
- **serializeParty:** дзеркальний replay циклу `simulateParty` (party-bot.ts, фази 1–5 у тому самому порядку) з інлайновим кроком місії (дзеркало `partyBotMissionStep`) — дає доступ до бойових логів; кінцевий стан партії серіалізується `serializeParty(party, 'probe')` — повний знімок (геосцена, ростер, лікарня, цех, економіка, кампанія).
- **Гілка ≡ main:** той самий untracked-скрипт `scripts/probe-p15.3.ts` виконано двічі — на робочому дереві змін П15.3 і на стані ≡ main через `git stash` (untracked-файл скрипта під stash виживає; `git stash pop` після прогону).
- **Сіди × пресети:** 6 сідів (1, 2, 3, 7, 42, 45) × 3 пресети («легкий», «норма», «складний») = 18 партій, повний горизонт.
- **Формальна перевірка «боти ніколи не викликають evacuate»:** (а) статична — жодного входження `evacuate` у `ai.ts`, `ai-utils.ts`, `ai-bot.ts`, `party-bot.ts`, `intercept-bot.ts`; єдиний файл із викликом `evacuate(` у `src/` — `combat.ts` (сама функція; викликачі — UI/тести, П15.4); (б) динамічна — у replay підраховані події `evac_unit` у бойових логах усіх місій і `mission_evacuated` у журналі геосцени всіх 18 партій.

## Вердикт

**Байт-у-байт: ПІДТВЕРДЖЕНО.** Траєкторії 18 партій (6 сідів × 3 пресети, повний горизонт) без евакуації — метрики `simulateParty` і `serializeParty` кінцевих станів — тотожні між main (c095221) і гілкою П15.3. Жодного виклику `evacuate` ботами (статично + динамічно: нуль `evac_unit`/`mission_evacuated` у всіх логах симуляцій).

Обмеження: probe П15.3 — регресійний (18 партій); probe-баланс з політикою евакуації (120 сідів × 3 пресети, «порожні перемоги») — окремий крок П15.5 за прецедентом П11.8.
