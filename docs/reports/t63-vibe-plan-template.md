## Звірка скіла і контексту проєкту `rubezh` у Mistral

Що бачить сесія в Chrome власника (`chat.mistral.ai`, розділ Code, 17.11.2026):

- **Інструкція проєкту** `rubezh` (вкладка Context): один рядок англійською — гобі-проєкт, стратегія, AI-native SDLC. Вказівок немає, з планом не розходиться. Підключений репозиторій — `sergkarpenko/rubezh`.
- **Скіл `rubezh-session`** (Skills, «Created by me»): увімкнений; у сесії Code його видно в меню поля повідомлення («+» → Skills → Personal). Опис: завантажувати на початку кожної Work-сесії про «Рубіж»; там само — «Кодові сесії … веде Vibe Code (VS Code) … — він цей скіл і тему знань не бачить». Чи підтягує Vibe Code скіл сам, за описом, сторінки не кажуть.
- **Сесія виконавця Т.61** від першого повідомлення: перші дії — `git` і читання плану; рядка про завантаження скіла не видно (кроки інструментів у вікні згорнуті — межа (а)).

Розбіжності тексту скіла з шаблоном, `docs/agents/common.md` і `AGENTS.md`:

| № | Скіл (переказ) | Чинне | Наслідок, якщо виконавець скіл завантажить |
| --- | --- | --- | --- |
| 1 | Vibe Code працює у VS Code і скіла не бачить | Vibe Code Web — у тому ж акаунті, скіл увімкнений і видимий у сесії Code | припущення скіла про власну невидимість хибне |
| 2 | Початок сесії: прочитати тему знань «Рубіж», звірити з репозиторієм, узяти перший пункт «Наступні кроки» теми | Vibe Code не планує (`AGENTS.md`, ADR-0042); рішення власника 15.11: «Vibe: планування не давати»; крок і план дає сесія Claude | самостійний вибір кроку замість плану; тема знань з кроками Т.* не синхронізована |

## Перевірка

- `parsePlan` зі `scripts/vibe-plan-check.mjs` на новому шаблоні і на шаблоні з `main` (`d066deb`): назва PR, рядок тегу, відповіді власника, шлях і розділи звіту, терміни, заголовки й `afterAudit` (`false`) — ті самі; змінились лише слова, цитати, вказівки поза блоками і місця для заповнення (8 → 11: нові чотири місця виконавця замість одного місця-переліку).
- Шаблон із заповненими `<ім'я>`, `t<NN>` і `<N>` (у тимчасовому робочому дереві з комітом) — `vibe-plan-blocks.mjs` вирізає 5 блоків; блок `pr-body` з незаповненими місцями виконавця — `vibe-plan-check.mjs --title … --body-file …` показує всі чотири як «незаповнене місце плану», після заповнення — жодного з них (лишаються лише місця планувальника шаблону).
- Той самий план із дописаним розділом `## Після аудиту: порції (…)` — скрипт переходить у стан «після» і показує «Аудит ще не проведено» в описі PR; сам шаблон лишається в стані «до» (назва розділу в ньому — у тексті пункту, не заголовком).
- `rm -rf dist && node scripts/agents-docs-check.mjs` — розбіжностей немає.
- Коду гри, тестів і `.github/` PR не чіпає: чекліст коду не потрібен, обов'язкові чеки — у CI.

## Межі

- (а) Чи завантажує Vibe Code скіл `rubezh-session` сам, не встановлено: у вікні сесії Т.61 кроки інструментів згорнуті, старі повідомлення вантажаться прокруткою; на початку сесії видимого завантаження немає.
- (б) Шаблон перевірено розбором скриптів, а не живим кроком Vibe: чи виконавець утримається від пушу після PR і чи вставить таблицю файлом — покаже перший крок за новим шаблоном.
- (в) Місце з назвою кирилицею, заповнене вигаданим текстом, скрипт від правильного не відрізнить — як і раніше (межа (в) звіту Т.62); це закриває звірка дифа з прототипом планувальника.
- (г) Перелік кандидатів сесії Claude (документ проєкту claude.ai) оновлюється поза репозиторієм.
