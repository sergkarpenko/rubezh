# Т.35. PR без «схвалюю»: клас PR за шляхами

Дата: 2026-11-14. Рішення — ADR-0094. Код гри не змінювався.

## Що було

Кожен змістовний PR чекав «схвалюю» власника (ADR-0052). За журналом кроків Т.15–Т.33 це від 3 хвилин до 9 годин на крок. Частина кроків гру не змінює — звіти симуляцій, огляд UX, скрипти аналізу, тести; у них «схвалюю» нічого не додавало до чеків, а з Т.34 — і до аудиту окремою моделлю.

## Рішення власника (кнопками, до реалізації)

| Питання | Відповідь |
| --- | --- |
| Що вважати «не грою» | `docs/`, `scripts/`, тести (`src/**/*.test.ts`, `e2e/`). `.github/` — ні |
| Що вважати «аудитом без знахідок» | Немає невиправлених: підтверджені виправлено другим комітом, відхилені перелічено з причиною в описі PR |

Винятки всередині «не гри» названо в питанні й записано в ADR: ADR (`docs/adr/`), скрипти CI і хуків, видалення файлу тестів.

## Що зроблено

- `scripts/pr-class.sh <base> <head>` — клас PR за шляхами змінених файлів: рядок на файл і останній рядок `КЛАС: auto` або `КЛАС: approve`. Режим `--ci` — крок workflow (клас у підсумку прогону; правило береться з бази PR, якщо скрипт там є). Режим `--self-test` — самоперевірка.
- `.github/workflows/pr-size.yml` — два кроки в наявній джобі: самоперевірка скрипта і «Клас PR». Нової джоби й нового чека немає; клас `approve` чек не валить.
- ADR-0094; правила в `AGENTS.md` і `docs/workflow.md` (правила 5 і 8).

### Правило класу

| Шлях | Клас |
| --- | --- |
| `docs/**` | `auto` |
| `docs/adr/**`, `docs/prototypes/**` | `approve` |
| `src/**/*.test.ts`, `e2e/**` — доданий або змінений | `auto` |
| `src/**/*.test.ts`, `e2e/**` — видалений або перейменований | `approve` |
| `scripts/**` | `auto` |
| `scripts/pr-class.sh`, `scripts/pre-commit.sh` і скрипт, чиє ім'я згадано в `.github/`, `.husky/`, `package.json`, `scripts/pre-commit.sh` (у базі або в гілці) | `approve` |
| усе інше: `src/` без тестів, `index.html`, ассети, `AGENTS.md`, `README.md`, `.github/`, `package.json`, конфігурація | `approve` |
| порожній диф; зміна типу файлу | `approve` |

PR має клас `auto`, лише коли кожен його файл — `auto`.

На `main` зараз скриптами CI і хуків скрипт вважає: `pr-class.sh`, `pr-size.sh`, `iter-tag.sh`, `mutation-summary.mjs`, `pre-commit.sh`, `verify-exact-bytes.sh`. Решта `scripts/` (симуляції, probe, `geo-layout.py`, `trace-party.ts`) — `auto`.

### Умови мержу без «схвалюю» (ADR-0094, п. 3)

1. Клас `auto` за версією скрипта з `main` на останньому коміті PR.
2. Обов'язкові чеки зелені на останньому коміті.
3. Аудит окремим читачем пройдено, невиправлених знахідок немає; опис PR містить розділ «Аудит».
4. У PR немає рішення, яке ухвалює власник; зміна правил у `docs/workflow.md` — завжди з «схвалюю».

| Поломка | Результат |

## Межі

- Скрипт бачить шляхи, а не зміст. Тест можна послабити, не видаляючи файл; у `docs/workflow.md` можна змінити правило. Перше має ловити аудит, друге — умова 4 і аудит. Механічної перевірки цих двох випадків немає.
- Умови 3 і 4 виконує сесія; CI їх не бачить. Запис про аудит — розділ «Аудит» в описі PR і журнал кроків.
- Крок «Клас PR» у CI — довідка. PR, що змінює workflow, може її спотворити; такий PR має клас `approve` за версією скрипта з `main`.
- Скриптом CI вважається той, чиє ім'я файлу згадано в переліку місць. Скрипт, який викликає інший скрипт CI (крім `pre-commit.sh`), у перелік не потрапить, поки його не згадано там прямо. Зараз таких немає.
- Збіг за іменем файлу може дати зайве `approve` (ім'я згадано в коментарі) — це безпечний бік.
- Мерж без «схвалюю» діє, поки діє аудит кроків (експеримент Т.34–Т.36). Перше застосування — найближчий крок класу `auto`.
