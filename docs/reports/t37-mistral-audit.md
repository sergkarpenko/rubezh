# Т.37. Mistral — зовнішній аудитор PR

Дата: 2026-11-15. Рішення: ADR-0095. Код гри, тести гри й наявні workflow без змін.

## Що зроблено

| Файл | Зміст |
| --- | --- |
| `scripts/mistral-audit.mjs` | збирає диф PR і правила, викликає API Mistral, пише коментар у PR; режим `--self-test` |
| `.github/workflows/mistral-audit.yml` | джоба `mistral-audit` на кожен пуш у PR: самоперевірка, потім аудит |
| `docs/adr/0095-mistral-pr-audit.md` | рішення |
| `AGENTS.md` | рядок ADR-0095 у таблиці, два рядки про чек у розділі «Завершення сесії» |

## Рішення власника (кнопками, до реалізації)

| Питання | Відповідь |
| --- | --- |
| Модель | Mistral Large 4 (`mistral-large-latest`) |
| Замінює аудит Opus-субагентом чи поруч | поруч два-три кроки (Т.37–Т.39), потім рішення |
| Збій API або зіпсована відповідь | зелений чек і коментар про збій |
| Ключ API | власник показав, що на репозиторій встановлено застосунок MistralAI; з'ясовано, що джобі CI він ключа не дає — потрібен секрет `MISTRAL_API_KEY` |

На дату кроку в документації Mistral моделі Devstral 2 і Medium 3.5 позначено як виведені з обігу (заміна — Large 4), тому Devstral, якою раніше працювали агенти Vibe, власникові не пропонувалась.

## Розвилки, вирішені сесією

1. **Правила аудиторові — `AGENTS.md` з бази PR, а не з гілки.** Інакше PR міг би переписати правила, за якими його перевіряють. Зміну правил аудитор бачить у дифі.
2. **`docs/workflow.md` аудиторові цілком не дається** (≈ 266 КБ): запис кроку і звіт він бачить у дифі.
3. **Один коментар на PR, що оновлюється,** а не новий на кожен пуш: позначка `<!-- mistral-audit -->`, автор — бот. Коментар людини з такою самою позначкою скрипт не чіпає.
4. **Подія `pull_request`, а не `pull_request_target`:** PR з форку секрету не отримує, і джоба для нього пропускається.
5. **Перезапуск на `edited` не додано:** зміна опису PR аудит не перезапускає — інакше кожна правка опису коштувала б виклик API. Наслідок: аудитор читає опис, яким він був на момент останнього пушу.
6. **Назва моделі — змінна репозиторію `MISTRAL_MODEL`** з перевіркою формату; порожня або недопустима — типова.
7. **Скрипт — Node без залежностей** (`fetch` у Node 22), `package.json` не змінено.

## Що аудитор бачить і чого ні

- Бачить: `AGENTS.md` (база), назву й опис PR, диф по файлах.
- Не бачить: `package-lock.json`, бінарні ассети, файл понад 60 000 знаків (лише початок), усе понад 240 000 знаків дифа — перелік не показаного є в коментарі.
- Не може: запустити команду, прочитати файл поза дифом, побачити результат чеків. Аудит субагентом це може — тому два аудитори порівнюються, а не взаємозамінні.

## Самоперевірка і навмисні поломки

`node scripts/mistral-audit.mjs --self-test` — 63 перевірки (51 до аудиту кроку): збирання дифа в тимчасовому репозиторії (`mktemp`, `git init`, гілка, `main`, що пішов далі; шлях із пробілом, кирилицею і знаками шаблону), розбір відповіді, знешкодження тексту, повний прохід з підставним `fetch` (успіх, оновлення коментаря, 401, 429 і 503 з повтором, помилка мережі, без секрету, зіпсована відповідь, відмова GitHub, немає бази, подія не PR), відсутність ключа в коментарі й журналі.

Навмисні поломки за переліком гілок логіки — по одній заміні в копії скрипта; перелік і запуск — `docs/reports/t37/mutations.py`:

| Прогін | Поломок | Не помітила самоперевірка |
| --- | --- | --- |
| перший | 35 | 8: межа дифа, два крапки замість трьох у `git diff`, шлях без `literal`, доказ без знешкодження, пошук коментаря без позначки, багаторядкова причина збою, і дві нижче |
| після шести нових перевірок | 35 | 2 |
| після виправлень за аудитом (63 перевірки) | 49 | 2 — ті самі |

Дві, що лишились, поведінки не міняють: без перевірки «`findings` — масив» і без перевірки коду відповіді GitHub наступний рядок однаково кидає виняток, і результат той самий (коментар про збій; «коментар не записано» в журналі).

## Обмеження

- Самоперевірка не викликає справжній API: формат відповіді Mistral і поведінку моделі показує лише прогін на PR.
- Модель може повернути знахідку про рядок, якого в дифі немає; скрипт цього не перевіряє — перевіряє сесія.
- Текст у PR може намагатися керувати аудитором. Наслідок обмежений: аудитор без інструментів, його вивід знешкоджено, коментар мерж не вирішує.

## Аудит кроку (Opus, субагент без контексту сесії)

Десять знахідок, усі підтверджено і виправлено другим комітом. ≈ 6 хв, ≈ 128 тис. токенів.

| № | Важливість | Знахідка | Що зроблено |
| --- | --- | --- | --- |
| 1 | висока | скрипт, запит і фільтр файлів беруться з гілки PR — PR може послабити власний аудит; ADR стверджував протилежне | ADR виправлено; коментар попереджає, коли PR змінює скрипт або workflow аудитора. Повністю не усувається: workflow події `pull_request` теж береться з гілки |
| 2 | середня | файли йшли за абеткою: великі `docs/` витискали `src/` за межу дифа | спершу код, документи наприкінці |
| 3 | середня | перейменування з правкою аудитор бачив як новий файл | `--name-status -M`, диф по парі шляхів |
| 4 | середня | текст моделі лишав робочі зображення, посилання, заголовки й огорожі коду Markdown | екранування розмітки, підсумок з префіксом «Підсумок:» |
| 5 | середня | заголовки розділів запиту можна підробити з опису PR | одноразовий код у заголовках розділів |
| 6 | середня | перелік не показаного без межі: коментар міг перевищити ліміт GitHub і не записатись | до 30 рядків і «… і ще K»; коментар до 60 000 знаків |
| 7 | середня | сім прогалин самоперевірки; тест «коментар людини» подавав не ті дані; зламане визначення режиму давало мовчазний зелений вихід; перелік поломок не був у репозиторії | дванадцять нових перевірок; крок CI вимагає рядка «помилок 0»; перелік — `docs/reports/t37/mutations.py` |
| 8 | низька | пошук свого коментаря: одна сторінка, будь-який бот | до десяти сторінок, лише `github-actions[bot]` |
| 9 | низька | два суперечливі записи про той самий не показаний файл | один запис на файл |
| 10 | низька | визначення режиму за закінченням імені; без `GITHUB_EVENT_PATH` — код 1; залежність від `color.ui` і `commit.gpgsign` | порівняння повних шляхів; пропуск з кодом 0; `-c color.ui=never`, `-c commit.gpgsign=false` |

Не виправлено з десятої знахідки: ключ із недопустимими знаками вважається помилкою мережі (три спроби замість однієї) — результат той самий, коментар про збій.

Після виправлень диф — 628 рядків у підрахунку: PR має мітку `size-deviation` (ADR-0061); 250 рядків із них — самоперевірка.

## Перший прогін на PR кроку

Перший пуш (без секрету): чек зелений, коментар «Аудиту не було: у репозиторії немає секрету MISTRAL_API_KEY» — шлях збою працює наживо. Прогін із секретом — дописується наступним комітом.
