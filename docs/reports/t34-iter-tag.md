# Т.34. Тег кроку без дій власника

Дата: 2026-11-14. Рішення — ADR-0093. Код гри не змінювався.

## Що було

Кожен крок технічної лінії з Т.5 закривався так:

1. власник пише «схвалюю», сесія мержить PR;
2. власник дає сесії доступ до теки локального клону;
3. сесія ставить там тег `iter-T.N`, власник пушить його;
4. сесія відкриває другий PR — рядок тегу з sha merge-коміту — і мержить його після чеків (ADR-0057).

За журналом кроків Т.15–Т.33 кроки 2 і 3 — це дві дії власника і 2–12 хвилин очікування на кожен крок; крок 4 — ще одне коло чеків.

## Перевірка: чи може тег поставити сама сесія

Ні. Обидва шляхи відхиляє проксі хмарної сесії (перевірено 2026-11-14 на пробній назві `probe-t34`, тег не створено):

| Шлях | Відповідь |
| --- | --- |
| `POST repos/sergkarpenko/rubezh/git/refs` (`ref=refs/tags/probe-t34`) | 403 «Write access to this GitHub API path is not permitted through this proxy» |
| `git push origin <sha>:refs/tags/probe-t34` | 403, «the remote end hung up unexpectedly» |

Урок Т.5/Т.6 чинний, тому потрібен workflow.

## Що зроблено

- `.github/workflows/iter-tag.yml`:
  - джоба `check` — на відкриття PR, пуш і зміну опису: самоперевірка скрипта і назва майбутнього тегу в підсумку прогону; недопустима або вже зайнята назва — червоний чек;
  - джоба `tag` — після мержу PR у `main` або вручну (`workflow_dispatch`, входи `tag` і `sha`): ставить тег на merge-коміт через `POST /git/refs`; лише вона має `contents: write`.
- `scripts/iter-tag.sh` — назва тегу з рядка `Iter-Tag:` опису PR; перевірка назви; `--self-test`.
- ADR-0093; правила в `AGENTS.md` (мережеві дії, крок 4 завершення сесії, рядок таблиці ADR) і в `docs/workflow.md` (правило 8, розділ «Теги ітерацій», позначка на уроці Т.5/Т.6, запис кроку).

Як це виглядає для кроку: в описі PR — рядок `Iter-Tag: iter-T.N`; у записі кроку в `docs/workflow.md` — «Тег `iter-T.N` — на merge-коміті PR #N». Після «схвалюю» сесія мержить PR і перевіряє тег командою `git ls-remote --tags`. Другого PR немає.

## Перевірки до мержу

### Самоперевірка скрипта (`sh scripts/iter-tag.sh --self-test`)

15 пар «опис PR → назва або помилка», усі зелені: рядка немає; порожній опис; `iter-T.34`; `iter-8.4a`; `iter-P` з пробілами довкола; кінці рядків CRLF; той самий рядок двічі; рядок не з початку рядка (не рахується); дві різні назви (помилка); `v0.5.0` (помилка); порожня назва (як без рядка); зайве слово після назви (помилка); `iter-T.34;id` (помилка); `iter-T/34` (помилка); назва в зворотних лапках (помилка).

### Кроки workflow на заглушці `gh`

Блоки `run` витягнуто з yml і прогнано в `bash -e` із заглушкою `gh`, яка відповідає за наявний тег і за порівняння з `main` та записує виклики.

| Крок | Випадок | Код | Створень тегу |
| --- | --- | --- | --- |
| `check` | рядка немає | 0 | 0 |
| `check` | нова назва | 0 | 0 |
| `check` | назва зайнята | 1 | 0 |
| `check` | недопустима назва | 1 | 0 |
| `tag`, план | мерж без рядка | 0, виходів немає | 0 |
| `tag`, план | мерж з рядком | 0, `tag` і `sha` у виходах | 0 |

| `tag`, план | вручну, sha на 7 знаків | 1 | 0 |
| `tag`, план | вручну, `iter-T.34;id` | 1 | 0 |
| `tag`, план | коміт не в `main` | 1 | 0 |

| `tag`, запис | тег на тому самому коміті | 0 | 0 |
| `tag`, запис | тег на іншому коміті | 1 | 0 |

### Запити, на які спирається workflow, на живому репозиторії (лише читання)

- `compare/d9ab9b7d…e57c...main` → `ahead`; `compare/6bbff273…21a7...main` → `identical`;
- `git/ref/tags/iter-T.33` → `d9ab9b7d8b75bedbac90a5ecc49899665970e57c`; `git/ref/tags/iter-T.3` → 404 (пошук точний, не за початком назви).

## Межі

- Джоба `tag` до мержу цього PR наживо не запускалась: перше живе спрацювання — мерж самого PR Т.34. Не перевірено наживо: чи подія `closed` запускає workflow, доданий цим самим PR; чи вистачає джобі права `contents: write` за налаштувань репозиторію; чи немає правила захисту тегів. На ці випадки є ручний запуск, а якщо не спрацює і він — тег ставиться по-старому, у теці власника.
- Заглушка `gh` перевіряє логіку кроків, а не вирази `if:` джоб і не підстановку `${{ … }}`.
- Помилку в назві після мержу сесія не виправить: видалити чи пересунути тег може лише власник. Захист — чек `check` до мержу; він не обов'язковий.
- `scripts/` поза `tsc`, lint і тестами (урок Т.25): самоперевірку скрипта запускає лише джоба `check`.
- Тег з'являється одразу після мержу, до перегляду основного сайту власником.
