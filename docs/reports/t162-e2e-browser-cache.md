# Т.162. Кеш браузера Playwright у джобі `e2e`: вимір і висновок

Дата: 2026-11-24. Позафазний крок, клас PR `auto` (лише `docs/**`). Кандидат 5 переліку сесії Claude — вибір власника на фініші Т.161 кнопкою «Схвалюю; кеш браузера e2e (5)». Після виміру власник обрав кнопкою «А. Звіт без зміни CI» (відхилено «Б. Кеш, як задумано» і «В. Кеш браузера і apt»). Workflow `ci` не змінено, нового ADR немає.

## Результат

**Кеш браузера скоротив би джобу `e2e` на секунди, а не на хвилину.** Крок `npx playwright install --with-deps chromium` триває 16–34 с (медіана ≈ 26 с) з ≈ 131 с джоби, і більшу частину кроку займає не браузер, а системні пакети apt (`--with-deps`): медіана ≈ 18 с проти ≈ 7 с на завантаження браузера. Кеш `~/.cache/ms-playwright` прибирає лише завантаження (≈ 327 МіБ), а саме відновлення такого архіву з кешу GitHub теж забирає кілька секунд; пакети apt лишаються на кожному прогоні. Оцінка виграшу — ≈ 1–3 с на прогін (відновлення кешу не міряно: без зміни workflow його не виміряти).

Ще дві обставини зменшують виграш:

- Workflow `ci` іде лише на `pull_request`. Кеш, збережений у прогоні PR, видно тільки цьому PR; спільний для всіх PR кеш — лише з гілки `main`, де `ci` не запускається. Без окремого прогріву на `main` (наприклад, кроком у `preview.yml`) перший пуш кожного PR — промах, тобто повне завантаження плюс збереження кешу.
- Джоби `test`, `e2e` і `shuffle` ідуть паралельно. У тих самих восьми прогонах `e2e` (медіана ≈ 131 с) коротша за `test` (медіана ≈ 163 с) у шести, а в двох довша на 11–20 с. Кілька секунд у `e2e` очікування чеків PR здебільшого не скорочують зовсім.

## Звідки числа

- Вісім успішних прогонів workflow `ci` на PR #467–#474 (24.11.2026), джоби `e2e`: `138427846768`, `138431444344`, `138445539312`, `138450247136`, `138479176509`, `138488523337`, `138545228272`, `138550570973`. Журнали — `gh api repos/sergkarpenko/rubezh/actions/jobs/<id>/logs`, тривалість джоби — `started_at` / `completed_at` з `gh api …/actions/jobs/<id>` (так само для джоб `test` тих самих прогонів).
- Межі частин кроку — за мітками часу рядків журналу: початок кроку (`Run npx playwright install`) → перший `Reading package lists` (кінець `apt-get update`) → `Downloading Chrome for Testing` (кінець пакетів apt, початок завантаження браузера) → останній рядок `downloaded to /home/runner/.cache/ms-playwright` → `Run npm run test:e2e`. Числа порахувала скриптом сесія (Node, поза репозиторієм).
- Завантаження на кожному прогоні однакове: Chrome for Testing 159.0.8154.6 (playwright chromium v1255) — 199,3 МіБ, FFmpeg v1013 — 2,2 МіБ, Chrome Headless Shell 159.0.8154.6 — 125,7 МіБ (`@playwright/test` 1.65.1 за `package-lock.json`).

## Відхилені варіанти (рішення власника кнопкою)

- **Б. Кеш, як задумано:** `actions/cache` для `~/.cache/ms-playwright` з ключем за версією `@playwright/test`, `npx playwright install-deps chromium` на кожному прогоні, прогрів кешу на `main`; зміна двох workflow і ADR за ADR-0018 заради ≈ 1–3 с.
- **В. Кеш браузера і пакетів apt:** кеш `.deb` прибрав би частину завантаження пакетів, але не `apt-get update` і не їх встановлення; виграш, можливо, ≈ 10 с, а шрифти, які ставить `--with-deps`, задають метрики тексту в гейтах e2e (висота довідки «Як грати», `docs/agents/ui.md`) — підміна пакетів із кешу крихка.

## Наслідки

- Кандидат 5 закрито висновком «виграшу немає»; повернутись до нього варто, лише якщо зміниться картина: `ci` почне йти на `main`, браузер стане значно більшим або `e2e` стане найдовшою джобою.
- Повторити вимір — тими самими командами і межами по журналах свіжих прогонів.
