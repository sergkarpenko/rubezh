# Довідник агента: кроки про вигляд і UX

Читати разом із [`common.md`](common.md) — там же про те, що таке довідник, для кого він і як оновлюється (ADR-0096). Уроки цього типу кроків дописувати сюди в PR кроку. Розділ «Лише для хмарної сесії Claude» наприкінці — про одне середовище.

Оракул у цих кроках слабший, ніж у кроках про правила: механізм перевіряє розміри, положення і тексти блоків, а чи стало зручніше — оцінює власник на прев'ю.

## Порядок кроку

- **Зміна UI з вибором власника (Т.31 — 18 хв, Т.32 — 16 хв, Т.33 — 45 хв до зеленого PR):** `npm run build` → прев'ю → скрипт Playwright: кожен варіант — CSS через `page.addStyleTag` або правка DOM на живій сторінці, знімок 1366 × 768 і `getBoundingClientRect` ключових блоків → аркуш зі знімків (PIL; для правої частини панелі — вирізки на повний розмір поруч) власникові + питання з числами (до чотирьох за раз) → код → виміри «після» → гейт у сценарії → поломки → `tsc`, lint, тести → звіт, коміт, PR. В ескізі стан бою чіпляти як `#layout:has(#status.dimmed)`, у коді — клас `in-battle`.
- **Пристрої власника (рішення 14.11.2026):** телефон — завжди з ним; iPad Pro — частіше, ніж Mac mini; ноутбука немає. Прев'ю власник найімовірніше відкриє на iPad Pro або телефоні: посилання на прев'ю давати завжди; розмір iPad (1024 × 768) тримати серед розмірів вимірів і гейта; широкий екран (1366 × 768 і більше) показувати аркушем знімків у чаті.
- **Варіанти вигляду канви для вибору власника** (Т.44): `page.addStyleTag` канву не міняє — робити прототип правкою копії репозиторію (скрипт із заміною шматків `src/render.ts` і `src/ui/battle.ts`, варіант — за прапорцем `globalThis.__v`), збирати копію, знімати `locator('#battle').screenshot()` для кожного варіанта і складати аркуші. Прототип — джерело чисел і кольорів для плану, не код для гри.
- **Числа й тексти на ескізі брати зі сторінки або з констант ядра** (`title` плитки, `RIFLE.modes`), не вписувати руками (Т.33).
- **Аркуш знімків «після» дивитись до першого пушу, а ширини текстів друкувати у вимірах після кожної правки CSS** (Т.33: недійсний `font: … inherit` відкинув усе правило, виміри того прогону ширин не друкували).
- **Прев'ю гілки для власника (ADR-0060):** `gh api -X POST repos/sergkarpenko/rubezh/actions/workflows/preview-branch.yml/dispatches -f ref=main -f "inputs[branch]=<гілка>"`; готовність — `actions/workflows/preview-branch.yml/runs?per_page=1` (≈ 1,5–2 хв); адреса `https://sergkarpenko.github.io/rubezh/preview/<гілка зі «/» → «-»>/`. Пропонувати посилання разом із зеленим PR, не чекаючи питання.

## Прев'ю, Playwright, знімки

- Локальне прев'ю: `npx vite preview --port 4173 --strictPort`. `vite preview` віддає файли з диска — після `npm run build` перезапуск не потрібен.
- **Скрипт Playwright поза репозиторієм:** символьне посилання `<тека>/node_modules` на `node_modules` клону, інакше `@playwright/test` не знаходиться.
- **Виміри розкладки:** геосцена — `E2E_CHROME=… [PORT=4174] node docs/reports/t31/measure.mjs <мітка> [shots]`; бій — `E2E_CHROME=… node docs/reports/t32/measure.mjs <мітка>` (шість розмірів + результат); відповіді бою — `E2E_CHROME=… node docs/reports/t33/measure.mjs` (чотири розміри, п'ять станів, ширини підписів плиток). Скрипти Т.32 і Т.33 пишуть знімки в `out/` поруч із місцем запуску — теку `out` створити заздалегідь.
- **Огляд UI зі знімками (Т.30):** сценарій Playwright із трьома проєктами поза `e2e/`, що імпортує `e2e/mirror.ts`; запуск: `T30_OUT=/tmp/t30-shots/ E2E_CHROME=… npx playwright test -c docs/reports/t30/pw.config.ts [--project d1366]`. Один прохід одного розміру ≈ 35–40 с.
- **Рідкісний стан для знімка:** зберегти в слот 1, поправити JSON у `localStorage['rubezh.save.1']` (`state.econ.money`, `state.roster.soldiers`, `state.roster.hospital[id] = тіки`, `state.intercept.fighter.hp`), натиснути «Завантажити». Оперативник без AP у бою: вибрати тапом, двічі тапнути клітинку за 8 стовпчиків праворуч (`t33/measure.mjs`).
- **Числа розкладки брати з `getBoundingClientRect`, а не зі знімків**; для огляду склеювати кілька знімків в аркуш.
- **Вимір показує не твій код — перевір порт** (Т.43): `vite preview --strictPort`, запущений у фоні, мовчки не стартує, якщо порт 4173 зайнятий чужим прев'ю (e2e субагента-аудитора), і скрипт міряє чужу збірку — у вимірі не було жодного нового елемента. Перед виміром переконатись, що порт вільний (`curl -s -o /dev/null localhost:4173 && echo зайнято`); у вимір класти лічильник нового елемента.
- **Новий елемент у шапці чи рядок під кнопкою — міряти до коду** (Т.43, урок — у записі кроку): аркуш «до / після» з висотою шапки і кожної зачепленої панелі на 1366 × 768 і 1024 × 768 — до плану, разом із питаннями власнику; колонка вузла — ≈ 270 px тексту. Висоту довідки «Як грати» тримає гейт e2e на 1366 × 768 (межа — вікно мінус 32 px): новий пункт довідки може його зламати.
- **Гейт e2e не має залежати від шрифту машини** (Т.43): перевірка «текст на одній лінії з кнопкою» локально зелена, у CI червона — там інший шрифт і текст переноситься. Перевіряти властивість (`display`, число фрагментів `getClientRects()`, колір), а не збіг координат тексту.

## Гейт e2e і тести UI

- **`toBeVisible` Playwright — не «гравець бачить» (спостереження сесії після мержу Т.61):** він пропускає `opacity: 0`, прозорий колір тексту, перекриття іншим елементом і обрізаний текст. Зразок перевірки — хелпери `t61Look` і `t61Visible` у `e2e/acceptance.scenario.ts`: елемент у центрі через `elementFromPoint`, непрозорість з предками, альфа кольору тексту, кегль, `scrollWidth`.
- **Поломки гейта e2e (Т.32):** ламати лише файл під перевіркою (`cp` копії в `/tmp` → `sed` → `npm run build` → `E2E_URL=http://localhost:4173/rubezh/ npm run test:e2e` → `cp` назад); `git stash` ховає разом із кодом і сам гейт. Поки прев'ю на 4173 підняте, `npm run test:e2e` без `E2E_URL` падає з «already used». Поломку, яку e2e не бачить, прогнати тестами модуля і записати обидва результати (Т.33).
- **Новий елемент у панелі бою:** `el('<id>')` кидає помилку, якщо елемента немає, — додати його в розмітку `setupDom` у `src/ui/battle.test.ts` і `src/ui/input.test.ts`. Залежності `BattleDeps` у `battle.test.ts` підмінюються (`makeFixture({ hasRaf: () => true })`, `f.deps.anim.queued = …`) — так тестується все, що в jsdom вимкнено через відсутність rAF; таймери — `vi.useFakeTimers()`.
- **UI-тести панелей:** `src/ui/panels.test.ts` має фікстуру `makeFixture()`; `research-panel.test.ts` і `workshop-panel.test.ts` — глобальна `party` (`createParty(42)` у `beforeEach`; для пресета — `party = createParty(42, 'легкий')`). Тести на числа — на пресеті з множником не 1 (урок Т.29).
- **Скрипт поломок з e2e — довгий** (спостереження сесії після мержу Т.43): e2e на кожну поломку — ≈ 25 с; ганяти його лише для поломок розмітки, CSS і зв'язування (`main.ts`, `battle.ts`), для чистих функцій досить `vitest` на файл модуля.
- **Гейт e2e на пікселях канви** (Т.44): `getImageData` внутрішньої канви `#battle` (960 × 960, клітинка 48) від шрифту й розміру вікна не залежить. Три робочі форми: розкид каналів `max − min` у центральній ділянці клітинки («сіре / кольорове»); різниця середнього зеленого каналу клітинки до і після дії (заливка 0,09 на тайлі з G ≈ 179 дає лише ≈ 4 — поріг брати з запасом від найсвітлішого тайла); колір одного пікселя на лінії (`G − R`, `G − B`). Клітинки з юнітами й точки під плашками з гейта виключати явно.
- **Тест порядку шарів канви** (Т.44) — за індексами операцій у журналі контексту (`Proxy`, що пише `set:властивість=значення` і `метод(аргументи)`): шукати першу операцію кожного шару і порівнювати індекси. `createGame` видає стороні, що ходить, `maxAp` — для тесту з малим AP задавати й `maxAp`. Апостроф у назві тесту в одинарних лапках ламає файл — писати знак кодом. Фікстура, де `ap` дорівнює `maxAp`, не відрізняє одне від другого — умови «вистачає AP» тестувати після витрати AP; у тесті малювання перевіряти й `beginPath` перед кожним шляхом (обидві прогалини знайшов аудит PR #344).
- **Умова показу у двох місцях** (Т.45; урок — у записі кроку): прев'ю шляху ховають і обробник наведення (`battleCanvasHover`), і умова малювання (`renderBattle`). Сценарій e2e ставить шлях тапом, наведення в ньому — лише `locator.hover({ position })` по канві; фікстура наведення в `input.test.ts` — `hoverFixture()` (вибраний оперативник і досяжна порожня клітинка), авто-бій — `makeFixture(true)`. Режим пострілу в тестах зводити всіма трьома (`snap`, `aimed`, `auto`): тест лише зі `snap` не відрізняє `fireMode !== null` від `fireMode === 'snap'` (знайшов аудит). Після Т.46 старт авто-бою знімає зведений режим — стану «режим зведено і йде авто-бій» у грі більше немає (у фікстурі `makeFixture(true)` його все ще можна зібрати руками).
- **Гачок драйвера авто-бою** (Т.46; урок — у записі кроку): порядок виклику `onStart` (`src/ui/auto-battle.ts`) тестувати `mock.invocationCallOrder` проти `binfo` і `renderBattle`. Тест на сторінці (`src/main.ui.test.ts`) тримає спільний стан між тестами блоку — новий тест, що запускає авто-бій, ставити останнім у блоці й зупиняти авто-бій під `vi.useFakeTimers()`. У сценарії e2e зведення перед авто-боєм безпечне для дзеркала: стану бою воно не міняє.
- **Перевірка тачу без пристрою** (Т.46; урок — у записі кроку): копія репозиторію, у `playwright.e2e.config.ts` — `hasTouch: true` і свій порт, у сценарії **кожен** `click()` замінити на `tap()` (`sed 's/\.click()/.tap()/g'` — і в помічнику `tap`, і на кнопках); лічильник подій — тимчасовим рядком в обробниках `src/ui/input.ts`. Із самими тапами тап по канві дає `mousemove`, `click`; якщо лишити хоч один клік мишею, після кожного тапу додається `mouseleave` у точці того кліку. У звіт писати «в емуляції».
- **Вихід на стартовий екран і «Продовжити»** (Т.47; урок — у записі кроку): вихід через меню партію і бій із пам'яті не прибирає — лише показує стартовий екран; панель збереження в бою не вантажить (`loadSlot`), тому все, що завантажує сейв поза геосценою, спершу закриває бій (`battle.close()`). Тест на сторінці «сейв завантажено»: між сейвом і перевіркою зробити тік, звіряти годинник і баланс — рядок «Завантажено» в журналі лишається від попередніх тестів блоку; помічник `runAutoBattle()` доводить бій до екрана результату. У сценарії e2e дію, якої дзеркало не повторює (запуск місії перед завантаженням сейву), можна робити лише на сторінці, якщо далі стан повертає завантаження.
- **Вихід на стартовий екран зупиняє все** (Т.48; урок — у записі кроку): `exitToStart` у `src/main.ts` закриває бій (якщо він є) і скидає анімації геосцени; кожну нову дію чи таймер, що живе довше за один клік, перевіряти: чи зупиняє її вихід (спостереження сесії після мержу Т.47 — знахідка аудиту PR #347, у записі Т.47 вона названа лише як вада поза кроком). Зіпсований сейв для тесту: `state.geo.ufos = [null]` проходить перевірку метаданих (`slotMeta`), розбір партії падає; `state = null` чи `ufos = null` ламають і метадані — слот перестає бути останнім, а кнопка «Продовжити» в тесті лишається не вимкненою до наступного `showStart`. Число викликів `AnimEngine.prototype.cancel` (`vi.spyOn`) розрізняє рушій бою і рушій геосцени лише сумою — у тестах на сторінці rAF немає, черги порожні. Гейт e2e «нічого не рухається»: на три секунди підмінити `window.requestAnimationFrame` лічильником (`page.evaluate`) і чекати 0 — ловить цикл бою, геосцени й ambient; перевірку «журнал не змінюється» ставити лише після того, як сценарій дочекався першого рядка авто-бою (він з'являється через ≈ 2 с), і з вікном, довшим за цю паузу (знайшов аудит).
- **Якір поломки з двох сусідніх рядків** (спостереження сесії після останнього пушу Т.48; у записі Т.48 цього немає): ламається, щойно між рядками з'являється третій (у Т.48 — `ambient.pause()` між `geoAnim.cancel()` і `showStart()`); після виправлень за аудитом скрипт поломок перезапускати повністю до коміту — `assert count == 1` це й показує.
- **Виправлення слова в текстах UI** (Т.49; урок — у записі кроку): шукати без першої літери, щоб зловити обидва регістри й відмінки (`grep -rn ерехоплюач src index.html README.md e2e scripts`; збіги в `src/ui/help.test.ts` очікувані — це рядки-запобіжники), і окремо в `docs/glossary.md`; заголовки панелей повторено в розмітці тестів (`src/ui/status-tabs.test.ts`) і в переліках `main.ui.test.ts`; тест-запобіжник — `src/ui/help.test.ts` (довідка і весь `index.html` через `?raw`). Рядок журналу для причини події — у `geoEventText` (`src/ui/journal.ts`); панель перехоплювача бере той самий текст для `#fighter-last`.
- **Вікно поверх бою (спостереження сесії після мержу Т.71):** заборони клавіш в `onKeyDown` мало — плитку у фокусі Enter натискає браузер; фокус переводити у вікно, дії тулбара під вікном глушити, дію після «Так» перевіряти ще раз, вікно закривати в `battle.close` (знахідки 1–2 аудиту Т.71). `#btoolbar button { display: flex }` перекриває атрибут `hidden` — потрібне правило `[hidden]`.
- **`focus()` у jsdom під фейк-таймерами (Т.73, прототип планувальника):** jsdom ставить подію фокусу в чергу через `setImmediate`, і `vi.getTimerCount()` після `focus()` уже не нуль — перевірки «таймерів 0» у `src/main.ui.test.ts` (Т.48, Т.53, Т.55) падали. Сторінкові тести вмикають фейк-таймери з `PAGE_FAKE_TIMERS` (`toNotFake: setImmediate, clearImmediate`). Там само: вікно «Як грати» першого візиту відкрите від завантаження сторінки, і з Т.73 під ним бій не відповідає — хелпер `startParty` спершу закриває його «Грати».
- Гейти: бій — `expectBattleFits(page, мітка, межа)` на 1440 × 900 (740), 1366 × 768 (640), 1024 × 768 (540) і на банері результату; відповіді бою — `endTurnOnPage` в `e2e/acceptance.scenario.ts`; геосцена — крок «геосцена: екран без прокрутки, журнал у вікні» (лише 1440 × 900; розміру iPad там ще немає).
- **Новий рядок журналу — ще й тестом на сторінці (спостереження сесії після мержу Т.75):** юніт-тест чистого перетворювача з заглушкою імені (`battleEventText(e, () => 'Олена')`) не бачить, що на сторінці ім'я береться з іншого місця — у Т.75 рядок писав id евакуйованого (його вже немає в `units`). Перевіряти ще й `#log li`.
- **Пастка фокусу в jsdom (Т.75):** jsdom сам фокус по Tab не рухає — тест має перевіряти `defaultPrevented` на краях кола, інакше зникнення `preventDefault` не ловиться.
- **`focus()` у jsdom заводить `setInterval` (`Window._requestFocusFixup`, пачка 1 PR Vibe, #383):** `PAGE_FAKE_TIMERS` у `main.ui.test.ts` не підробляє ні `setImmediate`, ні `setInterval`. Якщо гра колись почне використовувати `setInterval` — `vi.getTimerCount()` його не побачить.

## Як влаштована розкладка

- **Без прокрутки:** прокрутка сторінки є лише у вікнах, вужчих за 900 px або нижчих за 520 px; у решті прокручуються `#status`, `#focus` і `#log`. У бою (`#layout.in-battle`) колонки `#status` немає; журнал — колонка 320 px (вікно ≥ 1280 px і пропорція ≥ 8:5) або смуга 88 px. Новий блок у колонці чи фокусній зоні висоту сторінки не міняє; новий блок на рівні `#layout` — міняє. Новий блок у панелі бою — у другу колонку сітки панелі з явним рядком (`grid-column: 2; grid-row: N`), у розмітці — після `#binfo`, щоб у вузькому вікні не зсувати поле.
- **Розмір елемента від вільного місця (Т.32):** `container-type: size` на обгортці + `min(100cqw - …, 100cqh)` на елементі; обгортка має рости (`flex` або рядок сітки `1fr`), бо її власний розмір — нуль.
- **Хід демонів у UI (Т.33):** `endPlayerTurn` в `input.ts` застосовує хід синхронно, анімації грають поверх фінального стану; поки демони ходять (`#bturn` показано, класу `done` ще немає), `playerTurnActive()` — хиба і тапи по полю ігноруються. У сценаріях і скриптах після `#btn-end` чекати `#bturn.done` (`endTurnOnPage` в e2e).
- **Межі (Т.32):** вікна нижчі за ≈ 730 px (журнал смугою) і ≈ 640 px (журнал збоку) — плитки вищі за доступне, фокусна зона прокручується; колонка вузла в бою не показується.

- **Шари канви бою** (Т.44, `renderBattle` у `src/ui/battle.ts`): рельєф і туман (`drawNightTerrain`) → сині квадрати висадки → зона ходу (`drawReachZone`) → прев'ю шляху з ціною (`drawPathPreview`) → рамки цілей і зона гранати → юніти → анімації. Контур, зсунутий усередину клітинок, рветься на увігнутих кутах — перевіряти знімком зблизька. Текст на канві: ширину рахувати оцінкою (0,6 em для моноширинного), а не `measureText` — його немає в мок-контексті тестів.
