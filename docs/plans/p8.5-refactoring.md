**Версія:** 1.0

**Автор:** Vibe Code  
**Статус:** Заплановано

---

## Контекст

Згідно ADR-0044 (Процес рефакторингу) та аналізу поточного стану проєкту (p8.1-p8.4 завершені), необхідно провести рефакторинг архітектури проєкту для покращення підтримки, тестованості та модульності коду.

**Залежності:** п8.1, п8.2, п8.3, п8.4
**ADR:** ADR-0044 (Процес рефакторингу)

---

## Мета

Покращити модульність та підтримуваність коду через:
1. Виділення чистої логіки ядра (core) без DOM
2. Локальний рефакторинг модулів
3. Модульний рефакторинг системи
4. Глобальний рефакторинг архітектури

---

## Етапи рефакторингу

### 1. Локальний рефакторинг (п8.5.1)

**Meta:** Покращити читабельність та тестованість окремого модулю
**Область:** `src/core/combat.ts`
**Ризики:** Мінімальні

#### План:
1. Створити тести для функції `calculateDamage()`
2. Замінити виклики на нову функцію
3. Перевірити, що всі тести проходять
4. Видалити стару функцію

#### Критерії прийняття:
- [ ] Усі тести проходять (`npm test`)
- [ ] Покриття не знизилося
- [ ] Код став більше зрозумілим
- [ ] Покращено типобезпечність

---

### 2. Модульний рефакторинг (п8.5.2)

**Meta:** Покращити модульність та організацію коду в межах `src/core/`
**Область:** `src/core/*.ts`
**Ризики:** Середні

#### План:
1. Створити новий модуль `src/core/utils.ts`
2. Перенести спільні функції
3. Оновити імпорти в інших модулях
4. Видалити дублювання коду
5. Перевірити всі тести

#### Критерії прийняття:
- [ ] Усі тести проходять
- [ ] Покриття ≥ 80%
- [ ] Код став більш модульним
- [ ] Зменшилася дублювання

---

### 3. Глобальний рефакторинг (п8.5.3)

**Meta:** Полна реорганізація архітектури проєкту
**Область:** Вся кодова база
**Ризики:** Високі

#### План:
1. Виділити чисте ядро (core) без DOM
2. Перенести UI логіку в `src/main.ts`
3. Створити чіткий розподіл між core та UI
4. Оновити всі тести
5. Перевірити роботу demo-боту

#### Критерії прийняття:
- [ ] Усі тести проходять
- [ ] Покриття ≥ 80%
- [ ] Архітектура стала чіткішою
- [ ] Demo-бот працює коректно

## Наслідки

### Переваги
1. **Контрольований процес** - Рефакторинг відбувається поступово
2. **Середній ризик** - Кожен етап має свої ризики, але вони контрольовані
3. **Покращена підтримка** - Код стає більш зрозумілим та підтримуваним
4. **Краща тестованість** - Покриття тестами не знижується

### Недоліки
1. **Час** - Рефакторинг вимагає часу
2. **Складність** - Високі ризики при глобальному рефакторингу
3. **Координація** - Потрібна чітка координація між етапами

---

## Рішення

1. **Контрольований процес** - Рефакторинг проводити поступово
