### пR.2: Розбірка main.ts (ADR-0037; модульний рефакторинг ADR-0044)

**Мета:** main.ts → точка входу ≤ 200 рядків; UI-логіка — у модулі `src/ui/*` ≤ 500 рядків кожен.
**Область:** `src/main.ts`, нові `src/ui/*.ts`, `src/main.ui.test.ts` (лише перенесення/імпорти).
**Ризики:** середні (багато неявних зв'язків через модульні `let`-стан і слухачі DOM).
**Мітигація:** винесення від найбільш ізольованих блоків (демо-драйвер, збереження, журнал) до зв'язаних (бойовище, ввід); стан UI — явний об'єкт стану, що передається, замість глобальних `let`.

Послідовність PR (кожен ≤ 500 рядків зміни, тест-гейт між ними):
1. `src/ui/demo.ts` — покрокове демо (DemoSteps-драйвер, demoNext/demoPause/demoStop/demoBattle).
2. `src/ui/save-panel.ts` — слоти збереження (store, detectStorage, renderSavePanel, save/load/deleteSlot).
3. `src/ui/journal.ts` — журнал: drain*/EventText-перетворювачі, setLogFilter.
4. `src/ui/panels.ts` — рендери колонки стану і топбара (renderGeo/renderUfos/renderFighter/renderFinances/renderRoster/renderInterceptCtx + чипи).
5. `src/ui/battle.ts` — бойовище і флоу бою (renderBattle, launch/close/finish, checkOutcome, binfo).
6. `src/ui/input.ts` — ввід (battleCanvasClick/Hover/Leave, armFire, armOverwatch, endPlayerTurn, onKeyDown, cellFromPoint/Event).
7. `src/main.ts` — точка входу: init, partyTick, renderAll, зв'язування модулів.

EARS-критерії:
- Якщо PR змінює понад 500 рядків, то він розрізаний на серію PR (ADR-0036).

**Виконання (2026-10-15, пR.2 завершено):** усі 7 модулів винесено (серія PR #70–#79; код і тести — окремі PR за прецедентом #73/#74, тести стек-гілками). main.ts: 1500 → 319 рядків (init, partyTick, renderAll, зв'язування). Відхилення від мети «≤ 200»: без app-шару, якого нема в ADR-0037, точка входу далі не стискається — подальше стиснення лише за окремим рішенням власника. Деталі — рядок пR.2 у docs/workflow.md.
- Якщо модуль винесено, то `main.ui.test.ts` проходить без ослаблення тверджень (імпорти/перенесення допустимі).
- Якщо користувач виконує smoke-сценарій ADR-0030, то поведінка не відрізняється від main до рефакторингу (лог байт-у-байт).

### пR.3: Розділення render.ts/bot.ts (ADR-0038; глобальний рефакторинг ADR-0044)

**Мета:** чиста логіка відображення відділена від Canvas-викликів; логіка бота — без UI-інтеграції.
**Область:** `src/render.ts` → `src/core/render-core.ts` (перетворення стану → примітиви малювання, спрайт-матриці, AnimEngine-стан/анімаційні кадри — без Canvas API) + `src/render.ts` (лише Canvas-виклики); `src/bot.ts` → чиста логіка рішень/симуляцій + тонка UI-інтеграція у шарі відображення.
**Ризики:** високі (торкається рендера і тестів render.test.ts — 1049 рядків тестів).
**Мітигація:** спершу перенести чисті обчислення кадрів, Canvas-виклики лишати як тонку обгортку; тести рухати разом із кодом.

EARS-критерії:
- Якщо `render-core` імпортується, то він не містить жодного посилання на Canvas/DOM API (ADR-0002/0038).
- Якщо тести перенесено, то сумарне покриття не знизилось (ADR-0017; codecov/patch ≥ 95%, ADR-0034).
- Якщо прогнано демо-бій, то анімації і кадри байт-у-байт незмінні.
