## Відповідь власника (16.11.2026, до реалізації)

Питання 1: «Т.53 «Меню й авто-бій». Зараз кнопка «Меню» під час авто-бою нічого не зупиняє: бій іде далі під вікном меню і під вікном «Незбережені зміни». Що має робити відкриття меню під час авто-бою?». Відповідь: **«Зупиняти»** (варіант: «Відкриття меню діє як «Стоп»: авто-бій зупинено, після закриття меню гравець керує вручну або знову тисне «Авто»»).

Питання 2: «З меню відкриваються ще вікна «Налаштування» і «Як грати» (меню при цьому закривається). Чи діє на них те саме правило?». Відповідь: **«Так, усі вікна»** (варіант: «Меню, «Незбережені зміни», «Налаштування» і «Як грати» — авто-бій не йде під жодним із них»).

У звіті, записі кроку й описі PR рішення власника цитувати **лише з цього розділу, дослівно**. Іншого власник не казав: нових цитат не складати, слова не переставляти.

Рішення планувальника (не власника): нового тексту в `#binfo` після зупинки немає — поведінка та сама, що в плитки «Стоп»; кнопка «?» у шапці (`#btn-help`) теж зупиняє авто-бій, бо відкриває «Як грати» напряму, без меню.

## Що зробити

### 1. Код: `src/main.ts`, блок `if (typeof document !== 'undefined')`

Що є зараз (перевірено по коду на `main` = `d0b1e4a`):

- рядок 680: `el('btn-help').onclick = help.open;`
- рядок 704: `el('btn-menu').onclick = () => screens?.openMenu();`
- вікна «Незбережені зміни» і «Налаштування» під час бою відкриваються лише з меню (`src/ui/screens.ts`), «Як грати» — з меню і кнопкою `#btn-help`; тож зупинки на цих двох кнопках досить для всіх чотирьох вікон;
- `autoBattle.stop()` чергу анімацій не скидає: анімація поточної дії догравається — так само, як після плитки «Стоп».

Що додати. Перед рядком 680 — функцію, дослівно:

```ts
  // Т.53 (рішення власника 16.11.2026 «Зупиняти»): вікно поверх бою зупиняє авто-бій, як «Стоп»
  const stopAutoForWindow = (): void => {
    if (!autoBattle.busy) return;
    autoBattle.stop();
    battle.renderBattle();
  };
```

Рядок 680 замінити на:

```ts
  el('btn-help').onclick = () => {
    stopAutoForWindow();
    help.open();
  };
```

Рядок 704 замінити на:

```ts
  el('btn-menu').onclick = () => {
    stopAutoForWindow();
    screens?.openMenu();
  };
```

Більше в `src/main.ts` нічого не міняти. `src/ui/screens.ts`, `src/ui/help.ts`, `src/ui/settings.ts`, `src/ui/auto-battle.ts`, `src/ui/battle.ts` не чіпати. Планувальник перевірив цю зміну прототипом: `npx tsc --noEmit`, `prettier --check src/main.ts`, усі 88 тестів `src/main.ui.test.ts` і сценарій e2e — зелені.

### 3. Наскрізний тест на сторінці: `src/main.ui.test.ts`

Новий блок `describe('Т.53: меню і «Як грати» зупиняють авто-бій', …)` у кінці файла, після блоку Т.51 (блоки тримають спільний стан — у чужі не вставляти). Один тест `it`, назва починається з «Т.53».

У блоці — помічник: `const cap = (): string => (document.querySelector('#btn-auto-battle .tb-cap') as HTMLElement | null)?.textContent ?? '';`

Сценарій (сід 27, пресет «норма»; перевірено планувальником на сторінці в jsdom: кнопка місії з'являється, коли годинник `#clock` показує `Д1 09:00`; до зміни коду тест червоний на пункті 4 — `expected 'Стоп' to be 'Авто'`, після зміни зелений):

1. `startParty('27')`; клікати `btn('btn-tick')`, доки `document.querySelector('button.mission')` дорівнює `null` (запобіжник — не більше 1500 кліків); клікнути кнопку `button.mission`; `#battle-panel` не має класу `hidden`.
2. `vi.useFakeTimers()` у `try`, у `finally` — `vi.useRealTimers()` (зразок — тест «Т.48: авто-бій, запущений до виходу…» у цьому ж файлі).
3. Клік `btn('btn-auto-battle')`; `await vi.advanceTimersByTimeAsync(AUTO_STEP_MS * 3)`; `cap()` дорівнює `'Стоп'`.
4. Клік `btn('btn-menu')`: `#game-menu` без класу `hidden`; `cap()` дорівнює `'Авто'`; `vi.getTimerCount()` дорівнює `0`.
5. Запам'ятати `$('log').textContent`; `await vi.advanceTimersByTimeAsync(AUTO_STEP_MS * 50)`; текст `#log` той самий.
6. Клік `btn('btn-menu-close')`; ще `AUTO_STEP_MS * 50`; текст `#log` той самий; `$('bresult').textContent` дорівнює `''` (бій не завершено).
7. Клік `btn('btn-auto-battle')` (знову «Авто»); `AUTO_STEP_MS * 3`; `cap()` дорівнює `'Стоп'`; текст `#log` уже інший, ніж запам'ятаний.
8. Клік `btn('btn-help')`: `#help-screen` без класу `hidden`; `cap()` дорівнює `'Авто'`; `vi.getTimerCount()` дорівнює `0`. Клік `btn('btn-help-close')`.
9. Без авто-бою: запам'ятати `$('binfo').textContent`; клік `btn('btn-menu')`, клік `btn('btn-menu-close')`; текст `#binfo` той самий.

**Тексти UI в тесті — рядковими літералами** `'Стоп'` і `'Авто'`, скопійованими з цього плану і звіреними побайтно з `src/ui/toolbar.ts` і `src/ui/battle.ts`. Функцій, що будують текст, у тест не імпортувати.

Якщо момент появи місії на сторінці інший — це не помилка плану: важливий результат пунктів 4–8. Якщо сценарій не відтворюється взагалі — запасний сід: 42. Запобіжник наосліп не збільшувати: розібратись і записати у звіт.
