# Шаблон плану кроку для Mistral Vibe Code

Шаблон для агента, що планує крок, який виконає інший агент (Mistral Vibe Code). Зібраний із планів і записів Т.39 і Т.51 та довідника `docs/agents/common.md` (розділ «Крок, який виконує інший агент»); уточнений за кроками Т.53 і Т.55 (Т.56), за Т.58 та залишками Т.58 (Т.60), за Т.61 (Т.63), за Т.64 (Т.65) і за Т.66 (Т.67). Це не правило: правила — `AGENTS.md`, `docs/workflow.md` і ADR.

**Як користуватись.** Скопіювати файл у `docs/plans/tNN-<суть>.md`, прибрати цей вступ і розділи «Перед тим як віддати план» та «Після PR», заповнити все в кутових дужках `<…>` і прибрати підказки курсивом. Те, що заповнює виконавець (числа, результати, час), — місцем з назвою кирилицею, наприклад `<число рядків>`, а не голим `<…>` (Т.63; чому — пункт перевірок нижче). Одне місце — одне значення; одиницю каже назва місця, а після місця в тексті ні одиниці, ні слова, яке виконавець і сам допише, немає: `<тривалість прогону з одиницею>`, а не `<тривалість прогону> хв` (Т.65; чому — пункт перевірок нижче). Чого виконавець не вирішує — таблицю поломок, підсумки, числа, рядки чекліста і звірки, слова «немає» і «нічого» — у блоках теж місцем, але заповнює його скрипт плану (`docs-py`, `check-py`), а не виконавець (Т.67; пункти перевірок нижче). Розділи плану не викидати: якщо розділ не потрібен — лишити заголовок і написати «немає». План — перший коміт гілки кроку.

**Готові блоки (Т.60).** Усе, що виконавець додає дослівно — рядки коду з коментарями, тест, готовий текст документів, опис PR, — у плані лише блоками: рядок-позначка `<!-- блок: ім'я -->` і огорожа одразу після неї (` ```ts ` для коду, ` ```text ` для тексту; якщо всередині є огорожа — зовнішня з чотирьох зворотних лапок). Блоки вирізає один скрипт — і для виконавця, і для прототипу планувальника: `node scripts/vibe-plan-blocks.mjs <план> /tmp/blocks` пише кожен блок у `/tmp/blocks/<ім'я>.txt` (вміст огорожі без кінцевого переносу рядка) і відмовляє (код 1), якщо позначку написано з помилкою чи без огорожі, ім'я повторюється або має щось, крім латинських літер, цифр, `.`, `_` і `-`. Старих файлів у теці скрипт не видаляє — брати нову або порожню теку. Вказівки виконавцеві — поза блоками: усе всередині блоку він переносить дослівно, усе поза ним — ні.

```python
    print(rows[-1], flush=True)

cols = [c for c, _ in ALONE + WHOLE]

# Підсумок друкує скрипт — виконавець його не переказує (Т.64, знахідка 1)

print(summary)
# Перевірки без поломки: рядок з expect( у блоці нових тестів, на якому тест не впав на жодній поломці (Т.66, знахідки 3 і 4)

    for k in free:
        f.write('- рядок ' + str(k) + ': ' + block[k - FIRST].strip() + '\n')
    f.write('Перевірок без поломки немає.\n' if not free else 'Перевірок без поломки — ' + str(len(free)) + '.\n')
print(open(TMP + '/expects.md', encoding='utf-8').read(), end='')
```

## Обмеження

- **Розмір:** оцінка — <число> рядків коду і <число> рядків тестів, <один PR | серія з K PR>. <Якщо власник схвалив плановане перевищення 500: «відхилення записано тут, один PR, мітку `size-deviation` ставить виконавець (ADR-0061, ADR-0077)».> Інакше: якщо виходить понад <поріг> рядків — написати про це в сесії до того, як продовжувати; без запису про відхилення в цьому плані мітку `size-deviation` не ставити.
- **Не чіпати:** <файли і теки>.
- У доданих рядках (код, коментарі, тести, документи) немає трансліту — лише кирилиця.
- Тести не послаблювати, щоб пройшли.
- Історію не переписувати (без amend, rebase, force-push).
- **Працювати короткими кроками:** одна правка — одна перевірка — коміт. Великий документ писати частинами, а не обмірковувати цілком.

## Чекліст перед PR

`npx tsc --noEmit`, `npx tsc --noEmit -p tsconfig.core.json`, `npx tsc --noEmit -p tsconfig.e2e.json`, `npm run lint`, `npm run format:check`, `npm test`, `npm run docs`, `npm run test:e2e`.

Команди запускає скрипт `checklist-py` — по одній за запуск (команда, довша за 10 хв, у пісочниці обривається), на коміті тесту, до `docs.py`: скопіювати `/tmp/blocks/checklist-py.txt` у `/tmp/t<NN>/checklist.py`, далі `python3 /tmp/t<NN>/checklist.py tsc`, потім так само з ключами `tsc-core`, `tsc-e2e`, `lint`, `format`, `test`, `docs`, `e2e`, і наостанок без ключа — `python3 /tmp/t<NN>/checklist.py`: він зводить результати у `/tmp/t<NN>/checklist.md` (рядок на команду — Т.66, знахідка 9) і `/tmp/t<NN>/failed.md` («нічого» або перелік). У звіт і опис PR обидва файли вставляє `docs-py`; результатів руками не писати. Вивід команди, що не пройшла, — у `/tmp/t<NN>/checklist/<ключ>.log`.

<Одне з двох. Крок не зачіпає сценарій e2e (`e2e/` і те, що він клікає):> на e2e в пісочниці — **не більше 10 хвилин** (підготовка браузера — у розділі «Лише для Mistral Vibe Code» довідника; скрипт сам обриває команду на дев'ятій хвилині); не піднявся або падає так само на чистому `origin/main` — скрипт запише це рядком «не пройшла», написати про причину в сесії і йти далі: сценарій прожене CI (це вказівка, а не результат: про результати чеків CI не писати, розділ «PR»). <Крок зачіпає сценарій e2e: e2e обов'язковий (`AGENTS.md`); планувальник пише тут, як виконавець його проганяє і що робити, якщо пісочниця не дає.>

Після коміту документів, перед `check.py`: `git diff origin/main...HEAD -- . ':(exclude)docs/plans/' | grep -n '^+.*не має'` нічого не знаходить («немає» — одним словом; якщо знайшло — це рядок, набраний руками: виправити новим комітом).

*Каркас скрипта чекліста: планувальник заповнює один рядок (`TMP`), проганяє на прототипі і кладе в план блоком `checklist-py`, а цю підказку прибирає.*

<!-- блок: checklist-py -->
```python

import os, subprocess, sys

TMP = '/tmp/t<NN>'
LIMIT = 540  # секунд на команду: у пісочниці виконавця команда, довша за 10 хв, обривається

    ('tsc-core', 'npx tsc --noEmit -p tsconfig.core.json'),

    ('lint', 'npm run lint'),
    ('format', 'npm run format:check'),
    ('test', 'npm test'),
    ('docs', 'npm run docs'),
    ('e2e', 'npm run test:e2e'),
]

os.makedirs(DIR, exist_ok=True)

if len(sys.argv) == 2:

    with open(DIR + '/' + key + '.log', 'w', encoding='utf-8') as f:
        f.write(log)
    with open(DIR + '/' + key + '.txt', 'w', encoding='utf-8') as f:
        f.write(head + '\n' + result + '\n')
    print('`' + command + '` — ' + result)
    sys.exit(0)

assert len(sys.argv) == 1, 'один ключ за запуск або жодного'
rows, failed = [], []
for key, command in COMMANDS:
    path = DIR + '/' + key + '.txt'
    assert os.path.exists(path), 'команду ще не запущено: python3 ' + TMP + '/checklist.py ' + key
    with open(path, encoding='utf-8') as f:

    assert at == head, 'результат `' + command + '` — з коміту ' + at + ', а зараз ' + head + ': запустити ще раз'
    rows.append('- `' + command + '` — ' + result)
    if result != 'пройшла':

with open(TMP + '/checklist.md', 'w', encoding='utf-8') as f:
    f.write('На коміті `' + head + '`:\n\n' + '\n'.join(rows) + '\n')
with open(TMP + '/failed.md', 'w', encoding='utf-8') as f:
    f.write(('\n'.join(failed) if failed else 'нічого') + '\n')
print('\n'.join(rows) + '\nЩо не вдалося: ' + ('\n'.join(failed) if failed else 'нічого'))
```

## PR

- Гілка — ця сама: `<тип>/t<NN>-<суть>` (план уже в ній першим комітом). Комітити в неї, Conventional Commits українською. Назву коміту, яку дає план блоком `commit-…`, не набирати: `git commit -F /tmp/blocks/<ім'я блоку>.txt` (Т.64: назву з плану переписано зі спотворенням). **Помилку в коміті виправляти новим комітом, а не `git commit --amend`** — і до пушу теж (Т.66, знахідка 2).
- **Документи кроку закомітити до відкриття PR** (звіт, запис кроку, рядки довідника): перед `gh pr create` команда `git log --oneline origin/main..HEAD` показує коміт із ними.
- PR у `main`, **не чернеткою**. Назва — **дослівно**: `<тип>(<область>): Т.<N> — <назва>`; не набирати — вона ж у блоці `pr-title`.

<!-- блок: pr-title -->
```text
<тип>(<область>): Т.<N> — <назва>
```

- Опис PR — **увесь** блоком `pr-body`; місця в ньому заповнюють скрипти: `docs-py` — `<рядки чекліста>`, `<речення з summary.md>`, `<розбіжності з таблицею плану>`, `<число рядків>` (виходить чернетка `/tmp/t<NN>/pr-body-draft.md`), `check-py` — `<рядки vibe-plan-check>` (виходить `/tmp/pr-body.md`). Місць для виконавця в блоці немає; готовий опис руками не правити. Рядок `Iter-Tag` — з початку рядка, без відступу. Розділів понад ці не додавати; розділ «Аудит» до аудиту каже «Аудит ще не проведено», після аудиту його текст дає планувальник.

<!-- блок: pr-body -->

- Перед відкриттям PR, коли документи кроку вже закомічено, — звірка з планом разом із готовими назвою й описом; її запускає скрипт `check-py` і сам вставляє в опис рядки «Звірено» і «Знахідок» дослівно (Т.66, знахідка 7: рядок «Звірено» в описі було переказано): скопіювати `/tmp/blocks/check-py.txt` у `/tmp/t<NN>/check.py`, далі `python3 /tmp/t<NN>/check.py`. Скрипт друкує весь вивід звірки. Кожну знахідку виправити (правка файла — новим комітом, потім `docs.py`, якщо мінявся код чи тест, і знову `check.py`) або написати про неї в сесії з причиною — в опис її внесе планувальник.

*Каркас скрипта звірки: планувальник заповнює два рядки (`TMP` і `PLAN`), проганяє на прототипі і кладе в план блоком `check-py`, а цю підказку прибирає.*

<!-- блок: check-py -->
```python

# скрипт вставляє в опис сам, дослівно. Запуск з кореня репозиторію після коміту документів:
#   python3 /tmp/t<NN>/check.py                 — з чернетки /tmp/t<NN>/pr-body-draft.md робить /tmp/pr-body.md
#   python3 /tmp/t<NN>/check.py --pr <номер>    — після відкриття PR: звіряє назву й опис самого PR
import subprocess, sys

TMP, B, V = '/tmp/t<NN>', '/tmp/blocks/', ''  # у порції після аудиту: V = '-v2', назва PR — з /tmp/blocks/, як і була

BODY = '/tmp/pr-body' + V + '.md'
PLACE = '<рядки vibe-plan-check>'


def read(path):
    with open(path, encoding='utf-8') as f:
        return f.read().rstrip('\n')


def check(args):
    done = subprocess.run(['node', 'scripts/vibe-plan-check.mjs', '--plan', PLAN, *args], capture_output=True, text=True)
    assert done.returncode in (0, 1), done.stdout + done.stderr  # 0 — знахідок немає, 1 — є; інше — помилка запуску
    tail = [line for line in done.stdout.split('\n') if line.startswith('Звірено:') or line.startswith('Знахід')]
    assert len(tail) == 2, done.stdout
    return done.stdout, '\n'.join('    - ' + line for line in tail)


if '--pr' in sys.argv:
    out, lines = check(['--pr', sys.argv[sys.argv.index('--pr') + 1]])
    print(out, end='')
    print('Рядки звірки в описі PR ті самі.' if lines in read(BODY) else 'Рядки звірки інші, ніж в описі PR: написати про це в сесії, опис не правити.')
    sys.exit(0)

draft = read(TMP + '/pr-body-draft.md')
assert draft.count(PLACE) == 1, 'у чернетці опису немає місця для рядків звірки — спершу docs.py'
title = read(B + 'pr-title.txt')
lines = '    - (рядки звірки)'
for _ in range(3):  # опис із вставленими рядками звіряється ще раз: рядки в описі — ті, що дав останній запуск
    with open(BODY, 'w', encoding='utf-8') as f:
        f.write(draft.replace(PLACE, lines) + '\n')
    out, new = check(['--title', title, '--body-file', BODY])
    if new == lines:
        break
    lines = new
else:
    raise AssertionError('рядки звірки не усталились за три запуски')
print(out, end='')
print(BODY + ' готовий; назва PR — у ' + B + 'pr-title.txt')

```

- Відкрити PR готовими файлами: `gh pr create --base main --title "$(cat /tmp/blocks/pr-title.txt)" --body-file /tmp/pr-body.md` — без `--draft`. Одразу після цього — `gh pr view <номер> --json isDraft`: має бути `{"isDraft":false}`; якщо `true` — `gh pr ready <номер>` (Т.66, знахідка 1: PR відкрито чернеткою).
- Після відкриття — ще раз звірка, вже самого PR: `python3 /tmp/t<NN>/check.py --pr <номер>`. Якщо рядки звірки інші, ніж в описі, — **нового коміту не робити і опис не правити**, а написати про це в сесії: коміт одразу після відкриття PR скасовує перший прогін чеків, а аудитор, запущений на PR, читає вже не останній коміт (Т.55).
- Після відкриття PR — коротко відповісти в сесії: номер PR, вивід `gh pr view <номер> --json isDraft`, останній рядок `check.py --pr`, вміст `/tmp/t<NN>/failed.md` і перелік «пункт плану — зроблено / ні» з доказом `grep` на кожен рядок «зроблено». Скільки часу зайняв крок, не писати: час рахує планувальник. **Не мержити.**
- **Після відкриття PR — нічого не пушити, доки планувальник не дасть знахідок:** ні документів, ні чисел, ні виправлень. **Про аудит і результати чеків CI нічого не писати** — ні в документах, ні в описі PR: зелені чеки і коментар джоби `mistral-audit` — не аудит кроку, а коротка джоба на зміну опису (≈ 11 с) аудиту не робить зовсім. Розділ «Аудит» лишається «Аудит ще не проведено», доки його текст не дасть планувальник (Т.61: два коміти з документами після відкриття PR і «аудит» з короткої джоби, записаний як пройдений).

## Після PR (для планувальника; у план не йде)

- **Підказка для запуску сесії виконавця:** «Перемкнись на гілку `<гілка>`, прочитай `docs/plans/t<NN>-<суть>.md` і виконай план. Готові блоки вирізай `node scripts/vibe-plan-blocks.mjs`, руками не набирай. Коміть у цю гілку, відкрий PR у `main`, не мерж. Історію не переписуй: без amend, rebase і force-push — помилку в коміті виправляй новим комітом. Після відкриття PR нічого не пушити і нічого не писати про аудит і чеки CI — чекай повідомлення зі знахідками. Працюй короткими кроками.» Час запуску сесії записати одразу (година і хвилина за своїм годинником): час кроку у звіт пише планувальник (Т.66: amend коміту документів до пушу і час кроку не за фактом — знахідки 2 і 5).
- **Одразу після появи PR** — коротке повідомлення в сесію виконавця: «PR бачу. Нічого не пуш і не пиши про аудит — чекай знахідок» (Т.61: без нього виконавець запушив два коміти з документами).
- **Час кроку — за годинником планувальника** (Т.67): від запуску сесії виконавця до `created_at` PR (`gh api repos/sergkarpenko/rubezh/pulls/<номер> --jq .created_at`, UTC); одним значенням з одиницею і з обома моментами в дужках — у блок `report-v2`, у рядок «Час від запуску сесії до відкриття PR» (зразок — блок `report-v2` плану `docs/plans/t66-fighter-last-mission.md`).
- **Чернетка:** одразу після появи PR — `gh api repos/sergkarpenko/rubezh/pulls/<номер> --jq .draft`; `true` — у першому ж повідомленні попросити `gh pr ready <номер>` (Т.66, знахідка 1; у чеклісті виконавця ця перевірка тепер є — розділ «PR» плану).
- **Старт:** за 5 хв немає жодного виклику інструмента — перезавантажити сторінку, одна нова сесія, завислі зупинити, одне питання власникові, хто пише код (Т.43, Т.44).
- **Аудиторові для мержу** дати копію репозиторію і попросити запустити тести й гру (Т.39). Запускати через ≈ 5 хв після появи PR, коли `git diff --stat` гілки вже показує документи кроку: до Т.63 виконавець пушив ще один коміт одразу після відкриття PR (Т.53; у Т.55 — через ≈ 2,5 хв за часом прогонів CI; у Т.61 — два коміти), і заборона в плані цього може не втримати; інакше — дати аудиторові команду оновити копію перед читанням.
- **Звірка з прототипом:** `git diff origin/main...<гілка PR> -- . ':(exclude)docs/plans/'` проти збереженого `/tmp/proto.diff` — рядки `^[-+]` (залишки Т.58: збіг побайтний). Очікувані розбіжності — лише місця `<…>`, які заповнив виконавець; решта — перша порція знахідок.
- **Правку плану чи власних рядків** планувальник комітить у ту саму гілку перед порцією знахідок; перший пункт повідомлення виконавцеві — «спершу `git pull`» (Т.55).
- **Порції після аудиту — комітом у план** (зразок — `docs/plans/t61-victory-note-e2e.md`): у кінець плану розділ другого рівня, чия назва починається словами «Після аудиту» (`## Після аудиту: порції (…)`) — за цією назвою `vibe-plan-check.mjs` переходить у стан «після аудиту» (Т.62) і показує «Аудит ще не проведено», що лишилось у звіті чи описі PR. У розділі — порції третього рівня (`### Порція 1 — …`), у кожній вказівки поза блоками і блоки з суфіксом `-v2` (`test-t<NN>-v2`, `mutations-py-v2`, `report-v2`, `record-v2`, `pr-body-v2`): імена не повторюють блоків основної частини плану, інакше вирізач відмовить. Виконавець вирізає їх у нову теку (`node scripts/vibe-plan-blocks.mjs <план> /tmp/blocks2`), щоб блоки `-v2` не змішались зі старими. Назва коміту кожної порції — теж блоком (`commit-1-v2`, `commit-2-v2`…), коміт — `git commit -F /tmp/blocks2/commit-1-v2.txt` (Т.64: назву коміту порції 1 виконавець набрав руками — «стандарт драйвера» замість «стан драйвера», коміт `3b1ecab`). Блок `pr-body-v2` — увесь опис PR із готовим розділом «Аудит»: виконавець копіює його в `/tmp/pr-body-v2.md`, заповнює місця і подає `gh pr edit <номер> --body-file /tmp/pr-body-v2.md`; у порції — «спершу опис, потім пуш»; пуш один, наприкінці останньої порції. Усі порції — одним комітом у план (у Т.61 — так); виконавцеві — повідомленням «роби порцію K» після коміту попередньої. Документи в порції збирають ті самі скрипти: блоки `table-plan-v2`, `limits-v2`, `report-v2`, `record-v2`, `pr-body-v2`, а `docs-py-v2` і `check-py-v2` — каркаси розділів 5 і «PR» з `B = '/tmp/blocks2/'` і `V = '-v2'` (запис кроку, що вже є у файлі, `docs-py` замінює цілком); місць-слів для виконавця в порціях теж немає (Т.66: третя мала порція пішла лише на повторне «не має»). Пуш коміту з порціями запускає прогін Mistral на стані до порцій — такий коментар не розбирати (довідник, розділ «Аудит кроку»).
- **Знахідки аудиту — порціями по три-чотири**, документи (звіт, запис кроку, довідник) з числами — окремою порцією наприкінці, з числами аудиторів і переліком «підтверджені / відхилені» готовим текстом розділу «Аудит» — блоками розділу «Після аудиту» плану (пункт вище), вказівки поза ними (Т.53, Т.55: ≈ 8–10 хв, один пуш). Порція документів — теж по 3–4 пункти (Т.58: порцію з дев'яти пунктів виконано наполовину без слова про пропущене). Кожна порція закінчується проханням дати перелік «пункт — зроблено / ні» з доказом `grep`; наступну порцію («роби порцію K») давати після коміту попередньої. У Т.51 десять знахідок одним повідомленням виправлялись довше, ніж робився сам крок. Ціна порцій: кожен пуш — прогін чеків і джоби `mistral-audit`; щоб не множити прогони, просити комітити кожну порцію, а пушити раз, після останньої.
- **Хід закінчився посеред порції** (Т.66): через ≈ 5 хв після кожної порції — знімок низу вікна сесії; якщо біля поля вводу немає квадрата «Стоп», а коміту й підсумку порції ще немає — одне повідомлення «продовжуй порцію з пункту N».
- **«Thinking» без дій понад 20 хв:** зупинити хід і написати «продовжуй короткими кроками»; хто доробляє, якщо не допомогло, — питання власникові.
- **Перевірка виправлень** — власними прогонами чекліста і навмисних поломок, а не за звітом виконавця; назву PR, цитати власника, розділи звіту і терміни звіряє `node scripts/vibe-plan-check.mjs --plan <план> --pr <номер>` (Т.54; що скрипт бачить і чого ні — у звіті `docs/reports/t54-vibe-plan-check.md`).
