# Робочий процес «Рубіжу» (AI-native SDLC)

Конвенції розробки для власника і ШІ-агентів (Vibe Work / Vibe Code). Журнал статусу і план — тема знань «Рубіж» у Vibe Work; джерело правди коду і рішень — цей репозиторій.

## Принципи

1. Одна сесія ≈ один вузький крок: одна ітерація або її частина (свідоме рішення власника — не розганяти довгий контекст).
2. Кожна ітерація: ШІ готує → перевірка в пісочниці → людина валідує → фіксація (коміт + тег + тема знань).
3. Чисте ядро `src/core/` без DOM/Canvas; відображення — окремий шар (`src/main.ts`, ADR 0010).

## Цикл зміни ядра

1. Початок сесії: прочитати тему знань «Рубіж» цілком — статус, рішення, конвенції; взяти пункт з «Наступних кроків» (або вказаний власником).
2. Пісочниця: перевірити логіку сценаріями-перевірками до коміту. Інваріанти: детермінізм (один сід + дії = той самий лог), `geo.rng` не витягається, перма-смерть наскрізна.
3. Тести: сценарії-перевірки перенести у vitest (`*.test.ts`), звірити тести з реалізацією до пушу.
4. Коміт у main — Conventional Commits, повідомлення українською: `feat(core):`, `fix(core):`, `fix(test):`, `docs:`, `docs(adr):`, `chore(ci):`.
5. Пуш → CI: `npm test` → `vite build` → deploy Pages. Червоний CI = стоп; фіксити до продовження. Оновлюється превью: https://sergkarpenko.github.io/rubezh/
6. Exact-байти: після пушу через пісочницю звірити вміст файлів у репо — екранування могло пошкодити вміст.
7. Валідація людиною: сторінка з жорстким оновленням (Ctrl+Shift+R); помилки з консолі — скріншотом, фіксити наступною сесією.
8. Тег `iter-X.Y` на останньому коміті ітерації (після валідації людиною).
9. Кінець сесії: оновити тему знань — статус ітерацій, рішення, уроки.

## Теги ітерацій

- Формат: `iter-X.Y` (наприклад `iter-5.2`); нечислові кроки — `iter-P` (превью), `iter-D` (документація).
- Код ітерацій 0–5.1 потрапив у репо одним комітом — окремих тегів на ті ітерації не буде. Стартові теги:
  - `iter-5.1` → `86dae5d` (перенос ітерацій 0–5.1)
  - `iter-5.2` → `e1de497` (ростер загону)
  - `iter-P` → `4c9cf0a` (превью, валідовано людиною)

## Уроки (фіксуємо, щоб не повторювати)

- Локальне середовище: з 2026-10-13 встановлено Node.js (Homebrew) — `npm test` запускати локально перед пушем (підтверджено: 96/96). Правило: якщо локально бракує інструмента (node, npm тощо) — одразу повідомити власника, не мовчки обходити.
- Тести до першого ранта CI не запускалися — CI упав на 3 багах тестів. Правило: звіряти тестові файли з реалізацією до пушу; CI — останній рубіж, а не перший.
- Template literals у файлах, що пишуться через пісочницю, екрануються з помилками (Syntax error у тесті детермінізму). Правило: у таких файлах — конкатенація рядків.
- TDZ на рівні модуля (виклик `newParty` до оголошення `let`) убив весь main.ts: сторінка «напівжива», помилка лише в консолі. Правило: виклики — після оголошень; при порожній сторінці дивитися консоль.
- Автопрогравання ШІ на таймерах (setTimeout у useEffect) у React-віджеті зависало; синхронний цикл в обробнику кнопки — надійніше (5.1.4).

## Рішення

- Архітектурні рішення — ADR у `docs/adr/` (шаблон — `0000-template.md`). Записи незмінні; зміна рішення — новий ADR із полем Supersedes.
- Термінологія: «сід» (англ. seed), не «сія»; ідентифікатори англійською, коментарі українською.
- Помилки правил — `throw` з українським текстом; події — в `state.log`.
