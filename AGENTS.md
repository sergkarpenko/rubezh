## Принципи роботи

1. Одна сесія = один вузький крок (див. [docs/workflow.md](docs/workflow.md))
2. Читати перед дією: ADR, workflow, поточний стан коду
3. Тестувати перед комітом: `npm test` має проходити
4. Детермінізм: Один сід + послідовність дій = той самий результат

## Встановлення та налаштування

### Pre-commit hook

Хук встановлюється автоматично при `npm install` через Husky (ADR-0014): скрипт `prepare` задає `core.hooksPath = .husky/_`, а `.husky/pre-commit` викликає `scripts/pre-commit.sh`.

```bash
npm install
```

Hook перевіряє:
- Правила AGENTS.md (заборонені файли)
- Тести (`npm test`)
- Exact-байти (проти розходжень з git)

### Перевірка exact-байти

Для ручної перевірки:

```bash
./scripts/verify-exact-bytes.sh
# або з автоматичним виправленням (лише для текстових файлів)
./scripts/verify-exact-bytes.sh --fix
```

## Вимоги до коду

### 1. Коментарі та повідомлення

- **Мова:** Ukrainian (коментарі, тексти помилок, лог)
- **Формат комітів:** [Conventional Commits](https://www.conventionalcommits.org/) українською

  ```
  feat(core): додати підтримку заступи
  fix(combat): виправити розрахунок точності
  docs(adr): додати ADR-0011 про економіку
  chore(ci): оновити workflow preview.yml
  ```

### 2. Типізація

- **TypeScript:** Суворі типи, жодних `any`
- **ADR посилання:** Коментувати код з посиланнями на ADR

  ```typescript
  // ADR-0002: Чисте ядро без DOM — уся логіка тут
  export function calculateHitChance(unit: Unit, mode: ShotMode): number { ... }

  // ADR-0003: Детермінізм через ін'єктований RNG
  export function mulberry32(seed: number): RNG { ... }
  ```

### 3. Тестування

- **Покриття:** Мінімум 80% для ядра (`src/core/`)
- **Детермінізм:** Тести з фіксованим RNG

  ```typescript
  const alwaysHit: RNG = () => 0;
  const rng = mulberry32(42);
  ```

- **Перед комітом:** `npm test` має проходити

### 4. Шари архітектури

- **`src/core/`:** Чиста логіка (без DOM/Canvas) — див. ADR-0002
- **`src/main.ts`:** Цільове відображення (ванільний TS + Canvas 2D) — див. ADR-0010
- **`src/bot.ts`:** Демо-бот для превью

### 1. Початок сесії

```bash
# Крок 1: Ознайомитися з контекстом
cat docs/workflow.md
```

### 2. Розробка


## Уроки (Lesson Learned)

**Не повторювати:**

1. Тести до першого CI: Запускати `npm test` перед пушем (CI — останній рубіж)
2. Template literals: У файлах через пісочницю — конкатенація рядків
3. TDZ: Виклики функцій — після оголошень (не на старті модуля)
4. Таймери: Не використовувати `setTimeout` у React useEffect (зависання)

**Робити:**

1. Детермінізм: Уся випадковість через ін'єктований RNG
2. Валідація: Людина перевіряє превью (Ctrl+Shift+R) перед тегом
3. Exact-байти: Порівнювати файли після генерації через пісочницю
4. Локальне середовище: Node.js встановлено (2026-10-13) — `npm test` запускати локально перед пушем. Якщо локально бракує інструмента (node, npm тощо) — одразу повідомити власника, не мовчки обходити
